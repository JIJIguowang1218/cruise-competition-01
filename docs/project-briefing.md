# 邮轮AI竞赛项目简报

> 2026-06-30 | 中船外高桥新船AI方案设计

---

## 一、项目背景

**竞赛**：命题C — AI+邮轮深度应用与数字化系统创新设计（中国人工智能学会等主办）

**目标**：为中船集团上海外高桥造船有限公司的**新建邮轮**设计AI解决方案。不是改造现有船只，而是前装设计——从设计阶段嵌入AI系统。

**参考船型**：

| | 爱达·魔都号 | 爱达·花城号 |
|---|---|---|
| 吨位 | 13.55万吨 | ~14.2万吨 |
| 载客 | 5246人 | 5232人 |
| 船员 | ~1292人 | 待确认 |
| 舱室 | 2826间 | 2130间 |
| 甲板 | 16层 | 16层 |
| 母港 | 上海 | 广州 |
| 航线 | 日韩 | 东南亚 |
| 状态 | 运营中 | 预计2026.11首航 |

**比赛三大方向**（可自拟场景）：
1. 智能运营与决策优化
2. 安全感知与风险预警
3. 空间与体验智能设计

**作品要求**：技术方案说明书（PDF）+ 成果展示视频（≤2分钟 MP4）+ 辅助证明材料 + 加分项：可运行Demo

---

## 二、方法论

**"两端收敛"策略**——不局限比赛三个方向，从真实问题出发：

```
Step 1: 收集邮轮真实痛点（不带AI眼镜）→ Step 2: 学习黑客松AI解法（翻Hackathon-reading 30+案例）
→ Step 3: 匹配分析 → Step 4: 锁定2-3方向深入设计 → Step 5: 提交
```

**核心原则**：
- AI产品经理视角：先问"谁用、省什么、为什么是现在"，再问"用什么技术"
- 邮轮=微缩社会：空间/网络/人力/时间/安全五重约束
- AI能力边界：AI感知+确定性计算分离，不把AI当万能胶水
- 叙事策略：目标受众含国企领导——说"省了多少钱/少出多少事"，不说"用了什么模型"

## 四、Hackathon-reading 经验库

已分析 **30+ 个黑客松获奖作品**（Google Cloud Rapid Agent 21篇 + Google Gemini 3 10+篇），每篇含产品经理视角的叙述性分析+结构化评分。

从中提炼了**6个正向模式**和**4个反面模式**：

### 正向模式（评委买账的）

| 模式 | 代表作品 | 核心 |
|------|---------|------|
| AI感知+确定性计算分离 | Spatial Engine, Scam Swarm, AMRShield | AI看数据，公式做计算，各取所长 |
| 多Agent职责单一 | Globot Shield, Scam Swarm | 不是万能Agent，各专注一领域后汇总 |
| 闭环自主决策循环 | Synt, Globot Shield | OODA循环：观察→判断→决策→行动 |
| 预写场景承载能力 | Globot Shield | Demo用mock数据但产品逻辑真实可部署 |
| 推理过程透明化 | Synt | 让评委看到AI每一步在干什么 |
| 低端颠覆（TurboTax类比） | Spatial Engine | 不替代专家，服务请不起专家的长尾 |

### 反面模式（会死的）

| 反模式 | 代表 | 症状 |
|--------|------|------|
| 电影布景 | CityGuard C/45 | UI精美但AI是假的，Run Scenario = setTimeout |
| Multi-Agent贴纸 | NeuroStudy C/52 | 声称5个Agent，实际同1个prompt改词 |
| MCP标签 | MallCore C/45 | README列MCP但代码无SDK |
| 1次提交 | NeuroStudy/CityGuard | 无迭代历史，一次性批量生成 |

## 五、当前锁定方向：邮轮实时人流感知与智能分流 ⭐

**对应比赛方向**：空间与体验智能设计

**一句话**：船载摄像头+AI实时感知人群密度→动态引导乘客去空闲区域→消除排队、缓解拥挤。

**解决的实证痛点**：
- 餐厅拥挤、服务下降 [钛1/2]
- 上下船排队 [钛2]
- WiFi信号差→联动引导 [钛2]

**借鉴的Hackathon技术模式**：
- Scam Swarm (A/84)：规则引擎（阈值触发）+ LLM（语义推荐）双层架构
- Globot Shield (A/81)：多Agent管线 + "高保真Mock"Demo策略
- Synt (A/87)：OODA循环 + 推理剧场透明化
- Spatial Engine (B+/61)：AI感知+物理计算分离

**技术路径**：
```
摄像头画面 → 人群密度检测（规则引擎：阈值触发）
         → 空闲区域识别（AI：图像识别空桌/空位）
         → 个性化推送（AI：根据乘客位置+偏好生成建议）
         → App/船载屏幕显示实时热力图+导航
```

**Demo策略**：预写"11:45AM午餐高峰"场景——用预录视频+确定性脚本保证可靠，LLM生成推荐文本展示AI能力。产品逻辑真实，数据mock。

**详细设计见**：`design/direction-1-deep-dive.md`
