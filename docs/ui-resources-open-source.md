## 三、状态动效 / 微交互

| 资源(仓库) | star | 定位 | 建议用途 |
|---|---|---|---|
| **Motion** `motiondivision/motion` | ⭐33.3k | 现代轻量动效库（Framer Motion 新主体） | 时间轴事件出现、Tab 切换、审批流推进过渡 |
| **GSAP** `greensock/GSAP` | ⭐27.9k | 强动画库 | 大屏切换/演示转场（录制加分） |
| **Lottie** `airbnb/lottie-web` | ⭐32.1k | After Effects 导出动效 | 乘客 App（P6）触达、加载态 |
| **XState** `statelyai/xstate` | ⭐30.0k | 状态机/状态图 | 把"静默→激活(L4/升级)→处置→回静默"和各页状态做成**显式状态机**，演示"核心逻辑真实可跑"加分 |
| `prefers-reduced-motion` | CSS 规范 | 无障碍 | **必做**：降动效偏好用户关闭动画（值班场景更稳） |

**动效三原则**：①时长短 150–300ms（Material 口径）；②用状态机（XState）驱动界面状态与动效、联动闭环（决策→P6 触达"实时出现"）；③可关闭（`prefers-reduced-motion`，呼应 D2 低侵入）。

## 四、落地建议（对应船长端高保真纵切）

1. 先抽 **Design Token**（深色版色板 + day/dusk/night 三档 + 字阶 + 圆角 + 间距 + 动效时长），一次定清楚，反推 P2–P6 不返工；
2. 时间轴 & 大屏参考 **Open MCT + Carbon g100**；右栏处置/审批/推理附件参考 **Radix dark + Ant Design**；
3. 动效用 **Motion + XState + prefers-reduced-motion**，把第三幕（升级到船长、推理附件展开、审计导出）做成可演示交互闭环。

## 六、双向评估（2026-08-20，实网拉 README 后整理）

> 每个项目分两栏：**A = 站在我们页面需要，值得借鉴什么**；**B = 这些项目里有我们还没考虑到的亮点（反哺，建议补进我们设计）**。

### 6.1 NASA Open MCT（任务控制/遥测大屏）
- **A（借鉴）**：深色态势 + 时间轴/遥测时间序列 + 多面板布局 = 我们 P1 大屏最贴的参考；事件时间轴可吸收其"时间范围/时间指挥（time conductor）"的交互。
- **B（我们没想到）**：
  - **Time Conductor（时间指挥）**：把"时间轴窗口"做成可切换的 **滚动/固定范围/今日/航次段** 三种时间域——我们目前只是固定 2 小时窗口，可加时间域切换；
  - **Notifications & 常驻 Indicators（通知+常驻指示器条）**：顶部常驻一条"告警/调轴"指示器区，配合我们当前 KPI 位；
  - **Latch + 确认消隐（alarm 需人工 acknowledge 才消隐）**：海事关键告警尤其需要"看过并确认才解除高亮"，防止漏看——我们目前有倒计时/升级，但没有"告警确认消隐"机制，建议补；
  - **对象钉选（pinned）+ 钻取（drill-down）**：大屏点面板进入详情再返回，导航思路可借鉴到 P1→P3/P5 的进出。

### 6.2 IBM Carbon（企业设计系统）
- **A（借鉴）**：Tabs / DataTable / Notification / Progress（步骤条）这套正好是我们右栏 Tab、审批流、端口清单、通知的组件化来源；`g100` 深色 token。
- **B（我们没想到）**：
  - **通知分级（inline / toast / banner × severity 低/信息/警告/错误/关键）**：建议把"系统模式 + 降级横幅 + 触达通知"统一成一套分级通知语言；
  - **Progress Indicator（步骤条）**：审批流（值班→经理→法务→船长）用显式步骤条 + 当前步高亮，比我们现在的 apstep 更清晰；
  - **Code Snippet / 可复制**：推理附件、审计 trace_id 应可一键复制（我们目前只可看/可打印）；
  - **空态/错误态带"下一步动作"**：我们在 specify §0.4 已经提"错误不道歉、写明原因与下一步"，Carbon 有直观组件可套。

### 6.3 Material 3 / Material Web（token + 状态层）
- **A（借鉴）**：Design Token 口径（颜色/字阶/圆角/间距/**动效时长与缓动**）、Elevation（Z 层）、状态层（hover/focus/pressed）。
- **B（我们没想到）**：
  - **State Layers（状态层）**：按钮/卡片 hover、按下、聚焦有统一"状态层"叠加——我们高保真的点位反馈应统一，避免各处自造；
  - **Elevation / Tonal surface**：深色下的层级（卡片/浮层/阴影）有规范，避免深色糊成一片；
  - **动效 Token 语义（进入/退出/尺寸/共享元素）**：时间轴事件出现、Tab 切换、推理附件展开可套用统一缓动/时长。
  - ⚠️ 注意：`material-web` 官方已标 **maintenance mode（缺新维护者）**，只借 token 理念，不引入依赖。

### 6.4 Radix Themes / Colors（无障碍 + 深色）
- **A（借鉴）**：深色主题开箱、无障碍（focus/aria）、`radix-ui/colors` 深色色阶做语义色。
- **B（我们没想到）**：**可访问性细节**（焦点可见性、键盘操作、无头组件行为）——我们高保真应把"值班平板触屏 + 键盘可操作"都覆盖。

### 6.5 XState（状态机）
- **A（借鉴）**：把"静默→激活(L4/升级)→处置→回静默 + 各页状态"建成**显式状态机**，杜绝非法状态、演示"核心逻辑真实可跑"。
- **B（我们没想到）**：**状态机 = 防漏/防错的结构化手段**：事件状态、审批、接管、降级之间的**不允许组合**（如"接管后不可自动审批"）应显式建模，而不是只靠 UI 隐藏。

### 6.6 Grafana（大屏面板）
- **A（借鉴）**：多面板栅格、时间序列、时间范围选择器、告警红/琥珀语义。
- **B（我们没想到）**：**Annotation（图面时间注解）**——在时间轴上给关键动作（确认/下达/恢复）打**注解点+文字**，比我们现在只在操作台日志里看得更直观；**时间范围选择器** + 自定义保存视图。

---

### 6.7 汇总：建议补进我们设计的"没想到亮点"（backlog）
1. **时间域切换**：时间轴按 滚动 / 固定范围 / 今日 / 航次段（仿 Open MCT / Grafana）+ 时间范围选择器 + 自定义保存视图；
2. **告警确认消隐（Latch/acknowledge）**：关键告警需人工看过/确认才解除高亮（防漏看，海事相关）；
3. **顶部通知/指示器统一分级**（inline/toast/banner × severity，Carbon 式）；
4. **审批流步骤条**（Progress Indicator）+ 不可允许状态组合（XState 显式状态机）；
5. **图面时间注解**（Grafana annotation）：关键动作在时间轴上打点标注；
6. **状态层 + 深色 Elevation 层级**（Material）：高保真统一点位反馈、深色不糊；
7. **可复制**：推理附件/审计 trace_id 可一键复制（Carbon Code Snippet）；
8. **可访问性**：键盘可操作 + 焦点可见 + prefers-reduced-motion。

> 以上候选将作为船长端高保真纵切的"待纳入"清单，逐个与用户确认后再入设计。
