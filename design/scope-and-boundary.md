# 系统边界与接口范围（Scope & Boundary）

> 状态：**草稿框架，待讨论**
> 目的：回答“我们的核心系统管哪一层、哪些痛点纳入、哪些通过接口接入、哪些明确不做”
> 关联：`design/ai-value-case.md` 是本系统价值基石；本文件应在 AI 价值论证后逐步收敛

## 1. 产品定位（当前共识）

- 产品形态：**B 端 AI 产品**
- 核心用户：邮轮公司 / 运营管理方 / 船员运营团队
- 核心任务：**全船空间×时间的调度决策**
- 非目标：不做 C 端乘客产品、不做乘客 App、不做船载屏/港口屏硬件终端
- Demo 边界：可以用静态/模拟视图展示“系统输出如何触达乘客/船员”，但不进入产品范围

## 2. 五层模型

| 层级 | 内容 | 我方职责 |
|---|---|---|
| L1 物理感知层 | 摄像头、LiDAR、WiFi/BLE、门禁、港口气象、船位等 | 接入/采购/规划，不自研硬件 |
| L2 资源状态层 | 餐厅满载率、排队人数、剧院余座、泳池密度、登离船进度、港口接驳排队 | 核心确定性计算层 |
| L3 调度决策层 | 分流策略、分批去重、时间窗、预警、审批、事件响应 | **核心系统主战场** |
| L4 触达执行层 | 乘客 App、船载屏、船员端、广播、短信 | 通过接口对接，不建设终端产品 |
| L5 专业子系统 | 落水检测、设备运维、能耗、智能客舱、AI 无感登船 | 作为外部模块/前装预留接口接入 |

## 3. 初步纳入 / 不纳入清单（待讨论）

### 纳入核心系统

| 场景 | 所属层级 | 说明 |
|---|---|---|
| 餐饮分流 | L2 + L3 | 实时计数 → 满载率 → 分批去重 → 推荐/策略下发 |
| 登离船调度 | L2 + L3 | 排队感知 → 分时建议 → 港口接驳联动 |
| 娱乐/公共空间 | L2 + L3 | 剧院/泳池/儿童俱乐部密度 → 替代活动建议（**已拍板纳入 MVP，轻量扩展场景**） |
| 港口端接驳 | L2 + L3 | 下船人流 → 交通方式分群 → 分时放行建议 |
| 航变事件响应 | L3 + L4 | 航变 → 影响评估 → 资源重新调度 → 统一沟通模板 → 审批 |

### 只做接口预留 / 不进入主场景

| 系统 | 处理方式 | 接口关系 |
|---|---|---|
| 落水检测 | 外部安全子系统 | 作为事件源接入，触发疏散/通知/资源重排，不负责检测算法 |
| 设备运维 | 外部运营子系统 | 暂不进入主场景；故障影响人流时可作为事件源接入 |
| 能耗管理 | 外部子系统 | 不进入主场景，可作为前装扩展 |
| 智能客舱 | 外部已建系统 | 可作为乘客偏好/通知的执行通道 |
| AI 无感登船 | 外部已建系统 | 可作为登离船状态的信息源或执行端 |
| 岸上游内容 | 非本系统范围 | 不纳入；仅在有明确联动时考虑 |

| 餐饮 | 摄像头/客流计数 | 分流建议、推送内容、船员预警 | 船上监控系统、乘客 App |
| 登离船 | 安检/行李/廊桥排队状态 | 分时建议、广播/App 通知 | AI 无感登船、港口系统 |

| 港口接驳 | 下船人流、出租车/短驳排队 | 离船时间窗、交通指引 | 港口信息屏、交通管理系统 |
| 航变 | 航线变更、赔偿标准、乘客分布 | 分层话术、资源重排建议、审批任务 | 客服系统、预订系统、通知渠道 |

## 5. 纳入筛选原则

1. **层级匹配**：必须属于 L2/L3，或与 L3 有直接输入输出关系。
2. **接口真实**：不是“听起来相关”，而是有明确数据/指令往来。
3. **AI 增量**：必须能在 `design/ai-value-case.md` 中回答“AI 带来的增量是什么”。
4. **Demo 可证**：如果进入主演示，必须能在一个 2 分钟 Demo 里讲清楚闭环。
5. **不堆叠**：宁可少而深，不要多而浅。

### Q4 航变审批边界

| 级别 | 动作 |
|---|---|
| 自动 | 事实生成（变更内容/原因/时间窗）；影响评估；话术草稿（LLM） |
| 需确认（船员一键） | 话术定稿；通知渠道选择；赔偿方案初稿 |
| 需正式审批（多级） | 赔偿执行；全量推送；航线变更正式通知；合同条款决定 |

**推荐**：三级审批，结构性设计（代码级，非 prompt），参考 DQ Sentinel "执行路径不经 LLM"。
✅ **已拍板（2026-08-17）：Q4 = 按推荐（三级审批）**

### Q6 调度 vs 消费引导

| 选项 | 依据 |
|---|---|
| A. 纯调度，不做任何策略/激励 | 最聚焦，但缺商业出口 |
| **B. 主方案纯调度，策略配置作为可选扩展预留接口（推荐）** | 不主动做消费引导；预留 L3 策略配置能力，未来可扩展；答"商业模式"时有出口 |
