# AI 价值对照基准：与黑客松高分项目的规则/AI 占比比对

> 状态：**完成（2026-08-18）**
> 目的：回答"我们产品的 AI 价值是否足够"——不靠自我论证，用高分项目做基准：它们的规则系统占多少、AI 真正参与多少、评委为什么买账，逐项对照我们的 B 线产品。
> 证据来源：`Hackathon-reading/analysis/` 精读原文（8 项目 12 份文件，3 个子代理分工精读）+ `research/round2/batch3/09-hackathon-mining.md` 65 条 Nugget。
> 核心结论：**我们的 AI 价值设计处于高分区间并有两项超越（审批/审计完整度、开放域异常发现）**；最大短板为无 Demo 与无 git 迭代证据——两者是未来最大分数杠杆。

## 0. 对照方法

1. 选取与 B 线（邮轮港岸协同与航变响应）同构度最高的 8 个高分项目；
2. 每个项目拆解：规则/确定性系统占比 vs AI/LLM 真正参与部分；
3. 用同一把尺子量我们的 B 线产品（AI 参与环节清单，见 §3）；
4. 结论：我们的 AI 价值是否足够、强在哪、弱在哪、Demo 如何突出优势。

## 1. 高分项目精读结果汇总

### 1.1 Globot Shield（81 A，航运业运营决策台）— 已精读 ✅

**A. 项目一句话**：全球供应链决策台——5-Agent 团队（市场感知/财务对冲/物流编排/合规/红蓝辩论）完成"感知→分析→决策"三级跳，把危机决策从"邮件+电话会议 2 小时"压到"HITL 确认 5 分钟"，输出一句话建议："建议改道好望角，绕行 6 天，额外成本 180 万美元……批准吗？"定位是"行动建议引擎"而非可视化大屏。

**B. 规则/确定性系统占比：约 75–80%**
- 5 个 Agent 中 4 个 **0% AI**：Market Sentinel 是 if/else 事件路由、Financial Hedge 是数学公式（VaR/Black-Scholes/互换定价）、Logistics Orchestrator 硬编码 3 条航线对比、Adversarial Debate 是两个预写辩论脚本轮换；
- 前端约 25,000 行 TS/JS/CSS + Deck.gl 3D 地图 + 思维链 UI 全是确定性工程；
- scoring 原文："AI/Human 配比 2/5，4/5 Agent 未真正调用 AI"、"核心推理链非 AI 生成"。所有业务结论（改道建议、180 万成本）由公式/硬编码产出。

**C. AI 真正参与（20–25%）**：Compliance Manager 是唯一 100% 真 AI（CrewAI+Gemini 2.0 Flash，分析 500 页保单+制裁名单）；Gemini Vision 真多模态（卫星图检测港口拥堵/运河堵塞）；5-Agent 编排外壳 + 思维链展示。
- 可被规则替代：辩论环节本质是"带数字的决策树比较"，AI 只是呈现包装；README 主动标注 "High-Fidelity Mock"。

**D. 评分理由（81 A）**：AI 轻度包装但"刻意、透明、正确"。满分项全在非 AI 维度：演示与叙事 10/10（"4:55PM 危机场景教科书级叙事"）、UX 18/20、定位 13/15；**AI 实现策略仅 16/25，是六维中得分率最低的**。结论：评委没把"AI 含量"当高分主因，高分来自"定位精准+叙事强+逻辑真实+UI 精美"。
- **明确槽点：HITL 四缺失——无超时机制、无权限分级、无操作审计、只有 Approve/Override 两按钮** → 这正是我们 §4.12–4.13 要补成加分项的地方。

**E. 可迁移到邮轮**：①决策台形态（"不只看港口拥堵，而是给'改港 B 还是延航 C'+成本+合规结论"）；②事件→资产→合规→财务→建议推理链（航变→受影响航次/乘客→SOLAS/合同条款检查→赔付与绕行成本）；③HITL 审批门 + 反面教训清单；④局势图（一张屏看清船位/港况/受影响航程）；⑤多专长 Agent 分工（岸基资源/成本/合规）；⑥北极星指标（每船每次危机节省的决策时间）。

### 1.2 Spatial Engine（82 A，空间能源引擎）— 已精读 ✅

**A. 项目一句话**：建筑能效审计——拍照+说一句话，AI 当"光学物理学家"完成审计，把"请顾问两周 $5,000–15,000"降到"拍几张照说几句话"。7 步 SOP：接收输入→Vision Audit→环境数据采集→物理计算→节能方案→用户确认→输出报告。

**B. 规则/确定性系统占比：约 60–65%**
- 物理计算全硬编码公式（热传递/太阳辐射/U 值）；7 步 Protocol SOP 硬编码工作流约束 Agent 自由度；PDF/HTML 报告导出、4 种物理图表、5,134 行代码大部分是确定性工程。
- 架构明言："Agent 做感知和决策 + 确定性公式做计算"——"如果让 LLM 直接推理这些数字，结果一定是幻觉"。

**C. AI 真正参与（约 35%，但核心感知 mock）**：ADK 双 Agent 编排、Gemini Vision 图片分析、Google Search 取数、Multimodal Live 语音、报告生成。
- **"有 AI 但实测不可用"的指认：Vision Audit 是 mock**（"AI 看到的不是你的照片，而是预设的一扇朝南双层玻璃窗"）、checklist 是前端模拟动画、FastAPI 后端疑似 stub——即"AI 看图提取参数"当前 demo 没真跑。

**D. 评分理由（82 A）**：评分讲"分工正确"本身就是技术高分点——"Agent+确定性物理计算分离架构设计正确，避免 AI 幻觉（+4）""7 步协议系统提示体现产品化思维（+2）"，被标为"🏆 正确的 AI Agent 设计典范"。加分全在于"AI 用得对"而非"AI 用得多"。（口径注意：正文评分 61/85 B+ 与评分清单 82/100 A 冲突，已如实标注。）

**E. 可迁移到邮轮**：①"AI 感知/决策 + 确定性公式计算"分离铁律（赔付测算/绕行成本/资源缺口用公式引擎）——与 B 线 §3.6–3.7 三高地完全同构；②7 步 SOP 强制门禁（防跳步编结果，第 6 步天然 HITL）；③Fallback 降级保证 Demo 稳健；④报告导出做可交付证据链（PDF/HTML）；⑤诚实标注 mock（Vision 是 mock 就写明，评委认可透明度）。

### 1.3 Scam Swarm（84 A，诈骗识别）— 已精读 ✅

**A. 项目一句话**：印度 UPI 数字金融诈骗实时识别——可疑短信粘贴进 SOC 仪表盘，三个"AI 侦探"并行分析，2 秒汇总成 0–100 综合威胁评分（>70 CRITICAL、<40 SAFE），给出处置建议（拨打 1930 热线）。流程：输入→启发式→AI→结果→导出。

**B. 规则/确定性系统占比：约 55%**
- 纯规则引擎在调 Gemini **之前先跑**：urgencyKeywords 关键词数组、URL 协议检查、域名/UPI 黑名单、typosquatting 检测，每个发现带严重度标签并累积启发式分；
- 阈值分档确定性（>70 / <40）；`indexOf('{')` 手动提取 JSON、双引擎热切换、导出功能、仪表盘 UI 全确定性；
- 启发式发现被序列化注入 Gemini prompt（`JSON.stringify(heuristicsReport.findings)`）。

**C. AI 真正参与**：语义理解——"这段话是恐慌还是正常提醒"（"规则看到 urgent 就报警，哪怕在说 no need to be urgent"）；最终威胁评分与处置建议生成。
- 可被规则替代/注水：**三代理是"一个 Gemini API 调用产出 agents 数组"（prompt 模拟多代理，无真实并行工程）**、Pub/Sub 扇出"是设计意图非已实现功能"。

**D. 评分理由（84 A）**：创意 12/15（痛点真实有数据）、**Vibe 21/25（28 次小步提交=教科书级迭代）**、代码 16/20（适配器模式、429/401 处理）、功能 17/20（完整 SOC 仪表盘）、技术 9/10（双层引擎+JSON Schema，扣 Pub/Sub 未实战）、展示 9/10。高分给的是"双层架构设计得准 + 工程素养 + 完整可跑交付"，不是 AI 多复杂。

**E. 可迁移到邮轮**：①规则引擎先跑+发现注入 prompt（"让 LLM 在已知事实上推理，比从零分析更可靠更便宜"）；②适配器+双引擎降级（卫星网络/API 不稳定）；③JSON Schema 强约束+"请返回 JSON"兜底提取；④0–100 风险分档迁移为航变事件风险等级；⑤"画了正确的架构图但不一定要完美实现"的务实交付策略。

### 1.5 StoreOps / Off-Duty（79 A，店铺运营审批）— 已精读 ✅

**A. 项目一句话**：小店"下班后没人看店又不敢把生意交给 AI"的信任问题——库存感知店务代理，顾客自然语言点单（确认在库→下单→扣库存→阈值触发补货→推给老板审批箱），老板问"下班后发生了什么"得晨报+可回溯 MongoDB 文档的"证据抽屉"。supervisor 按语义意图分发→子代理执行（确定性业务代码）→每个动作写带 trace_id 的 agent_action_logs→写操作全进人类审批。

- 10 项黄金校验（run_demo_checks.py 具名断言每一条架构主张）；MOCK_MODE 零凭证跑；模型探测降级（仅 404 降级，403/配额不降）；RRF 融合确定性排名。

**C. AI 真正参与**：supervisor 按语义意图分发（拒绝把所有工具塞进一个大 agent："工具选择准确度会掉"）；自然语言点单理解与商品匹配（词法+语义+嵌入+RRF）；货架照片识别、差评分类闭环、晨报摘要。
- 反模式检查全过："✅ 非 Phantom Agent（真实 ADK 调用）✅ 非 MCP Sticker（真实 stdio + 只读白名单）✅ 非 Docs-Only（3,419 行真实代码）✅ 非 Test Badge Lie（黄金校验真实可跑）"。

**D. 评分理由（79 A）**：创意 11/15（"会做事且自证"定位锋利，证据抽屉自称 "This is the trust layer… That's the moat"）；Vibe 20/25（但 4 个 commit 迭代弱）；代码 15/20（配置化+优雅降级，无 pytest 单测 -2）；功能 16/20（mock 零凭证全链路）；技术 8/10（真 MCP+混合检索+最小权限+降级分寸感）；展示 9/10（DEMO_SCRIPT 含"现场直播挂了怎么办"兜底话术）。**证据抽屉被明确定位为护城河**。

**E. 可迁移到邮轮**：①证据抽屉/trace_id/Grounded in MongoDB 作为**护城河**——与 B 线推理附件完全同构，"信任层就是护城河"直接搬进答辩叙事；②审批箱+5 秒反悔 toast（只提案不执行+人工接管）；③supervisor 按意图分发不堆工具；④读走通用协议、写走带业务规则领域函数（最小权限）；⑤演示工程化三件套（MOCK_MODE+三分钟脚本+兜底话术）；⑥**黄金校验**（用评估驱动开发对抗"README 吹测试仓库零测试"）；⑦模型降级"分寸感"。

### 1.6 FireGuard（80 A，城市应急响应）— 已精读 ✅

**A. 项目一句话**：山火撤离协调智能体——NASA FIRMS 卫星探测到超阈值火点且落在撤离区 150km 内时，自动触发撤离工作流，Gemini 并行查询撤离区/避难所/道路事件/火点/路线安全，60 秒输出"结构化简报 + 标注地图"（撤哪个区、去哪个避难所、走哪条路），把 20–45 分钟手工拼图压到一分钟。

**B. 规则/确定性系统占比：约 70%**
- 威胁分纯公式：`S = min(100, (FRP-50)/250×60 + (1-d/150)×40)`，FRP<50 直接挡在门外，参数有遥感文献背书（Wooster 2005 / Ichoku 2008 等）；
- 空间推理全交 Elasticsearch：geo_distance 150km、geo_shape intersects 多边形相交、路线插值、走廊缓冲区——全部确定性查询；
- MCP 围栏：Agent 永远不能直接碰 ES，只能调用固定工具，每个查询在工具轨迹里可审计；
- 触发条件确定性：FRP>50 且入 150km → 工作流自动打开；
- 可重放时间线 + 真实数据集（38,744 FIRMS 火点 + 633 BCWS + 182 多边形）无 AI 参与。

**C. AI 真正参与**：跨系统信息并行聚合 + 60 秒简报写作（"AI 只把结构化证据翻译成人话 + 组织推理链"）；路线 what-if（"如果 97 号高速关了会怎样"）的意图理解→工具调用。正文明确"AI 宕机时系统依然能预警，只是没有自然语言简报"——AI 是刻意可剥离的翻译层。

**D. 评分理由（80 A）**：AI 深度参与但定位"AI 副驾/翻译层"，核心决策刻意与 AI 解耦——是"克制分工"正面范例。高分来自 Idea（锚定真实灾难）、Technical（真 Elastic MCP + 文献背书公式）、Code Quality（30+ 类工作流引擎）、Feature（回放/评估/what-if 全跑通、离线零密钥）、Presentation（600 行白皮书 README）。**唯一大失分 Vibe 17/25——全仓库仅 1 次 git 提交，迭代痕迹空白**。

**E. 可迁移到邮轮**：①ApprovalGate 审批门 + 分级自主（AI 输出建议不自动执行）；②60 秒局势图（航变分散信息拼成现状图）；③威胁分公式化 + 文献背书（航变风险分级用可解释公式）；④what-if 假设推演（"如果推迟 6 小时到港"）；⑤MCP 工具围栏 + 可审计工具轨迹；⑥离线可重放演示。

### 1.7 CrowdPilot（68 B，人流应急分流）— 已精读 ✅

**A. 项目一句话**：大型活动应急部署决策系统——Google ADK SequentialAgent 四段串行流水线（Forecast→Incident→Resource→Operation），真 MCP 从 MongoDB 调历史事件/预案/资源模板，输出可执行部署方案（任务名、优先级、行动列表、成功标准）。

**B. 规则/确定性系统占比：约 30–35%**
- 与 FireGuard 相反：**没有评分公式、没有规则引擎**，核心判断（risk_level、事件类型、严重等级）全由 LLM 完成；
- 确定性部分只有：JSON schema 强约束（"You MUST call get_historical_events"、"Do NOT invent resource quantities"）、资源数字来自模板查询、demo_mode 硬编码模拟序列（88000 人体育场/94% 利用率/Gate A 拥挤）；
- 工程防错：15 秒冷却、429 检测、WebSocket 清理。
- **正文点名：没有规则引擎 fallback，Gemini 不可用时唯一降级路径就是 demo_mode 硬编码——这是它的硬伤**。

**C. AI 真正参与**：风险评估、事件类型判定（拥挤/医疗/火灾）、资源部署数字（半 AI 半约束）、最终行动计划生成。正文直接指出"风险评估这些核心决策仍是黑箱，一个活动运营商不会信任无法解释'为什么风险是 High'的系统"——**它的这三类判断换成密度阈值公式 + 事件类型枚举反而可解释性更好**，即"AI 做了三类可规则化的判断"，不可替代性最弱。

**D. 评分理由（68 B）**：AI 深度依赖但"依赖而不克制"。失分：Vibe 15/25（仅 1 次提交）、前端 AI Operations Console 是 mock（"AI agents are not connected yet"）、HITL 审批 API 就绪但无 UI 对接、核心假设"运营数据已在 MongoDB"未验证。加分：真 MCP、JSON schema + CRITICAL RULES prompt 工程、Demo/Prod 双模式诚实标注。

**E. 可迁移 + 教训**：①四段流水线映射决策步骤（对我们 M4 航变处置）；②"CRITICAL RULES + Do NOT invent + schema"约束（邮轮数字必须来自系统查询禁止编造）；③HITL 逐项审批（每 action approved/rejected）；④**三个反面教训：有审批 API 无前端 UI=功能不完整；审批结果不回流改进=无闭环；核心假设"数据已在系统里"必须验证**。

### 1.8 Mnemos（83 A，事故模式记忆）— 已精读 ✅

**A. 项目一句话**：个人职业记忆代理——/ask 输入请求后，ReAct 循环先混合检索（向量+关键词）捞记忆片段，再查日历、起草内容，一个"批评者"子代理自动审稿，生成带 [N] 引用标记的提案，**用户批准后才真正执行**。

**B. 规则/确定性系统占比：约 40%**
- 混合检索算法层确定性：向量（$vectorSearch）+ 关键词（BM25）并行，Reciprocal Rank Fusion（k=60）确定性融合；
- **强制批评者触发是代码级**（react_loop.py L233-256：模型没调 critique_draft 就自动补跑一次）——"约束写进代码，不写进提示词"；
- 降级逻辑确定性：索引未建好静默降级"仅向量"、Gmail 未连接诚实模拟发送、provider 切换零代码改动；
- 供应商中立层（neutral.py 98 行）纯函数可单测；审批硬门槛是确定性状态机。

**C. AI 真正参与**：意图理解与工具调用规划（ReAct，MAX_TURNS=14）、内容生成（邮件/日历草稿）、**批评者子代理**（AI 审 AI：检查无依据断言/幻觉人名日期/AIA 语气不符/结构/安全，输出严格 JSON approve/revise/reject）。唯一可规则化点：可选的 LLM 重排（RRF 已融合，重排锦上添花）。
- 瑕疵：`mnemos_use_mcp` 开关是贴纸（只报告状态，实际走 motor 直连）。

**D. 评分理由（83 A）**：**Vibe Coding 22/25——全分析系列最高分**，凭据是 87+ 次提交（2026-05-16→08-06）清晰的"人类审查→修 bug"节奏（如 fix: critic returned invalid JSON）。分析原文："这比任何 README 吹嘘都更能证明作者真的在用、真的在修"。失分：代码 15/20（仅 1 个测试文件 6 用例，ReAct/检索/批评者零覆盖）、创意 12/15（记忆代理赛道拥挤）。**打分逻辑：同是单次提交，FireGuard -8、CrowdPilot -10 重扣，87 提交在 Mnemos 直接 +22——git 迭代史是硬通货**。

**E. 可迁移到邮轮**：①强制批评者模式：AI 起草的乘客航变通知/公告必须过"审核子代理"且代码级兜底——比"提示词里写你必须审"可靠得多；②事故模式记忆库 = 向量+BM25+RRF+降级的混合检索（正是我们 B 线事故模式记忆库）；③[N] 引用标记 + hover 验证（每个结论挂证据来源）——直接对应我们推理附件/条款引用；④分级自主 = 审批硬门槛；⑤供应商中立层 + 诚实降级（卫星网络下切小模型）；⑥教训：核心决策路径要测试。

## 3. B 线产品（我们）AI 参与环节清单

### 3.1 系统骨架（确定性/规则，刻意不用 AI）

| 环节 | 实现方式 |
|---|---|
| 排队/等待/时间窗/影响人数计算 | 确定性算法、规则引擎、排队论（R1） |
| 事件分类的规则复核 | 规则引擎兜底（分类模型 + 规则复核） |
| 条款/策略检索重排 | RAG + 规则匹配（确定性优先） |

### 3.2 AI 高利益区间（不可替代增量）

| 环节 | AI 承担什么 | 规则替代性评估 |
|---|---|---|
| 事件分类（非结构化信号理解） | 从投诉原文/现场描述/天气措辞判断"发生了什么" | 规则只能读结构化字段，语义模糊即失效 |
| 跨系统弱信号整合 | 孤立看正常、合起来可疑的弱组合（A 3 条+B 2 条+时间接近） | 字段级 join 表达不了弱信号组合 |
| 长链路影响推演 | 未见过的组合多步推演（事故→下船口→接驳→暂缓→时间窗） | 规则预写分支组合爆炸、漏一条漏一次处置 |
| 开放域异常发现（库外） | 发现库里没有的异常信号，生成提醒卡 | 规则对库外信号"看不见"——封闭与开放之分 |
| 方案组合的"为什么" | 从库选择/组合 + 逻辑论证（推理附件） | 规则返回模板但说不清"为什么不是 B" |
| 多语言/多人群一致性 | 统一口径下适配不同人群的表述 | 模板固定，无法兼顾统一与适配 |
| 自检与信度校准 | 置信度 + 低信度转人工 + 推理链自检 | 规则不知道自己可能错了 |
| 工作流编排（3-4 Agent） | 事件→影响→资源→方案 顺序流水线 | 规则可线性串联但无法在环节间做语义判断 |

### 3.3 刻意不用 AI 的地方（对照"堆 AI 露怯"）

- 确定性计算（排队/时间窗/人数/赔偿范围）——纯代码
- 高后果执行（全量推送/赔偿/紧急）——审批门 + 人工接管

## 5. 最终结论：我们的 AI 价值足够 + Demo 展示要点

### 5.1 结论：AI 价值充分，且结构比高分项目更完整

**对照 8 个 68–84 分高分项目后确认：我们的 AI 价值设计处于"高分区间"并有两项超越。** 理由：
1. 我们的规则/AI 占比（55–60%）与 8 项目的中位数（60%）同价位——**评委认可这个比例**（Scam 84、WCO 79、StoreOps 79、FireGuard 80 全在这个区间）；
2. 所有高分项目的"信任层/审批/可解释"卖点，我们全部有且更完整（把 Globot 槽点做成机制）；
3. 我们独占一项别人没做的：开放域异常发现（§4.11）——这正是"如果只是规则调用，旧系统也能做到"的反证。

**"关掉 AI 还剩什么"的标准答案**（升级版）：关掉 AI，还剩一个能算准排队/时间窗、能按库触发事件、能审批留痕的确定性系统——**但那不是产品，因为：它看不见库里没有的异常（开放域）、推演不了没写过的组合（长链路）、解释不了为什么这么选（推理附件）**。这三项只有 AI 能提供，且都有高分项目证据背书。

### 5.2 Demo/展示必须特别关照的事项（持续留意 AI 价值判断）

1. **三高地必须做成 Demo 的三幕，不能被流程叙事淹没**：
   - 第一幕（确定性）：排队/时间窗计算+事件触发——**快速过**（证明"关掉 AI 也能算"不是吹牛）；
   - 第二幕（AI 高地 1+2）：登船日人流异常信号 → 库外异常识别提醒卡（开放域发现）→ 长链路推演（影响推演+资源重排）——**主角，给最长时间**；
   - 第三幕（AI 高地 3）：方案卡展开推理附件（为什么选这个方案、读了哪些数据、置信度）→ 审批签署 → 审计包导出 PDF——**收尾，展示信任层**。
2. **每个 AI 判断都要露出推理附件**——主界面结论+展开详情，让评委习惯性点开（StoreOps/Mnemos 模式）。
3. **审批与审计要演出来，不是讲出来**：人工接管按钮、循环提醒、签署确认单、审计包导出——全部点给评委看（Globot 槽点反杀）。
4. **诚实标注数据**：港口/登离船数据模拟+标注，但核心逻辑真实可跑（FireGuard 离线可重放模式）。
5. **git 历史从现在开始做**：把本次 3 轮审核的设计演进做成小步提交（Mnemos 87 次提交换 22/25 Vibe 分的教训）。
6. **答辩金句**："我们不是用 AI 给规则引擎化妆，而是把系统立在规则引擎到不了的三块地上：看见没见过的、推演没写过的、解释说不清的。"
