## 0. 决策框架（两分钟看懂）

**比赛要求**：作品逻辑链 = 问题定义 → 系统设计 → 技术路径 → 应用验证；加分项 = 可运行 Demo / 在线体验；另有 ≤2 分钟展示视频（MP4）+ 技术方案说明书（PDF）。

**评委打分硬通货**（8 个高分项目对照结论）：不是"AI 用量大"，而是 **AI 边界划得准 + 工程护栏完整 + 可跑交付 + 迭代证据**。我们当前最大短板 = **无可运行 Demo**——所以 B5 的选择标准是：

> **哪个场景最能同时装下"三高地 + 信任层"，且开发量在可控范围？**

**三幕结构（既定，§5.2）**：
- 第一幕（确定性）——排队/时间窗/影响人数计算，**快速过**（证明"关掉 AI 也能算"不是吹牛）；
- 第二幕（AI 高地 1+2）——库外异常发现 + 长链路推演，**主角，给最长时间**；
- 第三幕（AI 高地 3）——推理附件展开 + 审批签署 + 审计包导出，**收尾，展示信任层**。

**演示红线**：可 mock 数据源，**不可 mock 核心逻辑**；MOCK_MODE / REAL_MODE 显式分离；诚实标注模拟数据（§8.1 诚实量化口径顺势展示）。

## 1. 候选一：台风航变响应（★★★ 推荐）

**一句话**：**外部已成立航变决定**进入系统，在 3 分钟时限内完成"接收决定 → 局势集成 → 影响链推演 → 审批触达 → 审计留痕"的完整闭环（ClarSyn 不做航变预警/决定；只做决定后的登离船/接驳/时间窗调度响应）。

**三幕映射**：
| 幕 | 演什么 | 对应高地/护栏 |
|---|---|---|
| 一 | **接收外部已成立航变/靠离泊决定 + 本船状态** → 局势图自动集成（船期/登离船人数/港口接驳），影响人数与时间窗确定性计算 | 确定性底座（30s 内快过） |
| 二 | 弱信号组合触发**库外异常提醒卡**（如"某老年团 37 人已登岸未归 + 接驳巴士故障 + 距离港 90 分钟"→ 系统发现库里没有的组合）→ 长链路推演（延误→离港窗口→赔偿条款触发→资源重排）→ 方案组合"为什么选 A 不选 B" | AI 高地 1（开放域异常发现）+ 高地 2（长链路推演）——**主角** |
| 三 | 方案卡展开推理附件（读了哪些信号、置信度、条款原文编号）→ **审批链**（值班确认 → 运营经理/航次经理审批；涉赔偿法务复核；**船长知会/抄送不阻塞**；可加"安全/群体触发→L4 船长决策区"升级剧情）→ 投放审核矩阵分级触达（广播/App/船载屏分级）→ 审计包导出 PDF | AI 高地 3（可解释性）+ 信任层（审批/审计超越 Globot 的实证） |

**评委得分证据**：与 04-itinerary-change-compensation 素材库 Strong 证据呼应（航变赔偿是 2026 年最突出乘客痛点）→ 问题定义有实证背书；高后果场景是"信任层完整度"（分级审批/船长知会边界/超时双路径/循环提醒/四档签署/审计）唯一能全演出的舞台；边界诚实本身是加分项——"航变决定由外部+船长做出，我们只做影响链推演"正回应 ISM Code 船长权限边界证据（`research/round2/source-archive/06-master-authority-and-shipboard-org.md`）；§8.1 价值量化假设表第一行"航变响应逐批沟通 8 客服 5h+"可直接引用。

**风险与 Plan B**：①场景重、三分钟闭环时限要演出来——Plan B：把"感知→建议"用压缩时间轴展示（加"T-90min"倒计时条即可），不做真实等待；②审批环节容易拖长——Plan B：用"审批超时自动升级（常规默认执行+审计 / 涉风险升级 L4）"剧情代替逐级慢等，顺带反杀 Globot 的 HITL 槽点；③条款引用不能出错——Plan B：条款原文编号强制来自条款库样例，综最多 3 条，全部预置核对；④"航变决定"来源要向评委说清（气象/海事预警 + 船公司决定 + 船长安全确认在外部）——Plan B：第一幕用"已成立航变决定"作为输入卡片直接展示，不演"发现台风"。

**开发量级**：中（规则引擎 + 事件流 + 审批流为确定性代码，真实可跑；LLM 环节：事件分类/弱信号识别/推演/推理附件，用本地小模型或 API + 显式标注；数据 mock：台风路径、船期、客服信号）。

## 2. 候选二：登船日动态分时（轻量备选）

**一句话**：登船日客流洪峰，系统实时计算等待时间并动态重排分批计划，异常信号触发提醒与运营经理审批。

**三幕映射**：
| 幕 | 演什么 | 对应 |
|---|---|---|
| 一 | 排队/等待时间/分时窗口确定性计算；登船口队列实时变化 | 确定性底座 |
| 二 | 人流异常信号（接驳车迟到 → 分批计划冲突）→ 提醒 + 影响推演（下一批推多少人） | 高地 2 为主 |
| 三 | 推理附件（读了哪些信号、置信度）→ 运营经理审批 → App 分批通知触达 → 审计留痕 | 高地 3 + 信任层（简化版） |

**优点**：场景日常、贴近乘客体验、数据最好 mock、开发量最小、可控性最强（不易翻车）；与乘客端感知直接（评委好理解）。

**缺点**：事件等级以 L1/L2 为主——**"分级审批链 + 船长知会边界 + 法务条款 + 超时双路径"这套最能证明信任层完整度的戏份没有**；跟 A 线（空间体验调度）气质接近，评委可能觉得 B 线差异度变弱；"高后果决策"叙事强度明显低于候选一。

**开发量级**：小–中。适合时间紧、求稳；但分数杠杆弱一档。

## 3. 候选三：双场景快切（全景版，不推荐首选）

**一句话**：先 45s 登船日小场景（确定性 + 异常提醒），再切台风航变完整三幕（L1–L4 全谱系覆盖）。

**优点**：覆盖面最全（日常 + 应急、L1–L4、运营优化 + 安全预警两条比赛方向都点到）。

**缺点**：8 分钟演示太满，节奏容易乱；两个场景都要打磨，工作量最大；翻车点翻倍（第二个场景出问题，前面的好印象被冲掉）。**只在比赛明确要求"全景"且时间宽裕时选**。

**开发量级**：大。

## 4. 对比与推荐

| 维度 | 候选一 台风航变 | 候选二 登船日分时 | 候选三 双场景 |
|---|---|---|---|
| 三幕结构贴合度 | ★★★（完全咬合） | ★★（第二幕弱） | ★★★ 但节奏风险 |
| 三高地展示力度 | ★★★（开放域+长链路+可解释全有） | ★★（开放域发现弱） | ★★★ |
| 信任层（审批/审计）全演出 | ★★★（分级审批+船长知会+L4 判据+超时双路径+签署+审计） | ★★（单级审批） | ★★★ |
| 问题定义证据背书 | ★★★（04 素材库 Strong：航变赔偿=2026 最突出痛点） | ★★（登船拥堵多渠道证据，但偏体验） | ★★★ |
| 开发量 | 中 | 小–中 | 大 |
| 翻车风险 | 中（可控，Plan B 充分） | 低 | 高 |

**推荐：候选一（台风航变三级审批）**。理由：
1. **与既定三幕结构 100% 咬合**，三高地一幕一个，评委的注意力曲线天然对（主角放第二幕）；
2. **信任层完整度是唯一能超越高分项目的证据**（Globot HITL 四缺失反杀），而信任层必须有高后果场景才演得出来——登船日调度的审批太轻，演不出层次；
3. **问题定义有 Strong 证据**（航变赔偿 = 2026 年最突出乘客痛点，多源互证），"为什么是现在"闭环完整；
4. **§8.1 诚实量化直接入戏**（价值假设表第一行 + 目标指标表展示），企业级落地标准核对意见变成答辩素材而非负担。
