## 1. 可视化终端盘点表（持有人 × 硬件 × 位置）

> 关键判断 1：**同一套"决策层"产品跑在多个角色上，而不是为每个人一个独立 App**——值班/经理/法务/船长都是"运营调度台"的角色视图，靠角色切换区分权限。演示用一套主 UI 覆盖，避免 Demo 散成七八个独立应用。

| 终端 | 持有人 | 硬件设备 | 位置 | 系统角色（§4.7） | 承载什么 |
|---|---|---|---|---|---|
| **运营调度台**（主） | 值班船员→运营经理→法务→船长（多角色，靠切换） | PC + 大屏（调度室/运营中心）；船长位在船桥放大屏+触控 | **船上**（运营中心/船桥） | 决策端 L1–L4 全角色 | **AI 三高地全部落在这里**（见 §4） |
| 乘客 App | 乘客 | 手机（iOS/安卓） | 船上 + 岸上 | 告知端口·个人定向 | 效果验证屏（触达结果，不做 AI 高地） |
| 广播 PA | 全体乘客（通播） | 广播台 + 扬声器 | 船（驾驶台） | 告知端口·全船强打扰 | 执行屏（需 ≥L2 确认后播报） |
| 船载屏 | 公共空间乘客 | 楼层 LCD / 拼接屏 | 船公共区 | 告知端口·公共空间 | 执行屏（需 ≥L2 确认后显示） |
| 船员端（手持） | 现场船员/安保/服务台/维修 | 手持 PDA / 手机 | 船现场 | 执行端 | 任务接收与执行反馈（可选做） |
| 港口对接员端 | 港口对接员 | PC / 手持 | **岸上**（码头） | 执行端 | 接驳协同（用接口示意，不做主 UI） |
| 法务/合规 | 法务 | PC（可在岸上远程） | 船或岸上 | 决策端 L3 | 复用调度台 L3 视图（电子签署） |
| 岸上/企业服务器 | ——（系统侧） | 企业数据中心 / 云 | 岸上 | 部署层 | 不做 UI，仅在架构图呈现（异步/审计归档） |
| 感知端（摄像头/闸机等） | ——（采集，不给人看完整画面） | 摄像头/闸机/PoS | 船内外 | 外部/内部感知源 | 只输出**计数**（R6 仅计数不识别），Demo 以数据进入，不画画面 |

> 关键判断 2：港口/海关/OTA/客服是**外部与下游**，按 R7 边界不画我们的管控 UI——在 Demo 里以"已同步 / 已回执"状态呈现即可，不做交互面。

## 2. 事件 → 终端反应矩阵（重点事件 x 各终端反应）

> 作用：证明"每个事件都有明确终端反应、审批门/投放审核/审计都有落点"，也为演示锁定要演的屏幕。
> 说明：感知来源不需要"人看"——计数数据自动进入系统；加粗=演示时要点开看的屏。

| 事件示例 | 感知来源 | 决策终端（调度台角色） | 执行终端 | 告知终端 | 审计留痕 |
|---|---|---|---|---|---|
| E01 排队过长（L1/L2，日常） | 摄像头计数/App | 值班（L1 可自动） | 现场船员端 | **乘客 App**、船载屏 | 调度台 trace |

## 3. AI 三高地 → 终端落点（据此定主 UI）

| AI 高地 | 流水线环节 | 呈现在哪个终端 | 界面体现 |
|---|---|---|---|
| ① 开放域异常发现（X 系列） | [2.5] | **运营调度台**（+按风险抄送决策端） | 异常提醒横幅/事件队列高亮 + X 提醒卡 |
| ② 长链路推演 + 弱信号整合 | [3]/[4]/[5] | **运营调度台** | 局势图 + 影响推演 + 建议卡 |
| ③ 可解释性（推理附件/置信度） | [5.5]/[6] | **运营调度台** | 建议卡展开推理附件 + 审批卡证据链 |

> **结论：核心 AI 演示面 = 运营调度台**（含多角色切换）；乘客 App / 广播 / 审计是"效果 / 执行 / 留痕"辅屏。UI 与交互设计优先围绕调度台展开，辅屏只做轻量模拟。

## 4. 修订后的展示结构（日常轨道 + 应急三幕）

> 按意见②③合并：**先"日常是怎么工作的"，再"应急怎么升级"，最后回到闭环恢复**。

```
【开场 日常轨道 40s】事件轨迹时间轴页（ambient 滚动）
   日常事件处理轨迹：E01/ E25/ 小拥挤弱信号
   ——每条卡显示 发生→建议→确认→执行→恢复 的闭环状态条
   → 传达"系统每天都在盯，不是只响应急"

【第一幕 快过 30s】台风预警触发 E09
   局势图 + 影响人数/时间窗 确定性计算（R1 用代码）

【第二幕 AI 高地主角 90s】（你问的"第二幕演什么"=这里具体化）
   a) 弱信号整合：港口接驳巴士异常 × 离船批次冲突 × 时间接近 → 态势图高亮弱组合
   b) 库外异常（高地1）：某廊桥占用模式与历史不符 → X 提醒卡"不在事件库内，建议人工关注"
   c) 长链路推演（高地2）：E09 → 离船变更 → 接驳 → 条款触发区间 → 窗口连环更新
   d) 方案组合：A05+A06+A03，附"为什么不用 B"

【第三幕 信任层收尾 60s】
   建议卡展开推理附件（读了哪些信号/置信度/条款编号）
   → 三级审批（值班确认→经理→法务电子签署；可加超时升级剧情）
   → 投放审核矩阵分级触达（广播需确认、App 定向推送）
   → 乘客 App 效果屏 + 广播执行屏
   → 审计包导出 PDF

【收尾 20s】时间轴回到"恢复"：事件关闭，事故模式记忆回写 → 闭环
```

## 5. 可交互页面清单（要开发出来的页面）

> 原则（意见④）：**每个页面都是"完整功能模拟"**（逻辑真实、数据 mock 并标注），评委可手动点；另外用**自动化脚本**驱动走完整剧情（见 §6）。

**必做（6）**：
| # | 页面 | 承载剧情 |
|---|---|---|
| P1 | **运营调度台 · 总览**（主屏） | 态势 + 事件队列 + 建议卡 + 审批队列 + 接管入口（角色切换） |
| P2 | **事件轨迹时间轴**（滚动总览） | "日常轨道"开场 + 收尾恢复 |
| P3 | **事件详情 / 建议卡**（推理附件展开） | 分类置信度/依据信号/条款引用/备选对比（高地3） |
| P4 | **异常提醒卡**（X 系列） | 库外异常（高地1）+ 升级为正式事件 |
| P5 | **审批操作**（值班确认/经理法务签/船长 + 超时升级 + 转人工接管） | 第三幕审批 + 自动升级剧情 |
| P6 | **乘客 App 效果屏** | 分批通知/排队提示/统一口径+多语言（触达效果） |

**可选（3）**：P7 广播/船载屏执行屏（待确认→已下达→已播报）；P8 审计包摘要/导出（trace 链 + PDF 样张）；P9 船员端执行反馈。

**MVP 建议先做 P1–P5（撑起主剧情）**，P6 与 P7/P8 作为辅屏补充；P9 视工作量。

## 6. 自动化演示驱动（意见④的落地）

- **交互性**：P1–P9 全部可由人点击操作（模拟各角色点确认/审批）。
- **演示模式**：用自动化脚本（推荐 Playwright，或原型内嵌"剧情推进"模式）自动走完整流程——设事件状态→点击→切角色→滚动时间轴→导出，产出**流畅演示**；可录制为 ≤2 分钟展示视频（比赛要求 MP4）。
- **现场半自动**：关键步骤手动点（显"人在审批"），页面联动自动，既稳又不显假。
- **红线不变**：数据 mock 标注、核心逻辑真实可跑、推理附件必露、审批审计演出来。
