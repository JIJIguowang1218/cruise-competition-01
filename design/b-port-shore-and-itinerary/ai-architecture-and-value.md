## 3. AI 价值判断与架构选型（修订版）

> 这一章回答两件事：**AI 在 B 线工程场景中的真正价值是什么**，以及**用哪种 AI 组织方式实现这些价值**。它不是“AI 帮忙写通知”，而是“AI 做人类做不快、做不全、做不一致的高并发判断与长链路调度建议”。

### 3.1 AI 在 B 线真正解决什么

| 工程价值 | 说明 | 对邮轮港岸/航变的具体含义 |
|---|---|---|
| **事件分类与态势判断** | 从多源信息中判断“发生了什么、严重吗、属于哪类事件” | 登离船滞留要区分：找不到路造成堵塞 / 乘客受伤 / 电梯扶梯故障 / 港口接驳中断 / 恶劣天气触发；不同类别对应不同资源、权限、预案 |
| **跨系统高并发整合** | 同时读港口、船期、天气、乘客清单、客服投诉、现场感知等，快速形成统一态势图 | 把“人工拼图 20–45 分钟”压缩成“分钟级局势图”：哪些区域拥堵、哪些人群受影响、哪些资源可调度 |
| **长链路推理与影响推演** | 基于当前事件推理后续影响：局部拥堵→疏散/改道→资源不足→是否需要更高权限介入 | 岸上事故时，AI 可快速给出“船上还没下船的人怎么调度、下船口怎么调整、接驳怎么分流、哪些人暂缓”的整体方案 |
| **方案组合而非方案编造** | 从事件库、策略库、条款库、历史预案中选择/组合已有策略，而不是现场发明方案 | 航变响应不是让 LLM 编一个赔偿方案，而是从“条款库+判例库+历史处理模板”中检索并组合出可审计的候选方案 |
| **证据与信度控制** | 每个判断给出依据、置信度、可选方案差异；低信度时主动转人工 | AI 可以回答“为什么判断是设施故障而不是受伤事件”：依据是哪路闸机数据、哪个摄像头、哪条工单记录 |
| **人机协同与权限分级** | AI 建议、人审批；高后果动作必须过代码级审批门 | 日常分流建议可自动；全量通知、赔偿执行、紧急响应必须由相应权限的人确认 |

### 3.2 证据线：为什么这些价值成立

- **证据线 A（旧模式基线）**：`design/evidence-line-a-baseline.md` 证明现状是人工拼图、逐批通知、口径不一致、信息延迟 3–4 小时；这正是 AI 高并发整合与长链路推理的发力点。
- **证据线 B（黑客松高分项目）**：
  - **CrowdPilot**：4-Agent 顺序流水线 `Forecast → Incident → Resource → Operation` 映射应急决策步骤，证明“先判断事件、再评估影响、再调度资源、最后生成行动”是有效的工程结构；
  - **FireGuard**：60 秒局势图 + 确定性威胁分 + what-if 重评，证明 AI 的价值是“把 20–45 分钟手工拼图压成 60 秒局势图”，而不是写文案；
  - **Globot Shield**：5 Agent 并行处理市场/物流/金融/合规 + 红蓝辩论，证明多 Agent 可以高并发读取多个系统并形成可辩驳的方案；
  - **Cassandra / AgentCI / Ripple**：Meta-Agent、自检、事故记忆，证明长链路 AI 需要“自我检查 + 回归验证”，不能只跑一次 prompt；
  - **StoreOps / DQ Sentinel / Mnemos**：证据抽屉、结构性审批门、只提案不执行，证明高后果场景必须让人审批、让证据可回溯。

### 3.3 AI 架构选型总览（认知层选型，非详细设计）

| 系统能力 | 建议技术形态 | 理由 |
|---|---|---|
| 事件分类/严重度判定 | 事件库 + 等级表 + 分类模型 + 规则复核 | 先判断类别再决定资源与权限；不能靠 LLM 自由发挥 |
| 跨系统信息并发读取 | API/事件适配器 + 并行编排（Workflow / 少量 Agent） | 高并发读取是工程能力，不是 LLM 生成能力 |
| 影响评估/时间窗/人数计算 | 确定性算法、规则引擎、排队论、仿真 | 数字必须可复现、可审计 |
| 方案组合 | 策略库 + 条款库 + 历史预案 + RAG 检索 | 从已有方案中选择/组合，避免编造 |
| 长链路计划生成 | 3–4 个职责单一的 Agent/模块串联：事件→影响→资源→方案→话术 | 每个环节独立输入输出，可回滚、可审计 |
| **推理附件生成（2026-08-18 新增）** | 方案生成模块后挂轻量"推理与证据链整理"组件（LLM 摘要 + 确定性校验） | 每个方案标配可展开详情；异常苗头提权为重点提醒；见 `event-governance-framework.md` §4.11 |
| 方案解释与多语言触达 | LLM 生成解释/话术（**下游表达层**） | 这是最后一步，不是 AI 的核心价值 |
| 自检与信度控制 | 独立审计/校验模块 + 确定性检查 | 防止 AI 自己给自己判作业；低信度转人工 |
| 客服/乘客问答（若做） | 意图识别 + RAG + 路由 | 查事实走 API、查条款走 RAG、投诉/紧急转人工 |

### 3.4 为什么不是“AI 只是聊天机器人”

把 AI 理解成“生成话术”会丢掉 B 线最核心的价值。B 线的 AI 价值是：

1. **并发**：同时处理港口、天气、船期、客服、现场感知等大量信息；
2. **推理链**：从事件分类→影响传播→资源调度→预案组合，形成完整决策链路；
3. **策略复用**：不是现场发明方案，而是从历史/条款/策略库中快速组合；
4. **可控执行**：给信度、给证据、给替代方案，再让人审批；
5. **一致性**：面对 5000 人、多种语言、多个渠道，AI 可以保持统一口径与统一调度逻辑。

语言生成只是这个链路最后输出的一部分，不能代表 AI 价值本身。

### 3.5 AI 使用边界

- AI 可以：分类事件、整合信息、推演影响、组合方案、生成话术、给出信度与证据、辅助客服分流。
- AI 不可以：直接算赔偿金额/时间窗、执行全量推送、决定最终方案、替代审批、编造未收录条款/预案。
- 所有高后果输出必须能回答三个问题：**依据了什么数据？用了什么规则/策略？谁批准执行？**

### 3.6 AI 不可替代性矩阵（2026-08-18 新增，回应用户"如果只是规则调用，旧系统也能做到"的质疑）

> 这是对全文最关键的审视：**逐环节问"换成规则引擎/传统系统行不行？"**。结论必须先立住：**一个纯规则系统（阈值触发 + 查表 + 模板）确实能覆盖我们 40% 的界面效果，但那不是产品，是装饰。** 我们与"旧系统 + 规则升级"的差异，全部集中在下面这张矩阵里。

| 环节 | 规则引擎/传统系统能做到什么 | AI 的不可替代增量 | 为什么规则不行 | B 线落点 |
|---|---|---|---|---|
| **非结构化信号理解** | 只能读结构化字段（数值>阈值） | 从**文本/语音/多来源描述**中判断"发生了什么"——客服投诉原文、现场口头描述、天气预警措辞 | 规则查不了"词没写进字典"的表达；语义模糊时规则直接哑火或误判 | M1 感知 → M4 事件分类（判断"拥堵"是找不到路/受伤/设备故障/恶劣天气，4 种处置完全不同） |
| **跨系统非结构化整合** | 能拼表，不能"读懂" | 把港口公告、广播、票务、客服信号、乘客 UGC **互相关联成一处局势图**，并发现"孤立看都不异常、合起来可疑"的弱组合 | 规则只能做字段级 join；"A 系统 3 条 + B 系统 2 条 + 时间接近"这类弱信号组合，规则无法表达 | M1 态势总览、库外异常识别（X 系列） |
| **长链路演绎推理** | 只能执行预写好的"如果-那么"链 | 对**未见过的组合**做多步推演：岸上事故 → 下船口调整 → 接驳分流 → 哪些人暂缓 → 时间窗连环更新 | 规则引擎的组合爆炸：预写所有分支不现实，漏掉一条就漏掉一次处置 | M4 航变响应影响推演、M2 登离船联动 |
| **非规则系统推理（开放域）** | 只能识别库内模式 | **发现库里没有的异常信号**——偏离常态但未收录,生成提醒卡并建议人关注 | 新事件一旦不在规则表里，规则系统"看不见"——这是封闭系统与开放系统的本质区别 | §4.11 库外异常识别（A18/A19） |
| **方案组合的"为什么"** | 能查表返回模板 | 从库中选择/组合后，**给出为什么选这个组合的逻辑论证**（推理附件），并能在人追问时解释 | 规则返回"模板 B"，但说不清"为什么是 B 不是 C"；评委/船员追问时无解释能力 | §4.11 推理附件、M5 建议卡片 |
| **多语言/多语境一致性** | 无法模板化 5000 人的个性化表达 | 同一决策翻译成不同语言、不同乘客群（老人/家庭/轮椅）的**一致但适配**的表述 | 规则模板固定，无法既统一口径又照顾人群差异 | M6 触达输出（话术生成） |
| **自检与信度校准** | 无自我评估能力 | 对自己的每个判断给出**置信度**；低信度主动转人工；推理链自检冲突时提权提醒 | 规则系统不知道自己"可能错了" | §4.11 提权机制、R11 低信度转人工 |

**由此得出三个"AI 高利益区间"（守住它们 = 守住产品）**：
1. **开放域异常发现**（§4.11）——纯规则系统物理上做不到，是我们区别于"旧系统 + 规则升级"的**头号卖点**；
2. **长链路推演 + 弱信号整合**（M4/M1）——把"人肉拼图 20–45 分钟"压成分钟级，是 V2 的直接兑现；
3. **推理附件/证据链（可解释性）**（§4.11）——"每个方案都能说清为什么"，规则系统天生不具备，是 V3 的直接兑现。

**反之，明确"AI 不背书的低值区间"（别在这些地方堆 AI）**：确定性计算（排队/时间窗/人数）必须纯代码；高后果执行必须走审批门与人工接管——这两处堆 AI 反而露怯。

> 答辩金句：**"我们不是用 AI 给规则引擎化妆，而是把系统立在规则引擎到不了的三块地上：看见没见过的、推演没写过的、解释说不清的。"**

### 3.7 推理附件模型的全系统推广（2026-08-18 新增，依用户意见 2 扩展）

> 用户问题："AI 证据链推理 + 附加推理附件的模型还能用在系统的哪些部分？"——答案是**所有 AI 参与的判断环节都标配推理附件**，不只是方案生成。推广清单：

| 环节 | 推理附件内容 | 主界面展示 | 详情附件可展开 |
|---|---|---|---|
| 事件分类（M4 步骤 1） | 为什么判为 E 系列哪一类、依据哪些信号、置信度 | 分类结果 + 置信度徽标 | 读到的信号清单 + 分类理由 |
| 影响推演（M4 步骤 2） | 为什么影响这批人、时间窗如何算出、哪些假设 | 影响摘要（人数/范围） | 计算输入 + 假设列表 |
| 方案组合（M4 步骤 4） | 为什么选 A03+A05、为什么不用方案 C | 方案卡 + 推荐理由 | 备选方案对比表 |
| 库外异常提醒（A18） | 为什么可疑、可能走向、建议观察项 | 风险横幅 + 高亮可疑环节 | 完整推理链 + 依据信号 |
| 客服问答（M4.5） | 答案依据的条款编号/时间线 | 答案 + 引用标记 | RAG 命中原文 |
| 审批决策（M5） | 给审批人的决策摘要：结论+证据+信度+替代 | 审批卡 | 完整证据链 + 签署所需材料 |
| 升级判定（R10 超时升级） | 为什么升级、超时多少、谁被通知 | 升级通知 | 时限计算 + 通知记录 |

> 统一原则：**推理附件是"判断的交付物"，不是附加品。** 每个 AI 判断 = 结论 + 置信度 + 推理附件（可展开）。这同时是 V3 可审计信任层的完整落地——不是"出事才查证据"，而是"每个判断自带理由"。

## 部署与模型选型（初版）

### 部署形态

| 层级 | 部署位置 | 用途 |
|---|---|---|
| 本地边缘（船载） | 邮轮本地边缘节点/船载数据中心 | 实时闭环：事件分类、确定性计算、本地小模型、审批流、触达 |
| 云端/岸基（可选） | 云服务或公司数据中心 | 非实时任务：长文档解析、复杂方案离线优化、模型更新、远程审计 |
| 卫星链路 | 外部传输 | 仅异步同步/远程支持，不进入实时闭环 |

### 模型选型建议

| 任务 | 模型规模 | 选型考量 |
|---|---|---|
| 事件分类/严重度判定 | 轻量小模型或规则/传统分类器 | 实时、低延迟、可离线、避免幻觉 |
| 意图识别/客服路由 | 轻量小模型 | 本地即可，不需要大模型 |
| 检索向量化 | 轻量 embedding 模型 | 本地 RAG 用 |
| 条款/策略检索重排 | 轻量 reranker 或规则匹配 | 优先确定性匹配 |
| 话术生成/解释 | 0.5B–8B 端侧小模型 | 短文本、模板约束、可离线 |
| 复杂方案组合/长链路推理 | 本地 7B–14B 或云端大模型 | 实时闭环尽量本地；云端仅异步增强 |
| 长文档/法规解析 | 云端大模型（非实时） | 离线批量处理，不阻塞船上调度 |
| 审计/自检 | 独立小模型/规则检查 | 防止自己给自己判作业，确定性优先 |

> 原则：**能不用 LLM 就不用；能用小模型就不用大模型；能离线就不用云端。** 只有长文档理解、复杂跨域推理、异步分析等非实时场景才考虑大模型。

## 更多可迁移案例（速查）

- **Autosre**：检测 → 诊断 → 行动 → 验证四步自治事故响应，适合设备/运营异常闭环。
- **Arclo**：幻觉检测 + 置信度路由 + Blast Radius 决策，适合“AI 给方案前先判断影响半径”。
- **Pranjal / WorldCup**：置信度门控、walk-forward 验证，适合预测/建议类功能诚实性。
- **Ripple / Synkron**：事故模式记忆库、SOP/文档腐坏检测，适合策略库与制度同步。
- **ScuttlePay**：AI 执行任何高后果动作前必须有最小权限、限额、审计。
