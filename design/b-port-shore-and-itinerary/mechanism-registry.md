> 定位：**全系统治理/控制机制的母文档与统一索引**。后续作品集页面（P9 场景、P13 核心 AI 子系统、P15 事件治理等）引用机制时一律以本文件的编号与名称为准；详细设计细则以 `event-governance-framework.md` 各节为准（本文件给解析与逻辑，框架文档给字段级规则）。

> 层级判据（2026-09-04 定稿）：一级=有独立状态机/生命周期的系统能力；二级=一级内部的实现细则（规则/参数/形式）；全局=跨 ≥3 阶段或任何节点可用。机制名用"系统能力"命名，规则句（如"只审一次"）只作为二级细则的说明语，不作为机制名。

## 2. C0 前置决策支持（决定前支路）

> 主活动阶段：S2 尾（外挂支路）。框架出处：§4.15。
> 一句话：航变决定**成立之前**，把多源弱信号变成"多备选 × 多维度价值"的**可比较决策依据**，供船司选案、船长安全确认——**参谋，不决定**。

**设计目的与逻辑**：船长/船司在法定与责任上拥有航变决定权（船长安全否决权不可让渡），但决定质量受"信息拼图慢、价值看不清"制约。C0 的价值是让决定"更早、更准、更敢"：AI 不回答"要不要航变"，而是回答"采用方案 X/Y/Z 各自付出什么、得到什么、风险在哪"。这同时是 AI 高地②（长链路推演+弱信号整合）在"决定之前"的兑现，与决定后 C2 影响链推演形成前后两段价值。

- **C0.1 四维价值评估**：对每个备选航变方案（继续/延期/改靠/换港等）输出四维：**运营影响**（登离船/接驳/时间窗/资源缺口，确定性内核计算）、**经济影响**（赔付估算/停售损失/港口费差/改靠与差旅分摊——**相对量级 + 显式假设，不做货币化承诺**，对齐 PRD §8.1 诚实量化口径）、**风险影响**（安全等级/群体风险/声誉客诉/合规，与 C3.2 L4 判据联动）、**综合价值分**（加权评分，权重可配、可解释）。
- **C0.2 决策支持卡**：一份给船司（业务选案依据）、一份给船长（只看安全影响重点卡，作安全确认/否决输入，**不把它当执行指令**）。每张卡带 G3 推理附件。
- **C0.3 决定前增量刷新**：决定成立前信息源变化 → 决策支持卡**增量刷新**（版本闸/频次闸，如 30/60 分钟版本批次），供船司重新比较备选——这就是"重新讨论"的正当位置（发生在决定**之前**）。
- **C0.4 重推闸门**：仅当 3 个候选全不满足或基线失效时，人才显式触发整体重推（限频、留痕）；不随信号逐条重推。

**角色与时点**：ClarSyn=参谋（最早接入：预警信号出现即开始聚合弱信号）；船司=业务选案；船长=安全否决/最终确认；法务/客服=备选涉赔偿时条款复核与口径预审。航变决定成立（=船司选案 + 船长安全确认）后进入"已确认基线"，转交 C2/C3 走执行期。
**与其他机制关系**：输入复用 C1 的信号聚合；输出与 G3 绑定；决定成立后与 C2 交接；边界与"不做航变决定"承诺一致（PRD §2.2/§2.3）。
**可视化提示**：P9-1 画在"外部航变决定成立"节点之前，用**虚线外挂支路**，避免观者误读为决定主体。

## 3. C1 事件识别与分类

> 主活动阶段：S1–S2。框架出处：§4.2/§4.4/§4.11/PRD M1·M4。
> 一句话：把原始信号变成"这是什么事件、什么等级"的判断入口——系统一切后续动作的起点。

**设计目的与逻辑**：先判类别再决定资源与权限，不能靠 LLM 自由发挥；分类错误会让后续整条链走错方向。因此本机制采用"事件分类库 + 等级库 + 分类模型 + 规则复核"的组合（规则复核兜底 LLM），保证低风险、可审计。
**事件形成口径（2026-09-04 澄清）**：**所有事件只有两个来源——①弱信号经信度评估升级为正式事件；②突发强信号直接判入**。弱信号（尚未成为事件）阶段不叫"库外事件"：信度不足时停留为态势 chip/前置提醒；信度达标才成为事件候选，进入分类匹配。**X 库外事件 = 已被关注的事件候选在分类/匹配阶段库内无对应（分类失配 / 复合事件）**，不是"事件确认前的弱信号状态"。

- **C1.1 事件接入与标准化**：多源信号（船方内部/外部接口/现场感知/客服/库外 AI 感知）→ 统一事件模型；输入信息只做原始信号接入，不做判断；数据三态诚实标注（真实/模拟/不可得，R6）。
- **C1.2 事件形成与分类判定（L1–L4 初判）**：两路入流——弱信号信度达标升级 / 突发强信号直接判入 → 7 大类 + X 系列映射；等级初判不是最终定级——后续由 C3.2 判据与 C5.6 恶化升级动态修正。
- **C1.3 库外异常识别（X 系列）**：事件候选在分类/匹配阶段**库内无匹配（分类失配/复合）** → AI 评估风险等级、生成**提醒卡（A18）**并按风险路由 + 抄送（A19），**只提醒不执行**；人处置后可升级为正式事件回写分类库（这是 AI 高地①"看见没见过的"落点，P9-3 场景主线）。注意与 C1.2 的弱信号阶段区分：弱信号未成为事件前走"信度评估→态势 chip/前置提醒（§4.11.5）"，不直接进 X。
- **C1.4 低信度转人工（R11）**：分类置信度低于阈值/证据不足/规则冲突/策略无匹配 → 强制人工复核，不得自动分发。与 G3.2（异常提权）协同：低信度但风险高的信号用"着重提醒"而非静默转人工。

**与其他机制关系**：喂给 C2 推演；X 系列升级路径与 C5.6 出口共用"弱信号→信度→正式事件"同构；全程挂 G3。
**可视化提示**：S1–S2 主轴块；X 系列可用高亮色（高地①卖点），提醒卡与正式事件分开画。

## 4. C2 方案推演与生成

> 主活动阶段：S3。框架出处：§4.8/§4.9/§4.11.5/PRD M4。
> 一句话：在"已成立事件/决定 + 本船状态"之上做影响链推演，从库中组合出**可审批、可审计**的候选方案。

**设计目的与逻辑**：方案不是让 LLM 现场发明，而是"事件→影响→资源→方案"的受约束组合：确定性内核保证数字可复现（R1），动作库（A01–A19）保证动作可审计，AI 只在推演与选择处增值。同时明确边界：**本系统不预测"是否发生航变"，只推演"已成立决定"之后的影响链**（登离船/接驳/时间窗/船员任务/安全与乘客服务）。

- **C2.1 确定性影响评估**：影响人数、资源缺口、时间窗连环更新全部确定性计算（排队论/规则引擎），LLM 不参与算术。
- **C2.2 备选方案生成（A/B/C）**：同一事件生成 2–3 个候选（约束/资源/口径差异），为 C3.6 修订与 C0.4 重推提供素材；每个候选附带"为什么不用另一个"的对比说明（供 G3）。
- **C2.3 知识检索（RAG）**：策略库/条款库/事故模式记忆库检索，输出带条款原文编号（R8）；检索不到 → 显式标注"待人工确认"，禁止无出处承诺。
- **C2.4 推理附件挂载（调用 G3）**：方案卡 + 推理附件（读了哪些信号、算了什么公式、检索了哪条条款、置信度、备选对比）全量标配。

**与其他机制关系**：结果进入 C3 审批；被 C3.6 修订打回时走参数重算/备选切换（不重推）；C0 前置决策支持若在决定前生成过备选，此处可复用其约束集。
**可视化提示**：S3 主轴块；"备选 A/B/C + 推理附件"作为块内细则。

## 5. C3 权限路由与审批门

> 主活动阶段：S4（升级出口跨 S4–S7）。框架出处：§4.2.4/§4.2.5/§4.10/§4.13/PRD R3·R9·R10。
> 一句话：**谁有权批准什么**——审批门不是单点按钮，而是一族"事件级 + 动作级 + 生命周期 + 落地形式"的权限体系，是代码级结构性控制（R3：执行路径不经 LLM，模型无直接执行工具）。

**设计目的与逻辑**：回答三个问题——①什么事件要人批（事件级）；②同一动作投到不同端口要不要不同门槛（动作级）；③批的过程怎么走完、被驳回怎么办（生命周期）。设计主线是"**人审批一次、责任一次讲清**"：决策审批一次（L3），执行分派不重复审方案，避免效率崩与责任不清。

**审批状态机（C3 主状态流）**：
```
方案（C2 产物）→ 待审（L3）
   ├─ 通过 → 确认方案基线 → 交 C4 递送
   ├─ 驳回 → C3.6 修订三形态 → 重审 R+1（循环，可多次）
   ├─ 超时 → C3.7 双路径（默认执行+审计 / 涉风险升 L4）
   └─ 转人工接管 → G1（S4 为最常见触发点）
```

- **C3.1 事件级审批（L1–L4）**：L1 自动分发基层（留痕）；L2 值班船员/客服确认；L3 运营经理（航次/宾客运营经理）/法务审批；L4 船长/最高层决策。等级只决定"审批人是谁"，不决定动作细节。
- **C3.2 L4 船长决策区判据**：L4 不是"大事标签"而是**船长决策区**——触发判据是**决策权归属**而非影响大小：①安全不可逆（人身/公共安全、作业须紧急中止、疏散）；②群体必达（滞留/骚乱/拒绝下船）；③法定对外责任（海事当局/港口国/警方/保险/媒体）；④不可逆高后果且无代码级缓释。**反向测试口诀**："船长此刻在驾驶台忙碌，这个决定不找他也能被正确地做掉吗？能 → 不上 L4。"依据：ISM Code §5.2（船长最高权威限定于安全与防污染）。
- **C3.3 船长知会/抄送通道**：L2/L3 常规事件（含下船/接驳方案重排）方案变更**抄送/知会船长，不进入船长审批队列、不阻塞执行**——船长已知航变大局，避免增加信息负载、拖慢响应（A19 的知会语义 inform ≠ approve）。
- **C3.4 动作级审批（投放审核矩阵）**：与事件级正交的第二个审批维度——决定审批级别的是"**可见性 × 可撤回性 × 后果**"，不是端口类型：公共可见/不可撤回（广播、全船屏）须 ≥L2 人工确认；个人定向/可回撤（App 推送）可 L1 自动；统一口径/赔偿类须 L3/L4。**"审一次"不撤销端口级投放校验**。
- **C3.5 审批生命周期（一次审批规则）**：L3 对方案整体做一次决策审批；通过后 L2/L1 收到的是**已确认方案中分配给自己的任务包**，不再重新审 L3 的方案（避免重复审批、责任不清）；效率由"决策一次 + 分派多次"保证。
- **C3.6 方案修订三形态（驳回循环）**：审核不通过时的修改 = **受约束编辑**，不是自由发明、也不是默认让 AI 重新推理：
  - **参数级重算**：改约束（时间窗/批次人数/接驳车次/优先级）→ 确定性内核重算受影响子步骤（秒级），不动 AI 推理；
  - **备选切换**：从推理附件自带的候选 A/B/C 中换一条（即时）；
  - **受限动作编辑**：在动作库 A01–A19 内换/增动作（下拉选择，不自由输入）。
  每次修订追加 diff + 原因 + trace 轮次（R1/R2…）后重审。**为何不让 AI 重推**：长链路重推耗时（演示级 234s+）、卷入范围变大、破坏"人审批 + 确定性重算"的可审计性；仅当 3 个候选全不满意时人才显式触发"重新推演（放宽约束）"（限频、留痕，衔接 C0.4/C2）。
- **C3.7 超时双路径（超时升级出口）**：审批超时按时限体系（§4.2.1：L3 常规 30–60 分钟量级）分两路——**常规方案**：超时默认执行 + 审计回写（满足快速响应，不留无人处理的死区）；**涉风险方案**：超时自动升级 L4（宁可多打扰，不沉默）。这是"升级"在审批域的出口（另半条在 C5.6）。
- **C3.8 四档确认签署**：审批动作的落地形式——L1 自动留痕无签署；L2 电子确认记录（身份/时间）；L3 电子签署（确认单 + 条款编号 + 审批人 + trace_id，可导出 PDF 打印）；L4 紧急处置**事后补签**（安全优先、事后可回溯）。

**与其他机制关系**：被驳回转 G1 接管（S4 主触发点）；超时涉风险出口直连 L4；通过后交 C4；签署/修订全程进 G2 审计。
**可视化提示**：S4 唯一主轴块；细则（事件级/动作级/生命周期/签署）缩进在块内；**"升级"不画独立盒子**——超时升级画成块右缘箭头出口，与 C5.6 的恶化升级箭头在时间轴语义上合成"关系 A 升级线"。

## 6. C4 执行递送与反馈

> 主活动阶段：S5–S6。框架出处：§4.2.6/§4.14/PRD M5·M6。
> 一句话：把已确认方案按"三级粒度"送达到执行组织，并把执行结果按"包状态"收回——**AI 的手只伸到任务包**。

**设计目的与逻辑**：解决三个执行层矛盾——执行自由度（末端不该被规定每个动作）、反馈成本（逐人收集不可行）、信息负载（AI 引入后末端不能更忙）。方案：递送粒度与 L1–L4 审批维度**正交**（不是第 5 级），按组织层级切分信息内容。

- **C4.1 方案级递送（decision）**：接收者=L3（判据触发时船长）；内容=目标/约束/影响人群/资源缺口/合规/备选对比/风险；AI 生成整案 + G3 推理附件。
- **C4.2 任务包级递送（task-pack）**：接收者=L2（值班/领班/部门）；内容=**区域/环节/岗位角色** + 期望结果 + 优先级 + 建议执行方式；AI 拆包 + 字段级建议——**AI 结构化信息到此为止**；反馈=**包状态**（完成/受阻/延误），不做逐人反馈。
- **C4.3 现场提示级递送（field-hint）**：接收者=L1 现场人员；内容=一句话可选建议（时序提示/优先人群等）；AI 可生成但**必须经 +1（值班/领班）转达**；现场人员仍按现有系统（对讲/现有 App）接收 +1 指挥。
- **C4.4 AI 手边界**：**AI 信息写到任务包为止；现场提示只能作为可选注释、经 +1 转达；最末端服务人员不直接订阅 AI 指令**。收益：执行自由度（任务包只给"对象+期望+建议方式"）、反馈成本（包状态 + 感知端口自动补粒度，与 G1.3 最小登记一致）、信息负载（末端零新增）——"更快、更准、不更忙"。
- **C4.5 执行反馈池与包状态回传**：L2 包状态 / L1 最小登记 + 端口感知 → **append-only 反馈池**（G2）→ 周期性并入主事件血缘 → 闭环恢复点；异常升级链预判 → 沿血缘立即通知决策层。执行端分类：系统自动执行 / 人员执行 / 下游协同告知（各走不同触达与回执路径）。

**与其他机制关系**：输入来自 C3 确认基线；反馈结果喂给 C5 监控；全程 trace（G2）；涉及投放的动作同时受 C3.4 约束。
**可视化提示**：S5–S6 主轴块；**AI 手边界虚线**画在任务包层与现场层之间（这是轴图上最醒目的一条设计线）。

## 7. C5 监控与复检

> 主活动阶段：S6–S7（含执行期监测与挂起后复检）。框架出处：§4.2.2/§4.2.3/§4.2.7/§4.12.5/PRD R10。
> 一句话：事件进入执行或挂起后，"谁在看、看什么、怎么判定恢复或恶化"——是任务型时限与持续运营型判据的统一出口。

**设计目的与逻辑**：排队/高峰类事件会持续很久，仅因墙钟超时就升级是误报；航变类事件"发生与恢复"由外部决定，本系统只是响应方——两类事件不能共用同一监控语义。因此区分监控对象（P1/P2），并对任务型/持续型分别使用墙钟或物理劣化判据。

- **C5.1 挂起语义**：持续运营型/低风险任务事件执行后判定挂起 = **闭合**（时间轴琥珀空心点，不再渲染矩形）；不因墙钟升级，升级仅由物理劣化/安全阈值触发（与任务型事件的墙钟超时区分）。
- **C5.2 监测模式 P1（现场端口）**：监控本系统**感知端口**（排队/闸机/时间窗/设备）；适用局部拥堵、登离船排队、设备异常（E03/E01/E04/E07 等）；事件发生/恢复看同一批端口，**自证自闭环**。
- **C5.3 监测模式 P2（外部信息源）**：监控**外部传入信息源**（船期/港口窗口/天气/接驳），不落在本系统端口；适用航变响应（E09 等，外部决定、本系统响应）。**可读性分层**：执行中外部源可读（ETA 更新/港口通告）→ 判"是否仍成立"；不可读 → 用"影响副作用"（预计排队/接驳余量）代监测；仍不可读 → 人工接管 + 最小登记（G1），不等不确定性空转。
- **C5.4 周期复检**：挂起后按周期重新判定该事件（复检只进日志，不生成新事件）；判定三类：`still`（仍同类，仅日志）、`recovered`（恢复，关闭监测）、`upgrade/accident`（恶化/事故 → 走 C5.6 派生）。
- **C5.5 循环提醒**：挂起/接管期间不能无限静默——周期提醒含当前态势快照 + 一句标准建议；连续 N 次未解除 → 提醒自动升级到更高层级（值班→运营经理→船长知会），并提高提醒频率。终止条件：人确认结束 / 感知回落正常 / 事件正式关闭。
- **C5.6 恶化升级出口（关系 A 升级线）**：物理劣化/安全阈值触发 → **派生新事件**（如 L2→L3、拥挤→E13/E20）并沿 parentTrace 挂血缘（G2.2）；在时间轴画升级线（关系 A）。**这是"升级"在状态域的出口**（另半条在 C3.7，两端箭头合成完整升级语义）。

**与其他机制关系**：接管后的受监控由 G1 触发、C5 执行；派生事件交回 C1/C2 重新进入治理主线；复检产物进 G2 日志。
**可视化提示**：S6–S7 主轴块；复检三出口（记日志=虚线回环 / 恢复=绿色点 / 恶化=升级线箭头）是画面关键。

## 8. 全局机制

### 8.1 G1 人工接管

> 任意节点可用。框架出处：§4.12–§4.12.5。
> 一句话：人打断自动流、把执行权交给现有系统时，系统不消失，而是切换为"**观察 + 记录 + 建议**"的副驾驶 + 行车记录仪模式。

**设计目的与逻辑**：本系统是"决策增强层"而非"执行替代层"——保留船司现有调度系统（广播台/对讲/App 后台/纸质 SOP）作为人工接管端口；接管不等于逃逸出口，事件仍受监控，时限压力不消失。
- **G1.1 接管触发四式**：T1 审批时主动接管（最常见：人点"转人工接管"而非确认/驳回）；T2 超时升级后接管（升级通知带"一键接管"）；T3 系统降级触发（T1/T2 韧性故障建议降级为人工）；T4 现场先行处置后补录（事后补建接管事件、回溯补录时间线）。
- **G1.2 观察 + 记录 + 建议**：接管后系统继续读感知数据，持续生成"若按标准流程会怎么处理"的建议（仅供展示不执行）；自动记录接管时间线（谁、何时、从哪一步）。
- **G1.3 最小登记**：紧急情况下**绝不要求人补结构化信息**——只需一句话处置说明或处置单编号，其余由系统自动记录；人工登记文本标注来源，与系统记录区分。
- **G1.4 接管期循环提醒升级**：接管 ≠ 终结，进入受监控的人工模式；按 C5.5 循环提醒，连续未解除自动升更高层知会。

### 8.2 G2 血缘与审计

> 全程贯穿。框架出处：§4.13.2/§4.14。
> 一句话：每一个动作、每一次变更、每一份方案都能回答"从哪来、谁批准、变了什么"——**沿血缘做状态更新，不重复"发现"**。

- **G2.1 trace 链**：每条消息/动作带 trace_id：事件 → 建议卡/推理附件 → 审批签署 → 端口执行日志（谁/何时/什么/回执）→ 审计包。
- **G2.2 血缘链（parentTrace）**：主事件 → 同级兄弟派生、下游子事件（可观测物理症状）、异常演变（升/降级）；派生事件更新**沿血缘回写主事件**，共享监控上下文，不重复"发现"同名事件；挂起期按关系 A（画线）/关系 B（仅日志）区分表达。
- **G2.3 复合事件资源-触达聚合**：在跑事件按"受影响资源/端口/人群"归组 → 识别"同一闸机/批次同时被多个事件指向" → 在方案组合/决策层合并成复合事件引用；避免同一物理资源被各自处理、指令冲突；审计保留各来源 trace。
- **G2.4 审计包**：append-only + 哈希链防篡改；一键导出 PDF（事件详情 + 证据卡片 + 推理附件 + 审批签署 + 各端口执行日志），用于答辩/复盘/合规存档。
- **G2.5 事故模式记忆回写**：处理结果沉淀为可复用历史模式（业务轨）——同类事件下次更快。
- **G2.6 坏例双轨（模型轨回归）**：分类错误/检索未命中/方案不适用等由人依托推理附件"标记坏例"→ 回写评测集 → 回归（演示阶段以设计闭环呈现，不做真实训练迭代）。

### 8.3 G3 推理附件与证据链

> 全量标配（S2–S8 每个 AI 判断）。框架出处：§4.11。
> 一句话：**"每个 AI 判断 = 结论 + 置信度 + 可展开证据链"**——不是出事才查证据，而是每个判断自带理由（AI 高地③）。

- **G3.1 全量标配**：分类/影响/方案/异常/客服/审批/升级各环节的 AI 判断都带推理附件（读到的信号清单、计算公式、条款引用、置信度分解、备选比较、兜底边界）。
- **G3.2 异常提权**：AI 自检发现异常苗头（分类失配/复合可疑/推理链冲突）→ 附件从"详情"提权为"着重提醒"（风险横幅 + 高亮可疑环节）；提醒类**只提醒不执行**，错误成本 = 一次多余知会而非一次错误执行。
- **G3.3 附件组成要素**：证据引用、置信度、替代方案、假设列表；可展开、可核对、可打印；坏例标记入口挂在附件旁（G2.6）。

### 8.4 G4 韧性降级 T0–T3

> 全程（系统故障时）。框架出处：§4.5。
> 一句话：系统自己"病了"也要知道怎么优雅地病——按故障域隔离 → 熔断 → 优雅降级 → 人工接管四档，任何单点故障（卫星断/模型挂/断电）都不让船回到"原始状态"。

- **G4.1 T0 全功能**：本地 AI + 外部数据 + 全审批流在线。
- **G4.2 T1 外部降级**：云/卫星/外部数据不可用 → 用缓存与本地库，外部请求熔断 + "降级快照"标注（外部故障域隔离）。
- **G4.3 T2 本地降级**：本地 AI/部分感知不可用 → LLM 退回模板、感知退回上一快照 + 标注、自动动作降级为"建议 + 人工确认"（优雅降级 + 规则回退）。
- **G4.4 T3 核心不可用 → 人工预案**：断电/局域网/核心节点故障 → 触发人工应急预案（广播/对讲/纸质 SOP/现场指挥），系统不再承诺数字 RTO；**审计不可降级**——人工操作须在恢复后补录审计。
