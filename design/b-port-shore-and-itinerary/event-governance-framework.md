## 4. 事件治理与权限流转框架

> 这是 AI 价值落地到运营流程的关键：**不是所有事件都要打扰高层，也不是所有事件都可以自动执行**。系统必须能区分轻重、匹配权限、超时升级、低信度转人工。

### 4.1 事件分类库（初版框架）

| 事件大类 | 示例 | 典型影响 |
|---|---|---|
| 人流/秩序类 | 登船口堵塞、安检排队过长、离船批次混乱、接驳点滞留 | 等待时间变长、乘客焦虑 |
| 设施/设备类 | 廊桥故障、电梯扶梯停运、行李系统异常、岸电/供水延迟 | 动线受阻、时间窗失效 |
| 外部环境类 | 台风/大雾/大风、港口临时管制、道路拥堵、接驳中断 | 靠离泊调整、行程变更 |
| 安全/健康类 | 乘客受伤、突发疾病、人员落水、火警/疏散 | 立即升级，安全优先 |
| 合规/赔偿类 | 航变退赔、条款争议、投诉升级、群体维权 | 法务/最高层介入 |
| 信息与运营沟通类 | 大量乘客对同一调度信息反复询问、多渠道调度信息不一致、错误信息传播 | 统一口径、定向告知、减少信息冲突 |
| 特殊人群类 | 老人/轮椅/儿童通道受阻、无障碍需求无法满足 | 需要定向资源调度 |

> 分类库不是一次性写完，而是先建框架 + 首批样例，后续按真实事件补充。

### 4.2 事件等级与权限流转（建议初版）

| 等级 | 描述 | 默认处理方式 | 最小审批级别 |
|---|---|---|---|
| L1 轻微 | 局部、低风险、可通过信息/现场调整解决 | 系统自动分发给基层执行端，并监控处理结果 | 无需审批，但留痕 |
| L2 一般 | 影响一段流程或一批乘客，需要现场人员判断 | AI 生成建议 → 值班船员/客服确认 | 值班确认级 |
| L3 严重 | 影响航程/大批乘客/涉及赔偿或法务 | AI 生成方案+证据 → 运营经理/法务审批 | 经理/法务审批级 |
| L4 紧急 | 安全/群体事件/全船级响应 | AI 快速生成态势与候选方案 → 船长/最高层决策 | 船长/最高级 |

- **轻事件自动分发**：低风险、低权限策略（如显示“当前接驳排队较长”、通知现场船员增开通道）可直接自动下发到对应执行端，系统跟踪“是否处理、是否超时、是否升级”。
- **重事件人工审批**：高风险、高权限策略（全量推送、赔偿执行、航线变更正式通知、紧急疏散）必须进入审批队列，审批门为代码级。
- **升级机制**：每个等级设置处理时限；超时未处理自动升级到上一级并通知更高权限人。不能无限等待某一个执行端。
- **异常/不确定处理**：当事件分类置信度低、证据不足、规则冲突、或策略库无匹配项时，强制进入人工复核，不得自动执行。

### 4.5 系统韧性等级（系统自身故障 / 断电断网）

> B 线是船载调度系统，必须考虑系统自己“病了”怎么办。这里的等级与乘客事件等级 L1–L4 分开，描述系统可用性下降程度。

| 等级 | 状态 | 可用的能力 | 降级策略 |
|---|---|---|---|
| T0 全功能 | 系统全功能在线 | 本地 AI + 外部数据 + 全审批流 | 正常运行 |
| T1 外部降级 | 云服务/卫星/外部数据不可用 | 本地规则、本地小模型、缓存条款库仍可运行 | 不依赖外部，使用缓存与本地库 |
| T2 本地降级 | 本地 AI/部分感知不可用 | 规则模板、静态快照、人工确认仍可运行 | LLM 退回模板；感知退回上一快照 + 标注 |
| T3 核心不可用 | 电力/局域网/核心节点故障 | 系统无法提供数字服务 | 触发人工应急预案：广播、对讲、纸质 SOP、现场指挥 |

- 策略库需包含**系统韧性策略**：UPS/备用电源、双局域网、本地缓存事件/条款/策略、离线 Mock 数据、人工应急预案。
- 当系统进入 T1/T2/T3 时，所有自动动作应降级或暂停，并通知对应决策端。

### 4.6 标准化响应描述规范

> “主要响应”只是概述，真正可执行的定义必须使用下面的规范。**AI 只能从库中选择/组合，不能自由编造响应。**

统一格式：

```
响应 = 事件等级
     + 决策端（谁审批/谁确认）
     + 执行端动作（哪个端口执行什么动作）
     + 告知端口（必须通知哪些端口）
     + 回滚/升级规则（超时怎么办、失败怎么办）
```

示例（E01）：

```
E01 登船口/安检排队过长
等级：L1/L2
决策端：值班船员确认
执行端：现场安保/服务台执行“增开备用安检通道”
告知端口：乘客 App 推送排队提示、广播通知候船区
升级规则：15 分钟未处理 → 自动升级 L2/运营经理
```

## 用户投诉 / 情绪升级的边界

- 常规投诉、情绪安抚、服务补救属于 **C 端客服/宾客服务**职责，不进入 B 系统核心流程；
- 如果情绪升级发生在 **邮轮紧急事件或安全事件**场景中，则按安全事件处理，自动升级到 L3/L4；
- B 系统与 C 端客服的关系是**接口关系**：
  - 输入：客服系统可把“大量同类投诉/舆情风险”作为事件信号传给 B 系统；
  - 输出：B 系统向客服系统提供统一口径、条款依据、事件时间线。
- 因此“用户投诉/情绪升级”**不直接作为 B 端自动转人工/升级的独立触发条件**，除非它演变为安全/群体事件。
