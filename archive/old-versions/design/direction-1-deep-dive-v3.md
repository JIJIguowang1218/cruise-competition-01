# 方向一升级版：全船空间×时间双维实时调度系统（v3）

> 版本：v3 | 更新：2026-08-16 | 依据：`research/round2/pain-points-v3.md`、Gate 1 决策 A
> 关系：本文为当前方案基准；旧 `design/direction-1-deep-dive.md` 作为 v1 保留（其餐厅分流场景吸收进本文 4.2）。

## 1. 产品定义

**一句话**：船载感知 + 确定性调度 + 离线 AI 的**全船空间×时间双维实时调度系统**——实时感知登离船、餐饮、娱乐与港口端四类场景的拥挤/空闲状态，向乘客推荐“去哪里、几点去、怎么走”，向船员提供全局热力与调度建议，在航程异常时主动完成“解释—方案—赔偿路径”的闭环沟通。

**本质判断**：邮轮是 5000 人共享的封闭空间，资源（餐厅/剧院/泳池/港口接驳/通关通道）在时间上错配。船不能加餐厅、不能扩码头，但可以把需求从“拥挤处/高峰时”引导到“空闲处/平峰时”。这是**空间×时间的调度问题**，不是推荐系统，也不是 Dashboard。

## 3. 用户与价值

| 角色 | 场景 | 核心需求 | 使用方式 |
|---|---|---|---|
| 乘客（第一用户） | 午餐去哪吃、登船日怎么走、离船怎么约车、航变怎么办 | 少排队、少焦虑、信息可信 | App/船载屏：实时热力 + 错峰建议 + 航变通知 |
| 船员/运营（第二用户） | 全局哪里在堵、何时触发分流、投诉怎么答复 | 看得见、调得动、说得清 | 船员端：全局热力 + 预警 + 建议动作 + 事件沟通模板 |
| 邮轮公司/港口（买单者） | 投诉率、NPS、港口端秩序、航变处置成本 | 可量化价值 | 运营数据报告：分流效果、等待时间变化、投诉下降 |

**价值指标（方案书口径）**：
- 高峰场景等待时间下降（以原型/仿真给出目标区间，不写无出处的“减少 50%”）；
- 航变事件响应时间：从“事后群诉”变为“主动预案 + 分钟级推送”；
- 港口端：接驳信息一次说清，减少码头端滞留与投诉；
- 船员：从重复回答“哪里人少”中解放，转向高价值服务。

## 4. 场景设计（四大场景 + 一个事件响应模块）

### 4.1 登离船场景（PC）
- 感知：登船日安检/check-in 排队长度、行李区人流、离船日廊桥/行李提取区密度。
- 决策：按舱房分区/行李号分批推送“建议到达时段”；离船日生成个人化下船时间窗。
- 行动：App 分时预约 + 港口端接驳指引（地铁/出租/网约车/官方短驳）。
- 指标：登船排队时长分布、离船高峰错峰比例、港口端问询量。

### 4.2 餐饮场景（PB，吸收 v1 餐厅分流）
- 感知：免费餐厅/特色餐厅实时计数（摄像头计数，不识别身份）。
- 决策：规则引擎计算满载率、排队人数、步行时间；AI 生成推荐话术；分批去重避免“所有人被引导到同一处”。
- 行动：App/船载屏推送“船尾餐厅步行 3 分钟，当前有位”；预点餐可选。
- 指标：餐厅满载率峰值、排队时长、错峰用餐比例。

### 4.3 娱乐与公共空间场景
- 感知：剧院入场、泳池甲板、儿童俱乐部、免税店区域密度。
- 决策：开演前推“仍有座/已满”；泳池甲板“当前人少”；预约制 vs 先到先得的建议。
- 行动：App 活动提醒 + 替代活动推荐；船员端超阈值预警。
- 指标：热门活动满场率、投诉量、空间利用率。

### 4.4 港口端接驳场景（PA，v3 新增）
- 感知：到港日下船人流、出租/网约车/官方短驳排队。
- 决策：将乘客按目的地/交通方式分群，分时放行建议；对短途拒载/宰客高发场景给出“建议路线+预估价格+投诉入口”。
- 行动：App 到港前推送“你的离船时间 8:40，B 出口打车预计等 12 分钟，官方短驳 9:00 发车”；港口屏同步。
- 指标：码头端滞留时长、交通类投诉、官方短驳使用率。

### 4.5 航变服务与赔偿智能处理（事件响应模块，吸收 v3N1/PD）
- 触发：航线变更、台风缩短航程、取消停靠、退改申请。
- 决策：规则引擎先给确定性事实（变更内容、原因、法规/条款依据、赔偿标准、替代方案）；LLM 生成分层话术（老年人版/家庭版/投诉版）。
- 行动：App 主动推送 + 船员端统一答复模板 + 赔偿路径（客服/黑猫/司法案例引用）；关键动作进审批队列。
- 指标：航变通知推送耗时、群诉事件数、客服重复答复量。

## 5. 技术架构（升级版）

### 5.1 总体分层

```
感知层：摄像头计数（主） + 可选 LiDAR/3D 计数 + 可选 WiFi/BLE 定位（不依赖）
        ↓
确定性计算层：满载率/排队人数/步行时间/安全约束/合规脱敏/分批去重
        ↓
AI 层（边缘离线小模型）：偏好匹配 + 自然语言生成 + 航变解释话术 + 时序预测
        ↓
决策与行动层：OODA 循环（3 分钟船载局域网内闭环）→ 只读建议自动，写操作/群发进审批队列
        ↓
审计层：证据抽屉 + 动作 trace_id + 可回放时间线
```

### 5.2 关键工程决策（来自流⑦/流⑨）
1. **确定性优先**：计数、排队时间、步行时间、安全约束全部用规则/公式；AI 只做语义与生成。
2. **边缘离线**：本地 Jetson/国产算力模组 + 0.3B–8B 端侧中文小模型；云端模型仅做异步增强，不进入 3 分钟闭环。
3. **定位降级**：WiFi/UWB/BLE 仅作可选增强，核心决策不依赖个人精确位置。
4. **隐私前置**：“仅计数不识别”是法定义务设计（公共安全视频条例 + 人脸识别司法解释），不是口号；计数在边缘完成，原始视频不离开本地。
5. **网络合规**：船载网络方案需标注 IACS UR E26/E27 网络安全要求（流⑥）。
6. **降级链**：真实 AI → 规则推荐 → 模板推送；无网络/无密钥时 Demo 与产品均可用，且 MOCK_MODE 显式可见（流⑨ StoreOps 模式）。
7. **计数精度口径**：写“轻量 YOLO 系/双目客流相机为成熟路径，商用设备常见宣传 95–99%+，需目标场景实测标定”；不得写“YOLO 95%+”无出处断言。

### 5.3 多 Agent 表述纪律（反模式防护）
最多 4 个职责单一的 Agent/模块：感知、评估（规则）、推荐（LLM）、调度（去重/审批）。每个模块必须有独立输入输出与降级逻辑；Demo 与文档中不得出现“5 个 Agent 协同”但实际同一 prompt 的贴纸式表述。

## 6. 合规与安全

1. 摄像头仅计数不识别；视频在边缘即时匿名化；不存储人脸；乘客可选择退出个性化推荐。
2. 引用《公共安全视频图像信息系统管理条例》（国务院令第 799 号）与最高法人脸识别司法解释作为设计依据。
3. 安全约束：消防通道/限制区域不进推荐；疏散与安全返港（SRtP）要求优先于商业推荐；AI 不做安全强制决策。
4. 网络安全：按 IACS UR E26/E27 设计船载系统边界；MASS Code 当前非强制但应作为未来扩展参考。

## 7. Demo 设计（预写场景 + 真实链路）

### 7.1 四个演示 vignette（可任选 2–3 个用于 2 分钟视频）
1. **11:45 午餐高峰**（沿用 v1 剧本并升级）：三餐厅实时计数 → 规则引擎计算 → 离线 LLM 生成推荐 → 推送 → 15 分钟后满载率回落。
2. **登船日 10:00**：码头排队热力 + 分时预约推送 + 港口交通指引。
3. **到港日 08:40**：离船时间窗 + 出租/短驳指引（展示港口端调度）。
4. **航变 18:00**：台风缩短航程 → 主动推送“解释+赔偿方案+替代安排”→ 船员端统一答复模板（展示事件响应模块）。

### 7.2 Demo 纪律（流⑨红线）
- 允许：预录视频、mock 数据、合成数据、预写场景、MOCK_MODE 显式标识、确定性脚本。
- 不允许：核心动作造假（随机数订单/正则冒充 AI/硬编码推理步骤）、MCP/多 Agent 贴纸、PRD-only。
- 每个演示动作都能回答：关掉 AI，规则层还能给出可用的保守建议吗？关掉外部服务，Demo 还跑得起来吗？

## 8. 竞品与差异化（流⑧）

- 感知组件可采购（Outsight 3D LiDAR、V-Count 邮轮计数、March Networks/海康计数相机）→ **感知不是创新点**。
- 国际邮轮 App 有导航/预订/消息，未发现实时拥挤度分流闭环 → **差异化必须建立在“船上场景集成 + 决策闭环 + 航变事件响应”**，不能建立在单项技术上。
- 花城号已前装 AI 无感登船/智能客舱/机器人 → 我们定位为“全船空间优化调度层”，不与终端硬件堆料重叠；与船厂数字化能力（SWS TIME/数字孪生）形成前装协同。

## 9. 风险与对策（更新版）

| 风险 | 概率 | 影响 | 对策 |
|---|---:|---:|---|
| 感知层无壁垒，船东可自建 | 中 | 高 | 差异化押在场景决策闭环、航变模块、离线合规设计；Demo 展示完整逻辑而非单点算法 |
| 离线 LLM 推荐质量不足 | 中 | 中 | 规则模板兜底；推荐话术短文本 + 模板槽位填充；原型实测延迟与质量 |
| 隐私合规争议 | 低 | 高 | 仅计数不识别 + 边缘匿名化 + 退出机制；引用法条论证 |
| 新船无历史数据 | 高 | 中 | 场景规则不依赖历史；用仿真/试航数据逐步学习；诚实标注 |
| 与花城号已有智能系统重叠 | 中 | 中 | 明确边界：本系统是“调度决策层”，复用其感知与终端入口 |
| 评委认为“只是导航/App” | 中 | 高 | 强调“空间×时间双维调度 + 确定性计算 + 事件响应闭环 + 前装设计”；Demo 用证据抽屉展示推理 |
