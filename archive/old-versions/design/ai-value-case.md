# AI 价值论证（AI Value Case）

> 状态：**项目基石文档，证据线 A 草稿回填 + B 已回填（2026-08-17），待收敛 scope**

## 1. 文档目的

回答一个必须经得起追问的问题：

> 在已有监控、调度、信息系统的情况下，我们的 AI 加入到底改变了什么？如果关掉 AI，系统还剩什么？

## 2. 两条证据线

### 证据线 A：旧模式基线（草稿回填 2026-08-17）

> 每场景详版见 `design/evidence-line-a-baseline.md`；证据等级沿用 round2 标准（L0/L1/L2/L3）；**[待验证]** 标记无公开证据的环节。

为每个核心场景建立“没有我们的系统时，真实运营链路”：

| 场景 | 现在怎么做 | 用什么工具 | 信息延迟/人工成本 | 已知痛点证据 |
|---|---|---|---|---|
| 午餐高峰分流 | 船员目测→对讲机确认→广播通知；乘客到现场排队或凭攻略选择 | 肉眼、对讲机、广播；App 无实时拥挤度（⑧ P1，8 源 Strong） | 信息滞后不统一；**[待验证]** 高峰时段餐厅主管巡场推断约 6–12 人·时/天 | PB：餐饮排队 2024–2026 跨期持续，7 源 Strong；付费升舱逃避排队（④ S32，L2） |
| 登离船 | 登船日同一时段抵达排队；离船日分层下船靠广播/纸质通知；港口交通衔接不确定 | 人工窗口/自助机、广播、对讲机 | 靠岸到码头 ~1h + 分层下船再等 ~3h（④ S18）；**[待验证]** 登离船日船员协调人力 | PC：登离船跨年份断点，8 源 Strong；宝山区政府连续两年承认（04b S18/S19，L0） |
| 港口接驳 | 乘客自行判断交通方式；出租车短途拒载/宰客；港口信息屏仅静态指引 | 乘客手机叫车、出租车/短驳排队（无可视化） | 乘客滞留不确定；司机苦等 2h 赚 48 元（④ S19） | N3：码头端接驳断层，3+ 源 Strong；宝山区 2025/2026 连续两年政府答复承认（L0） |
| 航变响应 | 客服/船员逐批解释变更原因和赔偿，口径不一致；乘客信息真空中不信任→群体维权 | 口头/广播/黑猫投诉/对讲 | **[待验证]** 推断 5000 人级逐批沟通需 8 名客服连续 5h+ | PA：航变赔偿争议 8 源 Strong；2026 台风拒下船（④ S02–S06）；N9 群体维权 Strong |
| 娱乐/公共空间 | 剧院/泳池/俱乐部容量固定；App 静态活动列表→预约与先到先得都不满 | App 活动列表（无实时容量）、物理占座 | **[待验证]** 现场管理船员配置 | PO：国际 Strong（7 源）/中国弱（仅 1 源 L2）；N16 两种机制都不满 |

> **注意**：娱乐/公共空间中国侧直接证据仅 1 条 L2，v3 PO 模式为"国际 Strong、中国弱"——是否进 MVP 待用户拍板（见 Q5）。 见 `research/round2/source-archive/05-entertainment-public-space.md` |

要求：**旧模式描述不能只靠“我觉得”，要有具体来源或可验证的运营常识。**

从高分项目中提取“被验证过的 AI 优势”，映射到邮轮调度（分数为 09 挖掘归一化结果）：

| 黑客松项目/模式（分数） | AI 带来的具体优势 | 可迁移到邮轮哪个环节 | 说服力判断 |
|---|---|---|---|
| WCO(79) / Spatial Engine(82) / FireGuard(80) / Scam Swarm(84) / StoreOps(79) —「LLM 做语言，代码做算术」 | 确定性计算保准确，LLM 只做判断与话术："问 LLM 算 DSO 是危险的"；"像设计师一样看，像物理学家一样算" | L2 资源状态层（满载率/排队/等待/步行时间）全确定性；L3 建议层用 LLM | ★★★★★ 6+ 独立高分项目同构，直接回应"AI 挂了怎么办" |

已确认的初步候选（并入上文三点，不再单列）：确定性计算分工 ✓、跨系统实时整合 ✓、异常事件生成方案+审批+触达 ✓、证据可追溯 ✓、分层降级（作为 Demo 工程前提，非卖点）、多 Agent 按需调度（3–4 个职责单一，不贴标签）。

## 3. 收敛后的 AI 价值点（3 个 headline，2026-08-17 定稿）

> 由原 5 条候选经证据线 B 收敛而来；证据锚与失败模式详见 `research/round2/batch3/10-ai-advantages-cruise-mapping.md`。

### V1 确定性保底 + AI 判断（从"会算、会想混在一起"到"各司其职"）

- 人流计数、满载率、排队、步行时间、时间窗全部精确计算；LLM 只承担"非结构化→结构化"的感知判断与"数字→人话"的生成。
- 证据锚：WCO / Spatial Engine / FireGuard / Scam Swarm / StoreOps 六项目同构。
- 邮轮落地：L2 层（确定性）→ L3 层（LLM 建议）。例：摄像头计数 312/380 → 确定性满载率 → LLM 生成"建议去 3 楼，等待约 4 分钟"。
- 说服力 ★★★★★：最强证据模式 + 天然回应"关掉 AI 还剩什么"。
- 失败模式：计数与推荐链路造假 → 落入"核心动作造假"红线（Demo 只允许 mock 数据源）。

### V2 分钟级决策闭环（从"人肉拼图"到"AI 拼图 + 人拍板"）

- 把分散在预订/监控/港口/客服/公告系统的运营情报合并为一个决策视图；异常事件（高峰超阈值、航变）自动生成"事实→影响→方案→话术→审批任务"，人确认后执行。
- 证据锚：Globot（5 分钟 vs 2 小时）、FireGuard（60 秒局势图 + ApprovalGate）、CrowdPilot（4-Agent 流水线映射应急步骤）。
- 邮轮落地：航变响应、午/晚餐高峰超阈值、登离船与港口接驳联动批次。
- 说服力 ★★★★☆：航运同构类比易懂；但必须回答 CrowdPilot 被点名的假设——"运营数据已在系统里"在邮轮上是否成立。
- 失败模式：审批门只是 prompt 口头承诺，而非结构性"执行路径不经 LLM"。

### V3 可审计信任层（从"黑箱建议"到"可回溯、可问责"）

- 每个推荐/动作带证据抽屉（读了哪条数据、算了什么公式、谁批准）；风险/紧急分级用确定性公式可复现；写操作/高后果动作全部审批 + 审计包。
- 证据锚：StoreOps（证据抽屉=护城河）、FireGuard（威胁分可解释可审计）、WCO（全链路 trace）、DQ Sentinel（结构性审批门）。
- 邮轮落地：分流建议旁证据卡片；航变赔偿/资源重排留审计包；船员面板可回看依据与审批人。
- 说服力 ★★★★☆：回应答辩追问"你的 AI 凭什么让我相信"。
- 失败模式：证据链本身造假比没有更糟；MVP 只对写操作/高后果动作做全审计。

### 次级 / 承接 / 不采用

- **次级（不单独立价值点）**：个性化分群分批触达——属 L4 触达层，是 V2 的执行结尾（分批话术由 LLM 生成），Demo 做展示即可。
- **承接前提（非卖点）**：分层降级 + 演示工程化——MOCK_MODE/REAL_MODE 显式分离、预写场景 + 真 LLM 链路 + 规则降级、演示脚本与兜底话术。
- **不采用**：多 Agent 数量炫耀（3–4 个职责单一 Agent 足够）、MCP/摄像头标签（写真实接入状态）、"AI 万能胶水"叙事（每项能力过必要性检验）。

## 4. “关掉 AI 还剩什么”压力测试

| 场景 | 有 AI | 关掉 AI 后 | 是否仍可接受 |
|---|---|---|---|
| 餐饮分流 | 实时感知+预测+个性化推荐 | 固定时段广播、人工引导 | 可用但动态性差，需评估差距 |
| 登离船 | 动态时间窗+跨系统整合 | 固定批次表 | 可用但无法应对异常 |
| 航变 | 自动生成统一话术+资源重排建议 | 客服人工逐批处理 | 慢、口径不一、群诉风险高 |
| 港口接驳 | 实时排队+交通方式分群 | 静态指引 | 可用但无法响应实时变化 |

## 5. 评审/面试压力追问清单

- “以前没有这套系统，船是怎么运营的？”
- “你说的痛点，传统系统不能解决吗？”
- “AI 在这里是不是只是把规则引擎包装了一下？”
- “如果网络断了、模型不可用，系统怎么办？”
- “你的 AI 价值是乘客体验，还是运营效率？谁买单？”
- “为什么邮轮公司不直接买 V-Count/机场排队系统？”
- “你的方案比现有 App 的导航/预订功能强在哪里？”

## 6. 当前结论

- 证据线 A 草稿已回填（5 场景，基于 round2 六流素材 + 船型基线；详版见 `design/evidence-line-a-baseline.md`）；证据线 B 已完成回填；双线齐备后可进入 scope 收敛与 PRD。
- 证据线 A 中 **[待验证]** 标记处为无公开证据环节（如餐饮分流流程、航变 SOP、人工成本量化等），需 web_search 恢复后检索或用户提供资料补强——详见 `research/round2/key-items-public-search.md` 与 `evidence-gap-plan.md`。
- 对 scope 的直接影响：主战场 = L2 确定性层 + L3 建议层；个性化触达不再作为卖点；娱乐/公共空间可凭 V1 证据作为低成本扩展（中国侧证据弱，待 Q5 拍板）。
