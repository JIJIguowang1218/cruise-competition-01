## 第 1 页：业务技术选型——什么问题，用什么技术

**一句话核心**：我们不在系统里堆 AI，而是把每类业务问题匹配到最合适的技术形态——能确定的归代码，需要理解和推理的才给模型。

### 主内容：八类环节 × 技术形态

| 业务环节 | 技术形态 | 这样选的理由 |
|---|---|---|
| 多系统接入与数据标准化 | **工程适配器（纯代码）** | 高并发读取是工程能力，不是模型生成能力 |
| 事件分类、严重度判定 | **小模型（0.5B–4B）＋规则复核** | 类别空间被事件库锁死，模型只做"选择题"，不能自由发挥 |
| 库外异常发现（没见过的事件） | **无监督异常检测＋提醒卡** | 规则只能查已知模式，库外的事物理上看不见；**只提醒、不执行** |
| 时间窗、影响人数、排队、资源缺口 | **确定性算法（纯代码）** | 数字必须可复现、可审计——**AI 不做算术** |
| 条款、策略、历史预案调用 | **RAG 检索＋逐字引用编号** | 从已有库里选和组合，禁止现场编造条款 |
| **方案组合与长链路推演** | **多 Agent 固定链（第 2 页展开）** | 分段推理、结构化交接、每步可回滚可审计 |
| 多语言话术与乘客解释 | **端侧小模型单次生成** | 这是表达层，不是决策层；条款原文不可改动 |
| 审批、触达、审计 | **规则工作流＋人审批** | 模型不持有任何写操作和发送工具 |

### 三条选型规则（页底一行）

1. **能规则就不用机器学习**；
2. **实时闭环只用船载本地模型**（不依赖卫星网络）；
3. **云端大模型永不进入 3 分钟实时闭环**，只做岸基离线的长文档解析。

### 页脚金句

> AI 只站在规则引擎到不了的三块地上：**看见没见过的、推演没写过的、解释说不清的。**

**建议图形**：横向流水线色带（[0.5]–[9] 十一段），五色区分 纯代码／小模型／无监督检测／RAG／多 Agent 链／云端异步；表格放色带下方或作为口述备份。

## 第 2 页：核心——方案推演的多 Agent 架构

**一句话核心**：四个职责单一的智能模块按**固定顺序**协作，像流水线工位而不是一群自由讨论的人；模型只有"读和想"的工具，"写和发"全部在人审批之后。

### 主内容：四个固定工位（全线唯一的多模型协作段）

```
[4] RAG 条款/策略 ┐
[3] 确定性计算结果┼─▶ ① 事件理解 → ② 影响推演 → ③ 资源盘点 → ④ 方案组合 ─▶ 结构化候选方案
事件分类结果     ┘
```

| 工位 | 回答的问题 | 输出（结构化） |
|---|---|---|
| ① 事件理解 | 发生了什么、影响性质是什么 | 事件要素卡 |
| ② 影响推演 | 波及哪些人群、区域、时间窗 | 影响链＋假设清单 |
| ③ 资源盘点 | 有哪些人手、接驳、舱位、通道可用 | 资源缺口表 |
| ④ 方案组合 | 从策略库里组合出哪几个候选方案 | 候选方案＋四维评估（运营/经济/风险/综合） |

### 四条架构纪律（这是本页要让评委记住的）

1. **固定拓扑**：四个工位的顺序由代码焊死，模型不能决定下一步、不能互相自由交接——路径确定才可复算、可审计；
2. **无写工具**：所有模型只能调用只读工具，输出是结构化"提案 JSON"，不接触任何执行接口；
3. **契约交接**：每两个工位之间是预定义的数据契约，每一步独立可校验、可回滚，全程 trace 留痕；
4. **出链三道闸**：
   - [5.5] **推理附件**：每个方案附"依据了什么信号、算了什么、引用了哪些条款"，并过代码确定性校验（防 LLM 解释 LLM）；
   - [6] **证据与置信度门**：证据不足/低置信度 → 转人工优先复核队列，不自动分发；
   - [7] **审批门 L1–L4**：L1 自动派发 / L2 值班确认 / L3 经理法务审批 / L4 船长决策区（仅安全、群体、法定、不可逆四类判据触发）。

### 学习闭环（页底小环）

[9] 审计包 → **事故模式库（人工审校后才入库）** → 回到 [4] 检索：下一次同类事件更快更准。
注意口径：这是"每个航次后的组织学习"，**不是模型在线试错、自我反思重试**——高后果场景没有试错权。

### 答辩储备（不上幻灯片，被问才说）

- **为什么不用自主式 Agent（ReAct 那种自己决定下一步的）？** 步数不可预测 → 3 分钟时延不可控；错误会逐轮复合；路径不固定 → 无法复算和审计。业界实测自主多 Agent 系统 token 成本约 15 倍。我们的子任务事先可枚举，固定链是收益相同、风险最低的选择。
- **这还算多 Agent 吗？** 行业可以宽松地把它归为多 Agent 系统里**最确定的一种：固定拓扑、无自由交接**。

**建议图形**：四个工位横向链，工位下方挂输入/输出契约小标签；链下方三道闸门竖排；底部虚线弧画 [9]→[4] 学习回流。

## 第 3 页：沙箱与安全边界设计

**一句话核心**：因为模型不执行代码、不持有写工具，我们不需要"把自主 AI 关进代码沙箱"那种重方案；沙箱是**四层边界**，目标是让任何单点出错的代价，最多是一次多余的知会，而不是一次错误的执行。

### 主内容：四层沙箱

| 层 | 防什么 | 产品规则（验收口径） |
|---|---|---|
| **① 运行时隔离** | 防失控：死循环、超时、资源耗尽 | 每个智能模块独立运行，配 CPU/内存/**时延/token 硬配额**；超时自动熔断 → 降级为建议并转人工 |
| **② 工具权限隔离**（核心） | 防越权：AI 直接操作系统 | 工具分三级：**只读**（模型可用，只读凭据＋访问限流）／**写提案**（只能输出结构化申请，不接触执行接口）／**高风险**（对模型不可见：赔偿执行、航变决定、全量推送）。写执行器是审批门之后的独立程序节点——**这是拓扑保证，不是靠提示词约束** |
| **③ 数据与网络隔离** | 防泄露、防提示注入 | 实时链路全在**船载局域网**内闭环；云端只接岸基异步任务，乘客明细数据不出船；记忆分三层：事件工作记忆（航次内有效、到期清理）/ 事故模式库（人工审校入库）/ 坏例库（仅评测）；客服原文、港口公告、乘客 UGC 一律**当数据、不当指令** |
| **④ 发布隔离** | 防未经验证的能力上线 | 新模型、新策略先跑**影子模式**（只记录建议、不参与决策）→ 过评测集（含坏例库）→ 单船试点 → 全量；任何一级可回退到上一版本或纯模板 |

### 与降级体系的衔接（页脚一行）

断外部网络 → 断本地 AI → 断电：T1 用缓存条款库、T2 退回人工模板、T3 退回纸质 SOP；**审计在任何一级都不降级**。

### 页脚金句

> 沙箱不是为了让 AI 更聪明，而是把它的"爆炸半径"限制在一张提醒卡之内。

**建议图形**：四同心层（或四列竖层），从内到外 运行时 → 工具 → 数据网络 → 发布；中心放"多 Agent 推演链"；第②层用最深色强调；页脚 T0–T3 降级一条细带。

## 三页共用的口径纪律

- 不出现框架产品名（LangGraph 等仅技术说明书附录使用）；
- 不承诺指标绝对值：时延、准确率一律"演示级量级／目标区间，试点标定"；
- 不出现强化学习相关讨论（仅技术文档保留）；
- 模型候选名（Qwen/Gemma 等）不进展示页面，只说"端侧小模型/本地量化模型"；
- 被深问实现时统一收口："这是工程实现层，我们的验收标准是……"。
