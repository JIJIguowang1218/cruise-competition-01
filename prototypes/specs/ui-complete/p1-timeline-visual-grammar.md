## 0. 坐标系与对齐规则（必须严格一致）

- **横向 = 时间**：左 = 更早，右 = 更晚。右侧一根**实时竖线**贯穿所有车道，代表"当前时刻"。
- **底部时间轴**（位于 L1 车道与 X·库外 车道之间）与实时竖线**构成同一坐标系**：
  - 时间轴左端 = 车道背景左边界（同一 x）；
  - 时间轴右端（刻度"现在"）= 实时竖线所在 x，实时竖线必须**垂直落于刻度"现在"上**，不得错位。
- **车道背景**：每个等级一条浅灰背景矩形；所有车道的左右边界 x 一致（左 = 时间轴左端，右 = 实时竖线）。
- **事件矩形边界约束**：任何事件矩形/线段**必须完全落在所属车道背景之内**（左右不越界、上下不出车道）。
- **等级标签位置**：固定在车道背景**左侧外部**、垂直居中于该车道；任何时候不得随内容移动。

## 1. 车道分配（当前船长视角 v1）

| 车道 | 位置 | 相对高度 | 承载事件数（当前示例） |
|---|---|---|---|
| L4 | 最上 | 最窄 | 1 |
| L3 | 上 | 较窄 | 2 |
| L2 | 中 | 中等 | 5 |
| L1 | 下 | 最宽 | 9–10（细条堆叠） |
| X·库外 | 最下（时间轴之下） | 独立 | 只提醒，虚线框 |

- 高度向下递增以容纳低等级的大量事件；**高等级车道在上且窄**（当前取向，待用户最终确认是否改为按角色自适应）。
- 同级事件矩形条高一致；多事件在车道内**按行错开，禁止重叠**。

## 2. 基础事件图形语法（正常事件）

一个基础正常事件从左到右 = **至少：发现段 + 移交竖线 + 执行段 + 恢复点/开放末端**。

```
  ┌───────发现段───────┬───────执行段───────┐
  │   (识别色)   ❘(移交竖线)  (执行色)    ❘  ※端线
  └──────────────────────────────┘  ●恢复点(绿点,端线中点)
```

- **发现段**：事件矩形开头，识别色。
- **移交竖线**：一道比事件条稍高/稍粗的**竖向线**，正常交接 = 绿色；紧贴发现段右端。
- **执行段**：执行色。
- **恢复点**：执行结束且观测到数据恢复时，在**末尾竖线中点**画一个**绿色圆点**。
- **开放事件**（仍在执行中、未结束）：右边直达实时竖线，**无端线、无恢复点**。
- 事件矩形上**不写字**（"发现/执行/恢复"等字样一律不放）。

## 3. 异常事件图形语法

```
  ┌──发现段──┬──执行段──┬──────────────────────┐
  │识别色  ❘ 执行色  ❘(异常红竖线)  异常段(红)   │
  └──────────┘        └──────────────────────┘
```
- **交接异常竖线**：红色、比正常移交竖线**更长/更醒目**；其后转为**异常段（红色）**。
- 异常事件**只有最终结束**（数据恢复/处置闭环）才在端线中点出现绿点；未结束则红段直达实时竖线。

## 4. 升级事件图形语法（重点，务必按此）

- 下级事件**异常段末端**（"末尾红色竖线"）→ 从这里**向上**连到上一级车道，红色连线为**实线**（非虚线）。
- 上级事件矩形**开头（左边缘）就从红竖线落点处开始**，按"发现段"识别色向右生成；连读即：**红竖线落点 = 上级矩形左起点**。
- 即：`下级红段终点 ──红色实线↑── 上级发现段起点（同 x）`。
- 上级事件随后按基础语法推进（移交竖线/执行段/恢复点）。

## 5. 状态 → 颜色对照（低保真阶段临时取值）

| 状态 | 图形 | 色（hex） |
|---|---|---|
| 发现/识别/待处置 | 发现段 | #f5a623（琥珀） |
| 正常移交 | 移交竖线（稍高/稍粗） | #57be6c（绿） |
| 执行中 | 执行段 | #57be6c（绿） |
| 已恢复 | 端线中点绿点 | #2e8b57（深绿点） |
| 交接异常 | 红色竖线（更高/更醒目） | #e53945（红） |
| 异常持续 | 异常段 | #e53945（红，可半透明） |
| 升级传导 | 红色实线↑接上级开头 | #e53945（红，实线） |
| 库外异常 X | 虚线框（X 车道内） | #4a7fbf（蓝虚线框） |

## 6. 禁止事项（返工红线）

- 事件矩形上不得有文字。
- 同级事件条高/分段比例不得随意不一致。
- 事件不得越出车道背景、不得与实时竖线/时间轴错位。
- 等级标签位置不得随意变动。
- 升级连线必须是实线且接到上级矩形开头（不是接到上级矩形末端/任意处）。

## 8. v2 修订（2026-08-20 用户二轮，取代 §1/§2 中冲突处）

> 用户强调"理解再动手"。以下为本轮强制规则；与上文冲突处**以本节为准**。

### 8.1 统一细高（关键）
- **所有等级的所有事件矩形高度完全一致、一样细**（取 L1 的细度）。不得为了强调高级别而把矩形加高/加粗。没有任何拉伸/加高要求。
- 行与行之间拉开距离，不得挤在一起（靠车道内的虚线导轨定位）。

### 8.2 虚线导轨 / 车道高度按比例
- 每个等级灰色背景内，画**与背景等宽的水平灰色虚线**若干条；事件矩形就落在这些虚线之上。
- 固定条数（本轮）：**L4=2、L3=4、L2=6、L1=10**。
- **每个等级车道的高度由其虚线条数按比例决定**（不能随意定）：条数越多车道越高（L1 最高、L4 最矮）。
- 事件行就座落在某一条虚线上（一行可空置，事件分散不重叠）。

### 8.3 正常结束 = 恢复点，不要黑竖线
- 事件正常结束（数据恢复）只在**末端放一个绿色恢复点**。
- **禁止在事件末尾画黑色/深色短竖线**（去掉端线；恢复点自身即结束标记）。

### 8.4 升级红线必须真正接上
- 上级事件矩形的**左起点**与下级异常红段的**右末端**必须处在**同一条 x（同一垂直线上）**，红色实线从下级矩形末端**无缝**连到上级矩形起点，**不能有缝隙/错位**。

### 8.5 库外（X）事件
- X 事件用**灰色矩形**表示（不是蓝/虚线框）。
- 行为：观察中 → 继续向右延长；**决定升级 → 按升级画法画**；**决定忽略 → 直接停止延长**。
- **X 事件矩形附近不得有任何文字**（车道标签除外）。

### 8.6 时间轴 = 半小时实时时刻标点
- 时间轴标点用**真实时钟时刻**、每半小时一个，自实时竖线（当前时刻，如 06:00）**向左**推移：05:30、05:00、04:30……
- 不是"提前 N 分钟"的负数表述，而是"哪个时刻"。
- 例：实时竖线=06:00，左邻=05:30，再左=05:00，以此类推。

### 8.7 事件分布
- 各事件长度与前后位置尽量分散、留白，不要挤成一团。

## 9. v3 精细修订（2026-08-20 用户三轮，取代冲突处）

1. **虚线垂直居中**：每级车道内的虚线组必须**在该级灰色矩形内上下居中**（顶部与底部留白相等），不得偏上或偏下。
2. **恢复点样式**：正常结束点的绿点改为**深绿色空心圆**，直径 = 事件矩形高度（=9px），圆心白色。
3. **事件长度按升级时限**：非升级事件不得画得过长；应按各等级升级时限约束长度：
   - L1≈耗时→上限约 15′（短）
   - L2≈上限约 30′
   - L3≈上限约 60′
   - L4=立即（短）
   参考升级时限：L1/L2 15′、L2/L3 30′、L3 60′、L4 立即（来自 PRD/升级时限）。
4. **右侧实时竖线**：从 L4 顶部一直延伸到 **X（库外）车道灰色背景底部**。
5. **时间轴右端不要箭头**：去掉 marker 箭头。
6. **等级名放在等高铁框内**：每个等级名称放进**一个与该级灰色背景等高的矩形**，矩形**不是灰色**（用非灰/白底+描边以突出名称）。

### 9.1 恢复点不得遗漏（防再犯）
- **任何呈现"最终末端"（右侧有竖直硬边终点）的事件矩形，末端必须带空心恢复点**（深绿空心圆，直径=矩形高）。
- 进行中的事件**不得**呈现一个"假末端"：要么右端直达实时竖线并明确是"开放"（无点），要么就以带空心点的形式结束。**绝不允许出现"有末端却没有空心点"的中间态**。
- 改图后自检：数一遍每个等级的"最终末端"数量与空心点数量，必须一致。
