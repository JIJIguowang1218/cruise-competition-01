# 完整可交互终端 UI 规格（specify.md — 阶段 A，UI 先行）

> 定位：设计对象 = **完整可交互终端 UI（P1–P6 页面 × 功能 × 状态全集）**，不依附单一场景。
> 场景（台风应急/日常处置等）仅作**展示切片**，由后续 `demo-storyboard.md` 承载，不阻塞、不前置（修正见 `docs/development-standards.md` §6）。
> 本文件 = 功能/交互规格（IA + 状态 + 数据 + 交互）；**视觉方向（配色/字体/布局/签名元素）在阶段 B `design.md` 按 `frontend-design` 技能另出**。
> 依据：`demo-terminal-and-interactions.md`（§1 终端盘点 / §1.5 单中枢三形态 / §1.6 核心在船 / §5 页面清单 / §5.1 页面×硬件×屏幕）、`event-governance-framework.md`（L1–L4 / §4.11 / §4.12 / §4.13）、`interface-map-and-ai-components.md`（流水线 [1]–[9]）。

## 0. 全局约定（所有页面共用 — 先审这个，共性问题都在这里）

### 0.1 终端与导航模型（共性与联动的骨架）
```
┌─ P1 事件协同工作台（PC/大屏 1920×1080 主界面）─────────────────┐
│  顶栏：船名·航次 / 态势KPI / 角色切换 / 本地时间 / 韧性T档       │
│  左：局势图    中：事件轨迹（默认按时间轴，即 P2 嵌入）  右：建议卡+审批队列 │
│  ├─ 点事件 → P3 事件详情/建议卡（主区切换 or 弹层）          │
│  ├─ 点异常 → P4 异常提醒卡（弹层/横幅提权）                 │
│  ├─ 点审批 → P5 审批操作（右侧面板 or 独立平板视图）          │
│  └─ Tab：态势总览 | 事件轨迹时间轴(P2 全屏) | 审计(可选 P8)    │
└──────────────────────────────────────────────────────────┘
   P6 乘客 App（独立手机应用 375×812，另一终端，走触达接口/公网）
```
- **P1 = 壳**；P2 作为 P1 的"事件轨迹"主区或全屏 Tab；P3/P4/P5 从 P1 进入（详情/弹层/审批面板）；P6 是独立手机终端。
- **单一窗口应用**：不做多页面路由割裂，工作台内用"视图 + 面板/弹层"组织；符合"瘦客户端、一套中枢"。

### 0.2 角色与可见性（RBAC，全局）
- 角色：**值班/客服 → 运营经理 → 法务 → 船长**。同一界面随角色切换重渲染（Demo 用"角色切换器"演示；真实产品=登录定向）。
- 每个可交互元素只有三种态：**可操作 / 只读（锁定图标）/ 不可见（不渲染）**——前端只渲染服务端允许的（权限在服务端裁剪，前端不做安全边界）。
- 可见域（沿用 `framework` §4.11/§4.12 与 PRD §7）：值班=L1/L2 全操作+ L3/L4 只读；经理=L2/L3 操作+ L4 只读；法务=涉法/赔偿操作、其余只读；船长=L4 全量+全事件只读监控。

### 0.3 数据标注（全局）
- 每个字段三态徽标：**真（实）/ 模拟 / 不可得**（R6）。
  - 表示：字段旁小色点/角标（绿=真实、蓝=模拟、灰=不可得标注"以 XX 为准"），图例常驻顶栏。
- Mock 口径统一注明"演示数据，非实时"；唯独登录不了的外部数据（监管进度等）显示"不可得 · 以官方为准"。

### 0.4 状态体系（全局）
- 控件级状态：**空 / 加载 / 成功 / 失败 / 禁用 / 超时**，全部有明确视觉与文案（错误不道歉、写明原因与下一步——frontend-design 技能约定）。
- 场景级状态：**正常（日常忙碌）/ 待确认 / 审批超时 / L4 告警 / 系统降级（T1/T2/T3 横幅 + 受影响能力清单）**。
- 时间基准：船时；升级时限用**倒计时条**可视化（L1/L2 15′、L2/L3 30′、L3 60′、L4 立即）。

### 0.5 反馈闭环与术语一致（全局）
- 每次操作立即反馈：按钮态变化 + toast（"已确认"→随后出现"已执行→已播报"等）。
- 术语全程一致：**确认 / 签署 / 拒绝 / 下达 / 转人工接管 / 已恢复**；同一动作按钮与回执同一动词。
- 操作后可沿 trace 回看（小"链"图标 → 打开审计预览，对应 P8 可选）。

## P1 事件协同工作台（主屏，1920×1080 或 4K）

**功能清单**：态势总览 / 事件轨迹（时间轴主区）/ 事件队列（列表 + 筛选）/ 建议卡列表 / 审批队列与超时提醒 / 转人工接管入口 / 角色切换 / 韧性T档与降级横幅。

**数据字段**：
- 船期航次、泊位、天气/台风路径（真·可模拟）、登离船/接驳计数（模拟）；
- 事件字段：事件ID、等级(L1–L4)、分类(7类+X)、状态、已耗时/倒计时、处置角色、可操作性(角色打标)。

**状态枚举**：
| 状态 | 表现 |
|---|---|
| 正常（忙碌） | 时间轴滚动、队列按等级色条 |
| 待确认 | 事件条"待确认"徽标 + 倒计时 |
| 审批超时 | 超时升级横幅 + 目标角色高亮（提示接管/升迁） |
| L4 告警 | 全屏告警横幅（顶栏红闪+发船位）→ 必须人处理的醒目态 |
| 系统降级 T1/T2/T3 | 顶栏韧性档徽标 + 受影响能力清单 + 相关按钮禁用/降级文案 |

**交互**：筛选/排序（等级/类型/时间）；点事件→P3；点异常→P4；点审批→P5；"转人工接管"一键（L4 预置入口）；角色切换→全界面重渲染可见性。

## P2 事件轨迹时间轴（P1 嵌入主区 or 全屏 Tab）

**功能**：滚动时间轴（按船时）；每个事件一条**状态条：发生→建议→确认→执行→恢复**；日常与应急混合；可筛等级/类型/角色视角；异常事件高亮。

**数据字段**：事件ID、各阶段时间戳、处置人、当前状态、恢复时间（含"上一快照+标注"的降级判断）。

**状态枚举**：无事件空态（"本时段无事件，系统持续监控中"——空态=邀请式）；加载（滚动）；某事件异常高亮；已恢复（绿色闭环）。

**交互**：点事件→P3；时间缩放（日/航次段）；追改筛选。

---

## P3 事件详情 / 建议卡（主区切换页 or 弹层）

**功能**：
1. 事件头部：ID / 等级 / 分类 / 时间 / 状态 / 处置角色；
2. **信号依据清单**（读了哪些信号，可溯源）；
3. **置信度三档**（≥0.85 自动 / 0.60–0.84 人工确认 / <0.60 仅提示+强制人工标记）；
4. **条款引用**（条款库编号 + 原文，逐字，R8）；
5. **方案组合**（A 系列动作）＋ **备选对比"为什么不用 B"**；
6. **推理附件展开**（可打印，可回看）；
7. 处置轨迹时间线。

**数据字段**：信号源与时间、置信度值、条款条目、动作组合(决策端/执行端/告知端口/升级规则)、附件文本、处置轨迹。

**状态枚举**：待确认 / 待审批 / 已处理 / 已恢复 / 转人工接管（"human_takeover"标记）；低信度（强制人工徽标）；证据不足（"待人工确认"）。

**交互**：确认 / 拒绝（可写原因）/ 转人工接管（一键+最小登记）；展开推理附件；打印；查看备选。

## P4 异常提醒卡（X 系列，弹层 + 可提权横幅）

**功能**：
1. 标注**"不在事件库内"**（开放域、诚实标注）；
2. 风险等级（L1–L4 路由标记）＋ 抄送层级显示（A19）；
3. 可能走向 + 建议观察项（**"推测/建议观察"语气，非断言**，§3.8.1 兜底）；
4. 衔接引导：若演化成某库内事件将对应哪个（E 系列）；
5. **只提醒、不执行**（无执行按钮，仅处置动作）。

**数据字段**：异常信号集合与时间、风险评级、依据、建议观察项、抄送名单、处置结果（忽略/存档/升级为正式事件→回写分类库）。

**状态枚举**：待查看（横幅醒目）/ 已查看 / 已升级为正式事件 / 已存档忽略。

**交互**：忽略 / 存档观察 / 升级为正式事件（→转 P3 标准管线）/ 触发预案。

---

## P5 审批操作（右侧面板 or 独立平板视图，触屏友好）

**功能**：
1. 审批对象：事件 + 建议卡 + 推理附件摘要（结论+证据+信度+替代——决策卡）；
2. 按角色：值班**确认** / 经理**审批** / 法务**电子签署（L3 签单，含条款编号/事件/审批人/时间，可导出 PDF）** / 船长 **L4 触发**（紧急补签，事后可回溯）；
3. **超时倒计时 + 自动升级提示**（R10 / §4.9 时限）；
4. **转人工接管**：一键 + 最小登记（一句话或处置单号，不要求结构化录入，§4.12）；
5. 审批历史（trace 链）。

**数据字段**：审批人/角色、签署类型、时限与升级路径、拒绝原因、接管登记文本、审批时间线。

**状态枚举**：待确认 / 已拒绝（有原因）/ 已签署 / 超时升级中（原链冻结提示）/ 已转人工接管（观察+记录+建议 + 循环提醒红点）。

**交互**：确认 / 拒绝+原因 / 电子签署（签名触控/确认）/ 转接管；超时升级通知点击直达更高层。

## P6 乘客 App 效果屏（独立手机应用 375×812）

**功能**：
1. 通知列表：分批提醒 / 排队提示 / 统一口径消息（A05）；
2. 消息详情：**多语言切换** + **人群适配视图**（老人大字版 / 轮椅无障碍版 / 家庭版）；
3. 自查入口：我的时间窗 / 我的批次 / 接驳建议 / 价格区间提示 / 投诉入口（信息透明缓解，§2.3）。

**数据字段**：消息内容（多语言）、消息类型、时间窗/批次、来源 trace（可回看"由谁批准推送"）。

**状态枚举**：无消息空态（"当前没有需要您处理的通知"）；新消息角标；已读/未读；渠道送达回执（如可回执）。

**交互**：切换语言；查看我的时间窗；点消息看统一口径（含条款引用编号）；反馈入口。

## 跨页联动逻辑（审"联系性"重点）

| 触发 | 联动效果 |
|---|---|
| 新事件（L1 自动/L2+） | P1 队列新增 + P2 时间轴插入"发生" +（按等级）P1 KPI 变化 |
| 分类低信度/库外 | P3/P4 强制人工标记 + 审批按钮必须人工（不可自动） |
| 决策确认/签署 | P1 状态更新 + P2 时间轴插入"确认/执行" + P6 触达消息出现（若含触达）+ P5 审批流推进 |
| 触达下达 | 广播/船载屏（P7 可选）状态流 待确认→已下达→已播报 + P6 通知 |
| 系统降级 T1/T2 | 全局横幅 + 相关按钮禁用/变"建议+人工确认" + 时间轴标注"上一快照" |
| 恢复/事件关闭 | P2 时间轴"恢复"闭环 + 事故模式记忆回写标识 + 事件从队列移除至历史 |

## 待你审的"共性/联动"决策点（我初列，供你审时先看）

1. **导航模型**：P2 是否就作为 P1 主区（时间轴常驻），而非独立 Tab？P3/P4/P5 用"主区切换 vs 弹层 vs 右侧面板"哪种？（偏主区切换/弹层，保持大屏态势不丢）
2. **角色切换**：Demo 用"顶栏角色切换器"模拟登录定向——是否接受？（真实产品=登录定向，不做登录页）
3. **P5 审批的形态**：右侧面板（大氛围感）还是独立平板视图（触屏感）？——建议两者都要（同一组件两形态），或先定一个。
4. **联动深度**：决策→P6 触达消息出现是否要做"实时出现"动画（联动展示效果）？——建议做，这是评委看"闭环"的点。
5. **空态/降级**是否每页都要（标准要求，建议全做）。
