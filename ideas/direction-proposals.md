# 方向锁定建议 — Step 2 输出

> 基于35条痛点 + 30+Hackathon项目的匹配分析，筛选出2-3个方向。
> 筛选标准：痛点实证度 × AI可行性 × Demo可信度 × 叙事张力

---

## 方向一：邮轮实时人流感知与智能分流 ⭐ 首选

### 一句话
用摄像头+AI实时感知邮轮上的人群密度，动态引导乘客去空闲区域，消除排队痛点。

### 解决的痛点（实证）
- #11 餐厅拥挤、服务下降 [钛1][钛2]
- #7 上下船长时间排队 [钛2]
- #17 剧院抢座（推断）
- #10 WiFi信号差 → 可以联动引导乘客去信号好的区域 [钛2]

### 参考的 Hackathon 方案
- **Scam Swarm** (A/84)：启发式引擎+LLM语义分析的双层架构。规则引擎做阈值判断（餐厅>80%满载→触发分流），LLM生成自然语言建议推送。
- **Globot Shield** (A/81)：多Agent监测管线 + 场景化Demo设计。"4:55PM危机"模式→"11:45AM午餐高峰"模式。

### 技术路径
```
摄像头画面 → 人群密度检测（规则引擎：阈值触发）
         → 空闲区域识别（AI：图像识别空桌/空位）
         → 个性化推送（AI：根据乘客位置+偏好生成建议）
         → App/船载屏幕显示实时热力图+导航
```

### 为什么评委买账
- **痛点真实**：钛媒体两次报道都提到排队/拥挤
- **Demo可信**：不需要真实邮轮数据。用一段邮轮餐厅高峰期视频 + 预写分流场景，和 Globot Shield 的"高保真Mock"同策略
- **叙事有力**：展示AI从"被动响应"到"主动引导"的转变
- **符合比赛方向**：空间与体验智能设计

### 风险
- 摄像头部署依赖船上前装设计（新船优势：可以在设计阶段规划摄像头位置）
- 乘客隐私顾虑（需强调"仅计数不识别"）
- 如果只是"人多→告诉你去人少的地方"，产品太薄。需要加上时序预测（"15分钟后这个餐厅会空出来"）才有厚度

## 方向二：邮轮设备智能运维与能耗优化 🥈 备选

### 一句话
用多Agent系统监测邮轮5.5万个设备的运行状态，预测故障、优化能耗、自动派单。

### 解决的痛点
- #44 能耗管理粗放（推断但逻辑坚实：62.4MW总功率）
- #34 设备预防性维护缺失（推断：5.5万设备"坏了才修"）
- #6 客舱温度不均衡（推断：100台空调覆盖2826舱室）
- #35 库存预测不准（推断）

### 参考的 Hackathon 方案
- **Spatial Engine** (B+/61)：AI感知+物理计算分离。AI看数据→物理公式算能耗。"像设计师一样看，像物理学家一样算"。
- **Globot Shield** (A/81)：多Agent协作+预写场景Demo。制冷故障→15分钟完成故障定位→影响评估→替代方案。
- **Synt** (A/87)：OODA循环架构。观察→判断→决策→行动的自主管线。

### 技术路径
```
设备传感器数据 → 异常检测Agent（规则引擎：阈值+趋势）
              → 故障预测Agent（AI：根据衰减模式预测故障时间）
              → 影响评估Agent（AI：故障影响哪些区域/服务）
              → 维修调度Agent（自动生成工单+备件清单）
              → 能耗优化Agent（物理公式：空调/照明/动力负载平衡）
```

### 为什么评委买账
- **规模震撼**：5.5万个设备、62.4MW功率——这个数字本身就很有说服力
- **技术深度足**：AI感知+物理计算分离是评委认可的模式
- **符合比赛方向**：智能运营与决策优化

### 风险
- **数据可得性**：新船没有历史设备数据，传感器点位需要在设计阶段确定
- **Demo难度高**：不像人流方案有摄像头画面直观，设备运维的Demo需要设计巧妙的可视化
- **容易变"Dashboard"**：如果做成一堆图表，就落入CityGuard的反模式

## 方向三：邮轮无障碍AI助手 🥉 差异化

### 一句话
为邮轮上的老年群体和行动不便者（占总乘客比例越来越高）提供多模态AI辅助——从语音导航到手语翻译。

### 解决的痛点
- #25 无障碍需求45% [钛2实证]
- #20 多语言沟通障碍（推断）
- #5 客群老龄化"爷孙游" [钛2实证]

### 参考的 Hackathon 方案
- **Voiceless Voice Agents** (A/75)：唇语识别+多模态交互。"管道+人类校验"处理不完美AI的模式。
- **AMRShield** (A/80)：双层安全架构。"AI推荐+人类审批"在医疗场景的应用→映射到邮轮无障碍场景。

### 技术路径
```
乘客需求输入（语音/文字/手语/唇语）→ 多模态识别
                                   → AI理解意图
                                   → 个性化响应（导航/翻译/服务请求）
                                   → 船员确认关键操作
```

### 为什么评委买账
- **情感共鸣**："帮坐轮椅的老人独立找到餐厅"比"降低能耗3%"更有故事性
- **差异化强**：少有方案聚焦老年/残障群体
- **数据支撑**：钛2报道显示无障碍岸上游预订达45%

### 风险
- **技术门槛高**：多模态识别（特别是手语/唇语）远超 Hackathon 可实现范围
- **可能变"概念车"**：Demo可能需要大量mock，有CityGuard风险
- **受众窄**：可能被认为"不是一个主流问题"

## 推荐

| 优先级 | 方向 | 理由 |
|:--:|------|------|
| 🥇 | **方向一：人流感知与智能分流** | 痛点实证最强、参考方案最丰富、Demo最直观、叙事张力最大 |
| 🥈 | 方向二：设备智能运维 | 技术深度高、规模数据震撼、但Demo难度大 |
| 🥉 | 方向三：无障碍AI助手 | 差异化强、情感共鸣高、但技术门槛也最高 |

**建议**：主攻方向一，方向二作为"技术厚度补充"（在方案书中展示系统设计能力），方向三暂存待后续评估。
