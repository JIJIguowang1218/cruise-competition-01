## 1. IV 系统组织 = 1 页：夹在既有系统之间的一层决策中枢

**放弃列举式结构**（不再分组成/端口/工种三页），全页只让面试官记住一句话：

> **ClarSyn 不替换船上任何系统、不给船员新增终端——它是一层单中枢，通过端口适配器接入既有数据源和既有通信执行栈；岸基协同，船基闭环。**

依据：demo-terminal-and-interactions.md §1.5"单中枢 · 多终端 · 瘦客户端"；接住 III-5a 已定稿的"船员零新增终端 / 不装新 App，不增新界面"。

### 版式（A3 一页，五区）

1. **主图（约 60%，rel-hub-spoke 结构）**
   - 中央：ClarSyn 决策中枢**一个块**；内部六引擎只做小字标注（事件模型 / 确定性内核 / AI 推理 / 审批权限 / 审计记忆 / 输出编排），不展开——展开是 V 幕的事；
   - 左进线 = 输入适配器两组：
     - 船方内部（舱房/船期/排班/POS），用 ✅⚠️🚫 三态色点标数据可得性；
     - 外部源（气象/港口公告/条款库；海关边检"给什么用什么，否则不假设"）；
   - 右出线 = 三类输出端口：
     - **决策端**：事件协同工作台（唯一新 UI，船载局域网瘦客户端 PC/值班平板）；
     - **执行端**：UHF TETRA/DMR 对讲、PBX/IP-DECT 话机、PA/PAGA、公共屏、PDA/PMS 一排既有系统图标，标注 Channel Adapter（端口适配器）；
     - **告知端**：乘客 App / 船载屏（乘客触达渠道，不是船员执行系统）；
   - 岸基/船基一条横向分界带；卫星链路标注"仅异步同步/远程支持，不进实时闭环"。
2. **底部灰红区：不碰清单（红线视觉）**——驾驶台导航设备（radar/ECDIS/GMDSS）、港口海关执法系统、对船员个体的直接指令（AI 手边界止于任务包）。与 III 幕的"AI 手边界"形成产品层呼应。
3. **底条：机制 → 工种 6 个 chip**（确定性计算员 / 情报员 / 参谋 / 审批门 / 哨兵 / 稽核账房），每 chip 半句分工，不画矩阵——详细映射留给 V-2 收。
4. **角注徽章：T0–T3 韧性一行**（断外部 → 断本地 AI → 断电；T3 人工预案；审计不可降级），占角不占主图。
5. **页脚金句**："不替换、不新增、不越级——只在既有系统之间加一层可审计的决策中枢。"

### 信息纪律

- 全页无表格、无枚举段落；面试官从图本身读出"输入—中枢—既有输出"的结构；

## 2. V 技术实现 = Agent 架构多页展开（4 页 + 1 可选页）

### V-1 工程全景与技术选型（1 页）

- **主图**：[0.5]→[9] 工程流水线全景（含 [2.5] 库外支路、[5.5] 推理附件旁路、[7] 审批门、[9]→[4] 事故记忆回流），用色带标每段技术形态：确定性代码 / RAG 检索 / 本地小模型 / 本地中模型 / 云端（仅异步离线）；
- **口径（v1.1 补）**：节点形态、色带取值见 `core-multi-agent-architecture.md` §2 / §9.3；图上出现的库名、端口名与数字量词（7 大类 / 30 类事件库 / 62 条实例 / A01–A19 / 13 端口）见 `library-naming-registry.md`；
- **三条选型规则压成一行**：能规则不 ML；实时闭环只用本地；云端永不进 3 分钟实时闭环；
- **范式判断小卡（§3.9）**：有监督分类（事件分类，少样本/零样本+规则复核）+ 无监督异常检测（X 系列库外）+ 现成生成模型（不自训）；**强化学习显式不适用**（审批门禁止自动试错、低频高后果无样本）——评委追问加分点，值得占一格；
- **红线卡**：参谋不决定 / 经济值不承诺货币化 / 船长否决不被流程绕过；
- **多模态边界一句**：摄像头只输出计数不识别，多模态是"接口属性"不是"模型需求"（可视版面放此处或 V-4）。

### V-2 Agent 编排与控制（1 页，本幕主章）

> **事实源（v1.1 补）**：本页所有图形取值（节点编号、四种形态、三道门位置、回流环、色带）一律以 `portfolio/planning/core-multi-agent-architecture.md`（v1.1）为准。

- 架构模式名：**受控流水线（Governed Pipeline）**——编排器是代码不是模型，模型只在"选择和填空"处出现；
- 补画 **[O] 确定性编排器**（贯穿全线的托底细横条，**不与 [1]–[9] 并列**）——原流水线文档缺"谁在调度"，这一笔正是"多 Agent"与"普通流程"的分界；
- 把 IV 底条六个"工种"落成运行时模块：职责单一、结构化输入输出（JSON Schema/模板槽位）、每步独立可回滚可审计；
- 重点画方案推演段 3–4 个 agent 串联：事件 → 影响 → 资源 → 方案，每段的输入/输出契约；
- **话术生成 [5d] 画在审批门之后**（v1.1 修正：原文"方案（→ 话术）"的括注会让读者以为话术与方案同段；core §3.3 口径是对外口径必须先批准、后生成）；
- **三个控制门**（按流水线顺序，不是按编号顺序）：
  1. [5.5] 推理附件的确定性校验（引用编号真实存在、置信度有效、公式可复算——防"LLM 解释 LLM"；**不阻断**，画成挂角的小盾牌/校验戳）；
  2. [6] 证据与置信度门（低信度转人工，不自动分发）；
  3. [7] 审批门（**模型没有执行工具**，写操作/全量推送/赔偿执行必经人审；此处画**断线 ⊥**，箭头上标"人类签署"——这一笔让"模型没有执行工具"从一句话变成可见结构）；
- **回流环**：审计包 → 事故模式记忆库 → [4] 知识检索，下一次同类事件更快更准；另有**坏例回流**（[9] → 评测集 → 回归）与**升级回流**（[C5] → [1]，红线），版面紧张时按 core §5 的优先级裁剪。

### V-3 高风险点深描：库外发现 × 幻觉兜底（1 页，强烈建议保留）

- **左半：X 系列库外发现**——为什么规则引擎物理上做不到（无监督异常检测：定义常态、偏离即可疑，无需预定义标签）；产品化护栏：提醒卡一律"推测/建议观察"语气、显式标注"不在事件库内"、置信度门槛从严、只提醒不执行、最终处置永远是人；人处置后回写事件分类库；
- **右半：幻觉三层流程兜底（不承诺模型不错）**：
  1. RAG 给事实锚（条款/事实逐字引用 + 原文编号，表达层可翻译适配但不得改原文）；
  2. 结构化约束缩输出空间（JSON Schema / 模板槽位 = 在选择和填空中工作）；
  3. 置信度 + 人工兜底收尾（低信度转人工 ≠ 无人盯，进优先复核队列，超时仍升级）；
- **金句卡**："不承诺模型不会错，而是把 AI 的错误成本从一次错误的执行，降级为一次多余的知会、一次更早的人工介入。"
- **底部一行与韧性对齐**：T1 用缓存条款库（事实锚仍在）、T2 退回模板（无幻觉面）——三层兜底是"AI 在线时的护栏"，不是离线依赖。

### V-4 硬件与部署约束（1 页）

- **船载边缘拓扑**：边缘节点/船载数据中心；感知→分类→计算→方案→审批→触达全在船载局域网内完成，不依赖卫星；靠港可陆地网络增强，海上卫星仅异步同步；
- **模型尺寸分配**：0.5B–8B 跑分类/意图/话术/embedding（0.1–0.5s 级）；7B–14B 量化跑方案组合/长链路推演（1–3s 级）；云端大模型只做长文档/法规异步解析；论证 4K–8K 上下文足够（实时链路各环节 prompt 均为短输入）；
- **T0–T3 故障域 + RTO**：T1 外部断（熔断+缓存回退，RTO ≤ 15min）/ T2 本地 AI 断（模板回退+自动动作降为建议+人工确认，RTO ≤ 10min）/ T3 断电断网（人工预案：广播/对讲/纸质 SOP，不承诺数字 RTO，恢复后补录审计——审计不可降级）；
- 选型量级表（规则/小模型/中模型/云端 × 延迟/离线/幻觉风险）可做小卡，数字标"演示级量级，正式值需试点标定"。

### V-5（可选）实时闭环时序预算页

- 把"3 分钟闭环"拆成各环节延迟预算（毫秒级确定性计算 + 秒级模型调用 + 人审窗口并行）；

## 3. VI 证明与落地 = 1 页：一条从样例到船队的可验证路径

原四页（评测/原型/落地/差异化）合成一页，核心信息：

> **没有真实落地，不假装落地——用"证据基线 + 目标区间 + 显式假设"诚实量化，用五级验证阶梯收口到单船单港试点。**

### 版式（A3 一页，四区）

1. **主视觉：五级验证阶梯（process-chevron 横向，约 55%）**，每级"制品 + 证明什么"：

| 级 | 制品（已有的是实物，计划的明说） | 证明什么 |
|---|---|---|
| ① 离线样例 | EVENT-ROSTER 事件集（v0.6 语义；E09→E-L4→E11 主剧情，62 条） | 机制覆盖不同规模事件，非为台风特设（管道不变性） |
| ② 仿真 | sim-core.js 假实时引擎（挂起/超时/升级可跑） | 状态机与时限逻辑可执行，不是 PPT 机制 |
| ③ 高保真原型 | P1–P6 页面 + 90s 假实时演示 | 信息分层与认知负荷主张可被亲身体验 |
| ④ 单船单港试点（计划） | 接口三态实地校准、指标实测标定 | 目标区间换成真实值 |
| ⑤ 全船队铺开（计划） | 事件库扩充 → 多港扩展 → 岸基协同 → 全船队 | 落地路径（v4 五步压成阶梯最后两级） |

2. **右上：诚实量化卡**——2–3 个指标只写**目标区间 + 显式假设**（如：分钟级响应的前提是接口按三态接入；分类准确率给区间不给承诺）。口径沿用 presentation-strategy §4："不是我们已做到 3 分钟，而是设计目标分钟级，真实值需单港试点标定"；
3. **右下：前三风险 chip + 一句应对**——数据可得性（三态标注、不给什么不假设）/ 船员采纳（零新增终端、走进既有通信栈）/ 高后果无法真实验证（坏例双轨 + 事后审计层）；
4. **页脚一行差异化收束**（不画对比表，三句话）：
   - vs 规则升级——我们看得见库外（开放域异常发现）；
   - vs 聊天式 AI——我们有审批门、模型没有执行工具；
   - vs Globot 类工业系统——我们的信任层完整（血缘 + 推理附件 + 签署 + 审计包）。
   - 全册收尾金句：**"我们不是用 AI 给规则引擎化妆，而是把系统立在规则引擎到不了的三块地上：看见没见过的、推演没写过的、解释说不清的。"**
