## 第 2 页：宏观设计背景

### 页面目标

用简洁的宏观叙述解释：为什么邮轮行业、为什么是船岸交界、为什么是现在。

### 核心信息

中国邮轮市场正在复航与新船交付期，船↔岸交界是体验断裂最明显、利益链最长、决策最依赖人工跨系统核对的环节。

### 正文内容

1. 行业背景：
   - 中国邮轮市场复航，新船陆续交付，乘客规模大；
   - 船岸交界是登离船、接驳、航变等多类问题集中爆发的地方；
   - 邮轮公司、港口、OTA、旅行社、本地交通、政府监管共同构成复杂利益链。

2. 利益链相关方：
   - 邮轮公司：承担品牌、客诉、合规与赔偿风险
   - 乘客：关注等待时间、信息透明、行程确定性
   - 港口：负责通关、接驳、交通秩序
   - OTA / 旅行社：承担销售与退改沟通
   - 本地交通：出租车、网约车、短驳供给
   - 政府 / 监管：关注公共秩序、乘客权益、交通治理

3. 为什么是现在：
   - 2026 年航变与港口接驳是官方与媒体双确认的持续痛点；
   - 本地小模型、气象 API、RAG 等技术条件成熟；
   - 新船前装设计窗口允许我们把 AI 决策层作为系统能力设计进去。

4. 宏观判断：
   - 邮轮公司不缺单一信息系统，缺的是把多源信息变成决策依据的协同层。

### 呈现方式

- 上半页：一段宏观叙述文字 + 3 个关键行业标签
- 下半页：一张利益链示意图（邮轮公司 / 乘客 / 港口 / OTA / 交通 / 政府）
- 呈现：文为主，图为辅，信息量克制

#### 由公开证据推导的基线估算 —— 运营推演（待船司数据校准）

## 第 5 页：痛点分析与需求

### 页面目标

把第 4 页调研事实进行综合，形成有判断力的痛点总结，并说明这些总结背后的需求与优先级。

> 本页只描述业务问题与需求，不预设技术方案；技术路线是否适合、用在哪里，留到后续机会判断页再论证。

### 核心信息

调研事实综合后可以看到：船岸交界的问题不是几个并列痛点，而是由外向内嵌套的三层结构——最外层是乘客体验问题，中层是流程协同问题，最内层是决策治理问题。

### 正文内容

1. 痛点总结（综合判断）：

体验层：

- 离船流程的时间承诺与实际执行严重脱节，乘客在不确定中长时间等待。
- 登离船批次与现场状态缺乏联动，导致排队和聚集难以被提前化解。
- 港口接驳信息以静态文档为主，乘客无法在决策前获得可比较、可依据的交通方案。

流程协同层：

- 航变等事件发生后，运营人员需要跨系统收集与核对信息，决策准备时间长，且高度依赖个人经验。
- 面向大规模乘客的沟通依赖逐批人工解释，工作量大且口径难以保持一致。
- 各渠道信息不同步，导致乘客端接收到的通知滞后于船司内部决策。

决策治理层：

- 航变与赔偿类问题缺少透明、可追溯的依据，容易从个体不满升级为群体事件。
- 事件处理过程留痕不足，事后难以完整回答“为什么这样做、谁批准的”。
- 多个不明显的迹象同时出现时，现有流程难以提前判断风险正在积累。
- 面对新出现的异常情况，缺少清晰的处理路径与责任归属。
- 局部事件发生后，对后续环节的连锁影响难以快速推演，容易遗漏关联影响。
- 决策者很难快速理解“为什么选择这个方案、依据是什么、还有哪些选择”。

2. 痛点类别图（建议视觉）：

图名：**痛点不是并列的三类，而是由外向内嵌套的三层**

- 外层 · 体验层：乘客感受得到的等待、排队、信息不确定
- 中层 · 流程协同层：跨系统核对、逐批沟通、渠道同步、口径一致
- 内层 · 决策治理层：风险迹象积累、新情况识别、连锁影响推演、决策理由解释、透明留痕

相关说法：

> 三层不是并列关系：体验问题是表象，流程协同问题是中层机制，决策治理问题藏在运营最深处，并影响前两层是否能够顺畅运转。

3. 需求定义（暂不预设技术）：

- R1 事件信息组织与呈现：把分散在不同系统中的信息，整理成决策者可理解的事件状态。
- R2 风险迹象积累提示：当多个迹象同时出现时，提醒相关人员关注潜在升级风险。
- R3 连锁影响推演与候选方案：快速推演事件对后续环节的影响，并提供可选择的处理方案。
- R4 决策理由可见：让决策者看到依据、可选方案和选择理由。
- R5 人工审批、接管与留痕：高后果动作保留人工控制，全过程可追溯。
- R6 可复算的执行计算：时间窗、批次、触达等保持可计算、可复核。

4. 需求优先级是怎么来的：

- 不采用“痛点一一映射成功能”的方式，而是综合三条判断：
  1. 严重度：调研中反复出现的高后果问题；
  2. 可介入性：在船司权责边界内，系统能够实际干预；
  3. 现有手段覆盖不足：当前流程/规则/信息方式难以稳定解决。
- 优先级结果：
  - P0：风险迹象积累提示、连锁影响推演与候选方案——高后果、现有流程最难覆盖；
  - P1：事件信息组织与呈现、决策理由可见——直接影响决策质量和信任；
  - P2：人工审批、接管与留痕、可复算执行——治理与执行保障。

5. 产品定义视角补充：

- 本页只给出问题与需求，不说明技术路线；
- 技术路线是否适合、用在哪、为什么必须采用，属于后面的机会判断；
- 没有经过论证前，不应直接说“这个需求需要某种特定技术解决”。

## 第 6 页：业务理解

### 页面目标

在正式讲“我们做了什么”之前，展示 ClarSyn 在船司运营系统生态中的位置、联动关系与可干预边界。

### 核心信息

ClarSyn 不是接管港口、海关、客服、法务的超级平台，而是在现有船司系统之间增加一个决策增强层：从多源系统读取信息，经过事件识别、风险预测、影响推演与方案组合，再向船长端、船员端、客服系统、法务赔偿系统和乘客触达端输出可解释的预警与方案。

### 正文内容

1. 业务生态总览：

- 现有角色：船长、运营经理、值班/客服、法务、乘客
- 现有系统：船期管理、预订/POS、客服系统、法务/赔偿系统、乘客 App、船载屏、广播、船员端
- 外部机构/系统：港口、海关、边检、港调、交管、OTA、气象服务

2. ClarSyn 的生态位：

- 输入来源（上游数据源）：
  - 船期与泊位数据：船期计划 / 泊位状态 / 到离港
  - 气象与外部环境：台风路径 / 天气预警 / 港口公告
  - 乘客与业务数据：乘客清单 / 舱房 / 预订·POS / 岸上游
  - 运营与客服信号：客服工单 / 咨询投诉 / 现场感知 / 排队状态
  - 知识与规则库：条款 / 合同 / 法规 / 判例 / 事故记忆
- 核心处理：事件识别、风险预测、影响推演、方案组合、推理理由、审批路由、审计留痕
- 输出对象（下游系统 / 协同对象）：
  - 决策与指挥端：船长端 / 运营调度台 / 船员执行端
  - 客服协同系统：统一口径 / 条款依据 / 问答辅助
  - 法务与赔偿系统：事件事实 / 审计材料 / 签署记录
  - 乘客触达系统：乘客 App / 船载屏 / 广播 / 短信
  - 审计与回溯系统：审计包 / append-only 日志 / 导出 PDF

3. 与联动系统的关系：

- 客服系统：接收投诉/咨询信号作为输入；输出统一口径、条款依据、事件时间线；不替代客服执行。
- 法务赔偿系统：输出事件事实、条款依据、审计材料；最终赔偿结论与法律判断由法务/管理层决定。
- 乘客触达系统：输出可发布的统一通知；实际触达仍由船司既有 App、船载屏、广播等渠道完成。
- 港口/外部系统：只做信息交换，不接受我们的指挥。

4. 可干预边界：

- 管：
  - 船方乘客触达渠道
  - 船司内部调度
  - 可合法获取的气象、船期、港口静态资料
- 不管：
  - 不指挥海关/边检/港调/交管
  - 不替代港口或口岸系统
  - 不替代客服系统与法务赔偿系统的最终决策
  - 不处理与船岸调度无关的客服事件
- 数据三态：
  - 真实可用
  - 待接入
  - 不可得（不假设、不假装）

5. 业务理解收束：

> ClarSyn 是在现有业务架构里找一个“船司有权、有责、有利”的决策层位置，而不是把所有系统都收进来的大平台。

   - 已生成 SVG：`portfolio/svg-pm-diagrams/business-ecosystem-context.svg`

## 第 7 页：AI 机会判断

### 页面目标

用具体场景和前后对比证明：AI 在这里不是概念，而是能在真实事件中带来“更早发现、更快推演、更清楚解释”的价值。

### 核心信息

AI 价值必须落到具体事件上：过去靠人和规则发现不了、推不动、解释不清；ClarSyn 让这些环节变得“更早、更快、更清楚”，并且这些变化可以被验证。

### 正文内容

1. 三个 AI 场景价值卡：

场景 1：开放域异常发现（X-0001）

- 过去：规则系统只能看到已收录事件；楼层滞留、密度异常这类库外信号，只能等现场人员偶然发现。
- ClarSyn：对偏离历史模式但未收录的信号生成提醒卡，路由到值班人员确认，只提醒不执行。
- 价值：把“不知道有问题”变成“提前关注”，避免异常从苗头升级成秩序问题。

场景 2：长链路推演 + 弱信号整合（E09）

- 过去：台风航变时，运营人员需要人工打开船期、气象、港口、乘客等多个系统核对，决策准备约需 20–45 分钟；港口窗口取消、侧风、赔付风险这类弱信号组合容易被忽略。
- ClarSyn：自动整合多个弱信号，判断风险正在积累，生成影响推演与候选预案，进入 L4 审批。
- 价值：船长在决策窗口内直接看到选项，决策准备从“小时级人工拼图”压缩到“分钟级”。

场景 3：推理附件 / 可解释性（E-L4）

- 过去：决策高度依赖个人经验，难以快速回答“为什么选方案 A 而不是 B”；事后审计和纠纷处理也缺少完整依据。
- ClarSyn：每个 AI 判断都附带结论、置信度、关键证据和替代方案。
- 价值：降低误判与沟通成本，让审批、审计和事后追责都能找到依据。

2. 前后对比表：

| 场景 | 过去 / 传统 | ClarSyn 后 | 价值 |
|---|---|---|---|
| X-0001 开放域异常 | 规则看不见库外信号，靠人偶然发现 | 自动识别异常苗头 + 提醒卡 | 从“不知道”变为“提前关注” |
| E09 台风航变 | 人工跨系统核对 20–45 分钟，弱信号易漏 | 弱信号整合 + 影响推演 + 预案 | 决策准备从小时级压缩到分钟级 |
| E-L4 推理附件 | 依赖经验，难解释、难审计 | 证据 + 置信度 + 替代方案 | 降低误判，减少纠纷，可追溯 |

3. 为什么规则系统不够（具体化）：

- 规则系统没有“库外”概念，新异常不在清单里就看不到；
- 规则系统只能做预写分支，无法推演没写过的组合；
- 规则系统能返回模板，但给不出“为什么是它”的理由。

4. AI 场景价值判断链（辅助图）：

1. 需求是否真实且有证据？
2. 是否有可接入信号 / 数据？
3. 规则 / 人工是否已覆盖？
4. AI 增量是否可解释、可控？
5. 价值能否被评测验证？

5. 收束金句：

> AI 价值不是概念，而是每个具体场景都能回答：过去多慢、多险、多难解释；现在能更快、更早、更清楚。
