## 1. 一句话与架构模式命名

> **ClarSyn 的多 Agent 架构 = 一个确定性编排器，驱动一串职责单一、结构化输入输出的节点；主流水线 16 个方块里只有 8 个涉及模型，其余是代码；三道代码门卡在关键位置；模型侧到审批门为止——模型没有执行工具。**

**架构模式名（答辩用）**：**受控流水线（Governed Pipeline）**——不是 supervisor-agent、不是 swarm、不是自由对话式 multi-agent。

| 常见多 Agent 模式 | 谁在编排 | 我们是否采用 | 为什么 |
|---|---|---|---|
| LLM 编排（supervisor agent 决定下一步） | 大模型 | ❌ | 航次调度链路必须可复现、可审计、可离线；编排逻辑本身不能是概率性的 |
| 自由对话 / peer-to-peer swarm | 无中心 | ❌ | 无固定责任边界，审计链断；审批门无处安放 |
| **确定性工作流 + 单一职责节点**（本文） | **代码（状态机/工作流引擎）** | ✅ | 编排可复现、节点可回滚、每步可独立审计；模型只在"选择和填空"处出现 |
| 单一大 prompt 包打天下 | 无 | ❌ | 上下文噪声导致长链路中途丢约束（§3.8 明确列为本系统已识别的幻觉成因之一） |

**三条口径（图上必须能读出来）**：

1. **编排器是代码，不是模型**——没有任何一个 LLM 决定"下一步调谁"；
2. **模型节点只做"选择"和"填空"**（JSON Schema / 模板槽位约束输出空间），不做自由写作、不做算术；
3. **模型侧的所有连线止于审批门**——`[7]` 之后到执行端的那一段，只能由人的签署触发。

## 4. 三道控制门（V-2 主章的核心卖点）

> **三张门都是代码，不是模型。** 这是"信任层"在架构图上的落点。

| 门 | 位置 | 判据 | 不通过时 | 防的是什么 |
|---|---|---|---|---|
| **门 1 · 证据与置信度门** | [5.5] → [6] | 置信度低于阈值 / 证据不足 / 规则冲突 / 无策略匹配 | **强制转人工**，不进入自动分发；进优先复核队列，超时仍升级 | 低质量 AI 判断被自动执行 |
| **门 2 · 推理附件确定性校验门** | 挂 [5.5] 尾 | 引用编号**真实存在**于条款库、置信度落在有效区间、公式**可复算**、证据可回溯到 trace_id | 附件标红、提权为重点提醒；不阻断但强制可见 | **"LLM 解释 LLM"**——推理附件自身幻觉被二次放大（§3.8.1 第 3 条） |
| **门 3 · 审批门** | [7] | L1 自动 / L2 值班确认 / L3 经理·法务签署 / L4 船长决策区（判据：安全不可逆 / 群体必达 / 法定对外 / 不可逆高后果） | 不放行；超时走**双路径**：常规默认执行+审计 / 涉风险升级 L4 | **模型没有执行工具**——写操作、全量推送、赔偿执行必经人审 |

**图上最关键的一笔**：在 `[7]` 处画一条**断线（⊥）**——上游所有模型节点的连线在此终止，`[7]` 到 `[8]` 的箭头上标注「**人类签署**」。这一笔让"模型没有执行工具"从一句话变成一个可看见的结构。

**门 2 的画法**：不画成竖门，画成挂在 `[5.5]` 方块右下角的**小盾牌/校验戳**，因为它不阻断流程，只做核对。

## 11. 答辩要点（图旁可放的小卡）

| 追问 | 一句话回答 | 图上的证据 |
|---|---|---|
| "凭什么叫多 Agent？不就是个流程？" | 编排是代码、节点是模型——我们把"流程"做成了**可回滚、可审计、可离线**的结构；自由编排的多 Agent 在高后果场景反而是缺陷 | `[O]` 是代码；每节点独立 Schema |
| "为什么不用一个大模型端到端？" | 上下文噪声会在长链路中途丢约束（如漏掉"轮椅乘客"），且单点幻觉无法定位 | [5a]–[5c] 分步输入输出；[5.5] 附件记录"读了哪些信号" |
| "模型会不会乱来？" | 模型侧连线止于审批门——**模型没有执行工具**；三道代码门都是确定性检查 | `[7]` 的断线 ⊥ |
| "AI 到底用在哪？" | 只用在规则引擎物理上做不到的环节：开放域异常发现 / 长链路推演 / 可解释性 | `[2.5]` `[5a-c]` `[5.5]` 三个高亮块，其余全灰 |
| "断网了怎么办？" | T1 走缓存条款库（事实锚仍在）；T2 退回模板（**没有幻觉面**）；T3 人工预案，审计不可降级 | T0–T3 四格窄条 |

**加分小卡（版面够才放）**：
> **强化学习显式不适用**——① 审批门结构性禁止"自动试错"；② 航变/群体事件低频高后果，样本不足。这不是能力问题，是产品决策。
