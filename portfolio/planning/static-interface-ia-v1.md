## 0. 规划三原则（用户 2026-09-17 拍板）

1. **按"工作"组织页面，不按机制组织页面。** 规划轴 = 谁在用（角色）× 处理什么工作对象 × 多久用一次（班次日常 / 事件中 / 低频后台）。机制只做"可见性映射"附在页面上。
2. **真实系统是复合的。** 一条机制散落在多个页面碎片里（超时双路径同时出现在审批单、任务包、监测页）；大量机制没有也不该有专属界面——排队内核、排班求解器、RAG、分类模型、RBAC 服务端校验、哈希链都是隐形的，用户只看到它们的**产物**（核算结果、条款卡、分类标签、不可操作状态、完整性徽章）。
3. **页面信息以研究证据为上限。** 无来源数字不出现，或以"显式假设参数"形态存在于后台、前台带假设标记消费。证据纪律见 §4。

**事件之夜的定位**：20:40→07:40（及次日作业窗口）是这些页面的**时间状态序列**，不是为每个节拍新建页面。同一张事件工作区，21:06 停在核算页签、21:09 停在方案页签——是状态，不是两张页面。

## 2. A 组：一线界面（宾客运营中心）

### A1 值班态势台

- **使用者/频率**：值班员、运营经理；班次全程；监控形态（大屏/值班 PC，只读为主+轻确认）
- **是什么**：班次开始就开着的主屏。今日靠泊时钟轴与窗口、登离船批次进度、在船旅客聚合计数（名单折叠）、岸游团状态、事件队列（按 RBAC 打"可操作/只读/不可见"）、弱信号 chip 与 X 提醒卡、挂起监测栏（P1/P2 在监测事件）、审批待办计数、系统降级状态灯
- **可见机制**：C1 分类标签、C1.3 X 卡（"不在事件库内·推测·只提醒"）、C5 挂起监测、G4 降级状态灯、数据三态色点
- **隐形机制**：分类/异常模型、RBAC 服务端裁剪、排队内核
- **事件之夜状态**：20:40 X 卡浮出于此页（是状态不是新页面）；深夜 P2 静默监测挂此页挂起栏

### A2 信号收件箱（待核实）

- **使用者/频率**：值班员；高频（凡有外部信息进入）
- **是什么**：外部非结构化信息（港口代理邮件/消息/通告原文）与 AI 抽取槽位卡并排；槽位待确认、低信度槽位黄框、手动修正、电话补录（G1.1 触发④）；确认后才生成/更新事件；弱信号被正式通知证实的状态闭合在此可见
- **可见机制**：C1.1 标准化、C1.4 低信度转人工、G1.1-T4 补录
- **证据依据**：PortCDM 只是自愿共享时间戳的记录系统、不推送窗口变更（r1 Q1，Springer《Maritime Informatics》）——入口必须是邮件/消息/电话，**不得画成标准数字接口直连**

### A3 事件工作区（核心页，内部 4 个工作页签 + 右侧常驻抽屉）

- **使用者/频率**：值班/经理/法务按角色进入同一事件；操作形态（平板/PC）
- **事件头**：事件编号、分类、等级、来源、trace_id、当前状态机位置、子事件血缘入口（如 47 起投诉）
- **页签① 核算**（确定性，无 AI 判断语）：窗口对照与 8h 缓冲带、输入三态、容量算术、37 个岸游逐行可行性、聚合计数（详见 §3）
- **页签② 方案**：A/B/C 候选卡（统一字段、合法性灯、区间值、假设清单、AI 仅叙述）；被驳回时此处出现修订三形态入口（参数重算/备选切换/受限动作编辑）
- **页签③ 依据**：条款依据卡（原文+编号，不写条款号占位）、系统不出赔偿金额的显性边界条、投诉子事件分流预览
- **页签④ 监测**：P1/P2 监测三层（外部源可读→副作用代监测→建议接管）、预期曲线 vs 实测、周期复检日志（still/recovered/升级）、循环提醒状态；分支突发事件以"派生事件"挂入此页
- **右侧常驻：推理附件抽屉（G3）**：读到的信号、计算公式（可复算）、检索条款、置信度分解、备选比较、假设列表；异常时从"详情"提权为"着重提醒"；引用经确定性校验（LLM 不解释 LLM）
- **隐形机制**：解析排队/ILP 求解器、RAG、分类模型——全部只见产物

### A4 审批中心

- **使用者/频率**：值班/经理/法务必处理；船长只看知会栏
- **是什么**：我的待审批队列 + 审批单。L2 电子确认 / L3 电子签署（确认单+条款引用+trace_id+可导出 PDF）/ L4 船长决策区路由；独立的**知会/抄送流（不阻塞标识）**；超时倒计时与双路径提示（到点默认执行留痕 / 涉风险自动升级 L4）；投放动作带投放审核徽标（广播等公共端口 ≥L2）
- **可见机制**：C3.1–C3.8 以"一张正在流转的真实单子"呈现，**不画权限流程图**
- **拆法**：队列独立成页；审批单本体长在 A3 事件工作区内（见开放问题 Q2）

### A5 执行与触达台

- **使用者/频率**：值班/部门领班；事件中高频
- **是什么**：
  - 左：任务包流——按区域/环节/岗位，每包=期望结果+优先级+建议执行方式；包状态（完成/受阻/延误）一键回执；无逐人指令；**派包校验（r8/S16）：候选执行人过滤条件含法定持证类别（如登船环节任务要求 A-V/2 §4 持证）与部署表岗位冲突检查（不得抽空应急必需岗），命中拦截时显示规则原文出处，不做黑盒过滤**
  - 右：投放渠道状态（乘客 App/船载屏/广播/对讲/岸方），每条"待确认→已下达→已播报/已回执"；公共端口 L2 确认锁；乘客可见文案预览（多语按 SOLAS 与船旗国要求定性表述）
  - 外部方状态：地接社等外部异步方的"等待确认/超时"状态在此可见
- **可见机制**：C4.1–C4.5、C3.4 投放矩阵；AI 手边界（现场提示必须经 +1 转达）体现为任务包上的"转发现场"动作而非直接下发
- **证据纪律**：不写语种数量（C17 挂账）

### A6 事件轨迹（时间轴）

- **使用者/频率**：值班墙屏 ambient + 事后回看
- **是什么**：每事件"发生→建议→确认→执行→恢复"状态条；日常小事件与大事件混排；可按角色视角筛选；恢复绿点、挂起琥珀空心点、升级线
- **价值**：回答"系统不是只在出事时才工作"——日常态证据

## 3. A3 事件工作区上屏内容细则（证据对齐 r1–r6）

### 3.1 核算页签

- **窗口对照条**：原 07:00–16:00（9h）→ 新 11:00–16:00（5h）；刻度带标注"有效缓冲主要在约 8h 以内（美国 3,238 个邮轮港日 AIS 观测，Frontiers in Marine Science 2026，统计阈值，非行业标准）"；5h 落在带外 → 红色算术结论"窗口内关键路径作业不可全部完成"
- **输入区逐项来源态**：
  - 1,842 名在船旅客 = PMS 事实（绿点；聚合计数+特殊需求标记，名单折叠，展开留痕——API 2004/82/EC、PNR (EU) 2016/681 支撑计数最小化，r3 Q7）
  - 船代 ETA = **区间显示**（黄点；脚注"航路到港预测公开最佳水平约 ±100 分钟量级，东地中海 2024 研究"；近港短视界 MAPE 0.25% 不同口径**永不同屏混用**，r4 Q2）
  - 边检通道产出率 = **斜纹假设标记**，可点击跳 C3 参数标定台（无公开来源，缺口 C6）
- **容量算术**：廊桥 ≤2,000 人/时（小字"2004 ASCE 设计参考值"，2025 PortMiami 文献待取 B8）、波次冲突数、工位需求区间
- **37 个岸游逐行**：窗口∩可达性（60–120 分钟，上海吴淞口案例区间·示例参数，r3 Q1）→ 可行/改半日/取消标灰；地接社为外部异步确认方
- **模型边界卡（HARNESS 展示点）**：本页批量规模使用**客流容量模型（解析排队）**；疏散分析遵循 IMO MSC.1/Circ.1533 属安全认证域，**本系统不运行、不引用其判据**（r2 Q3）——界面主动划界

### 3.2 方案页签

- 三卡统一字段：可完成下船旅客比例**区间**（离线 what-if 推演+假设，非单点）/ 岸游取消数 / 需增工位 / **船员排班合法性灯** / 告知规模 / 假设清单
- 合法性灯红灯旁列命中规则原文：MLC 24h ≥10h、7d ≥77h、分段 ≤2 且一段 ≥6h、间隔 ≤14h（UK MSN 1877 引 MLC A2.3，r2 Q4）；黄灯=例外方案（70h/周、≤2 例外日/7d）并附条件；**第二行灯=配员约束**：本船《船舶最低安全配员证书》载明的最低构成（按船种/吨位/航区核定，演示中按证书配置为可校验规则）＋关键岗位禁令"船长和大副、轮机长和大管轮不得同时离船"（配员规则第 22 条原文，r8/S16）；夜间抽调酒店部人员时不得清空应变部署表必需的安全岗位（见 §10.5 双轴）
- 每数字可在推理附件抽屉溯源到约束与输入；AI 只写卡底一段人话叙述；算术不可手改
- 方案有"建议"标记，动作区全部送 A4 审批，无自动执行按钮

### 3.3 依据页签

- 依据卡粒度：船票合同·行程变更条款（占位，A2–A4 合同到手前不写条款号）；欧盟海运乘客权利法规·告知与协助义务（EU 1177，不写条款号，A1 待取）
- 显性边界条：**系统不生成赔偿金额、不替承运人承诺**；47 起退款投诉=子事件按条款库分流（G2 血缘挂接）

### 3.4 监测页签

- P2 三层：外部源可读（ETA/通告→判基线是否仍成立）→ 不可读用副作用（排队/接驳余量）代监测 → 仍不可读建议人工接管
- P1 自证自闭环：同一批感知端口判发生/恢复；预期曲线（C2.5 模型输出）vs 实测偏差
- 复检三出口日志：still（仅日志）/ recovered（关闭）/ 升级（派生新事件，parentTrace 挂血缘）

### 10.5 船员编号与分组基线（v0.5：R8 后状态，依据 S16）

**结论：分组做双轴，编号分两层。**

**① 法定轴（A 级，界面可标公约/规章出处）：**

- **配员文件**：本船持《船舶最低安全配员证书》，载明按船种/吨位/航区核定的**船员构成及数量**（最低要求）；配员不足禁止离港；停泊期间船长/大副、轮机长/大管轮不得同时离船（《船舶最低安全配员规则》第 4/6/7/22/23 条，中国政府网全文）；
- **应急岗位**：每名船员在**应变部署表（muster list）**上被指派具体应急职责（集合站引导、走廊楼梯通道管控、舱室与公共场所搜索、名单清点、残障旅客协助、艇筏登乘管理等——措辞取《海船船员培训大纲（2021 版）》客船特殊培训课程原文）；部署表编制是船长法定适任知识；
- **持证类别**：STCW 规则 V/2 四类强制培训（5 年复训）：
  1. 人群管理（部署表中协助旅客的船员）；
  2. 旅客区直接服务安全培训（酒店一线全员）；
  3. 危机管理和人的行为（负责旅客安全岗位）；
  4. 旅客上下船/货物/水密门责任培训；
- **船内空间编号有法定用法**：门和楼梯的编号是合格证 III 课程正式知识点（培训大纲原文）——演示中楼梯组/舱门编号照此原则设计，具体编码随 A9 甲板图核实。

**② 行政轴（行业通用口径，界面标"行业惯例·演示设定"）：**

- 甲板部 / 轮机部 / 酒店部三分；酒店部子部门按职教培养方案对接口径：前厅部、客房部、餐厅/餐饮部、娱乐、商务中心、证件与人事等（C 级，非船公司一手；A10 待补厂商岗位树）；
- 一线岗位实名为 waiter / purser / 客房服务员等（JWS 2018、Safety Science 2019 互证）；
- 酒店部人员同时是安全组织成员（Safety Science 2019 摘要原文）——双轴并非我们的设计发明。

**③ 编号规则（演示设定，不声称有标准）：**

| 对象 | 处理 |
|---|---|
| 系统内工号 | 部门码+序号（如 HSK-0142），参数卡与 C5 页面均标"演示设定，无公开强制工号标准" |
| 人员详情卡 | 同时展示法定字段：船员证书类别、V/2 持证类别与复训有效期、部署表应急岗位——**法定字段比模仿真实工号格式更重要** |
| 配员证书编号 | 界面如出现，标注"与船舶国籍证书编号一致"（配员规则第 26 条） |
| 班组人数/管辖幅度（如客房服务员管舱数） | A10/C18 前**不出现具体数字**；需要时进 C3 参数台做显式假设 |
| 船员名单到离港申报 | 存在 IMO FAL 标准表式（C19 未取表式本体），界面不画其字段细节 |

**④ 对机制叙事的净增量**：C3 排班求解器的硬约束从"只有 MLC 休息规则"扩展为"MLC＋配员证书最低构成＋部署表岗位冲突＋持证类别匹配"四层；任务包派发的适任性（C4）有了可见的法源字段；分支 β 现场抽调时"为什么这个任务包只能派给这些人"可以在界面上被解释，而不是黑盒。
