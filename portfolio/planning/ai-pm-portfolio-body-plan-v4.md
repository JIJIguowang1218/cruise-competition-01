## 1. 总体叙事与阅读导览

### 1.1 叙事主线（一句话）

> **跟着一个航变事件走完全程**：先在业务层看懂"系统如何把一个事件的每个阶段管住"（机制），再看"哪些系统部件扛起这些机制"（系统），最后才谈"用什么技术、凭什么信、怎么落地"（技术/验证）。

### 1.2 四幕逻辑（两次换挡）

```text
第 I 幕  价值与问题        —— 为什么做（P1–P7 内容，基本保留）
        │ 换挡 ①：进入一个具体事件
第 II 幕 事件锚点          —— P9-1 全流程 + 事件轴×机制总谱（本册地图）
        │ 换挡 ②：沿轴逐机制展开
第 III 幕 机制展开（业务/治理层）—— 规矩与责任：谁决策、怎么升级、怎么监控（无技术词）
        │ 换挡 ③：机制 → 系统部件
第 IV 幕 系统组织（产品/架构层）—— 引擎/端口/工种分工（仍无模型与 agent 实现）
        │ 换挡 ④：进入技术
第 V 幕  技术实现           —— 模型选型 / agent 编排 / 硬件部署
第 VI 幕 证明与落地         —— 评测 / 原型指标 / 路线图 / 差异化风险
```

### 1.3 阅读导览页（建议放在第 II 幕之前，约 1 页）

用 II-2 轴图缩略版说明四种读法，供读者（评委/PM/技术）自选深度：
- **业务线**：II-1 详图 → III-1–III-9（治理规矩）→ VI-1（凭什么信）
- **机制线**：II-2 导航图 → 任一 III 章（按编号回跳）
- **系统线**：III 任一章 → IV-1–IV-3（部件）
- **技术线**：IV → V → VI

## 5. 第 III 幕 · 机制展开（业务/治理层，III-1..III-9）

> **层级纪律（本幕红线）**：只用业务/治理语言——角色、规则、责任、状态、边界、出口；**不出现模型名 / agent 编排 / RAG / 上下文窗口等技术词**（它们留到第 V 幕）。
> **章节公式（每章统一模板）**：① 对应轴段 + 机制编号（页眉回指 II-2）；② 业务一句话（这段在管什么）；③ 状态机/流程图为主图；④ "为什么这么设计"（逻辑/安全/效率/责任依据，含船长权限等证据引用）；⑤ 边界与红线（不做什么）；⑥ 小格：**同机制在 P9-2 日常场景的表现**（防单事件代表性风险）。

### III-1 决定前的参谋（C0）
核心信息：ClarSyn 不做航变决定——决定前它把弱信号变成"多备选 × 四维价值（运营/经济/风险/综合）"的决策支持卡；船司选案、船长安全确认、法务/客服复核。
为什么：船长/船司握有法定决定权（ISM 证据），AI 的价值是让决定更早更准更敢（高地②在"决定前"的兑现）。
边界：经济值=相对量级+假设，不做货币化承诺；决定成立后即交棒。
主图：外挂支路图（含决策支持卡样例）+ 角色时点表。

### III-2 识别与分级（C1）
核心信息：信号如何变成"事件"——接入标准化、分类+严重度初判、**库外 X 系列**（只提醒不执行）、低信度转人工。
为什么：先判类别再定资源与权限；分类错误全链走偏，所以规则复核 + 低信度转人工。
主图：识别流程 + X 系列提醒卡样例（P9-3 呼应）。

### III-3 方案从哪来（C2 + G3 引用）
核心信息：影响链推演（登离船/接驳/时间窗/船员任务）只针对"已成立决定"；方案=库中组合（动作库/条款/历史预案）不现场发明；给备选 A/B/C 与"为什么不用另一个"。
为什么：确定性数字可复现可审计；AI 只在推演与选择处增值。
主图：推演链图 + 备选对比卡。

### III-4 审批与权限（C3，本幕最重章，可拆 2–3 页）
核心信息与拆分建议：
- III-4a **分级体系与判据**：L1–L4 语义、**L4=船长决策区**（判据=决策权归属：安全/群体/法定/不可逆 + 反向测试口诀）、船长知会/抄送（L2/L3 不阻塞）——船长权限边界证据页内引用；
- III-4b **审批生命周期**：只审一次（决策审一次、执行不重审）、修订三形态（参数重算/备选切换/受限编辑 → R+1）、超时双路径（常规默认执行+审计 / 涉风险升 L4）；
- III-4c **动作级审批与签署**：投放审核矩阵（可见性×可撤回性×后果）、四档确认签署。
主图：审批状态机（通过/驳回/超时/接管四出口）+ 判据表 + 矩阵。

### III-5 执行怎么派（C4）
核心信息：三级递送粒度（方案级→任务包级→现场提示级）；**AI 手边界**——AI 信息止于任务包，现场提示经 +1 转达，末端零新增负载。
为什么：执行自由度 + 反馈成本 + 信息负载三约束；"更快更准、不更忙"。
主图：递送分层图（手边界虚线是视觉重点）。

### III-6 执行后谁在看（C5）
核心信息：任务型 vs 持续运营型；挂起=闭合（不因墙钟升级）；**P1 现场端口模式 / P2 外部信息源模式**（航变属 P2：外部可读性分层）；周期复检三出口（日志/恢复/派生）；循环提醒。
主图：监控状态机 + P1/P2 对比表。

### III-7 人在哪里接管（G1）
核心信息：接管≠逃逸——四触发（审批时/超时后/系统降级/现场补录），接管后系统=观察+记录+建议，最小登记，循环提醒直至恢复。
主图：接管状态图（含与现有系统的关系：原有调度系统=人工接管端口）。

### III-8 信任底座（G2 + G3）
核心信息：血缘链（不重复"发现"，派生沿血缘回写）；复合事件按资源聚合；审计包（append-only+哈希+PDF）；事故记忆回写；坏例双轨。推理附件=每个 AI 判断自带证据链，异常提权。
主图：血缘链图 + 审计包样例 + 附件展开样例。

### III-9 机制总谱收束页
- 全部机制 C0–C5 / G1–G4 汇成一张总图（引用 `mechanism-registry.md` 总览表）；一句话收束："事件从输入到回写闭环，AI 负责判断与推演，人保留审批与接管，机制保证可解释、可控制、可升级。"
- 本页是第 III 幕的"目录页"，同时承担 P15 旧页的收口功能。

## 6. 第 IV 幕 · 系统组织（IV-1..IV-3，产品/架构语言）

### IV-1 系统组成与部署
岸基决策协同层 ⇄ 船基实时执行层；核心引擎（规则/确定性内核、AI 推理、事件模型、审批/权限、审计/记忆、输出编排）；韧性 G4（T0–T3）在此补全。

### IV-2 接口与端口设计
能接什么（船方内部/外部源/库外 AI 感知）、输出到哪（决策端/执行端/告知端口按 §端口库分类）、**不碰什么**（导航设备、港口海关执法、末端个体指令）。

### IV-3 工种分工（业务化多 Agent 概念）
把 III 幕机制映射为系统"工种"：确定性计算员（C2.1）/情报员（C1）/参谋（C0/C2）/审批门（C3）/稽核与账房（G2/G3）/哨兵（C5）——用业务语言讲分工与协作，不做技术实现描述。
