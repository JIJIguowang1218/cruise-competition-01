## 第 3 页：一页看懂

**主标题**
ClarSyn：邮轮港岸协同决策层。

**正文**
邮轮公司在登离船、港口接驳、航变响应三个场景中长期依赖人工拼图：信息分散在船司、OTA、港口、客服、天气等多个系统中，关键决策靠人现场汇总，导致响应慢、口径不一、难以追溯。

ClarSyn 的价值不是“帮人写通知”，而是：
1. **快速调用多源 API 与系统数据**，把气象、船期、港口、客服信号汇总成统一态势；
2. **接收外部航变决定、识别下游影响性弱信号**，提前给出影响推演与预案（航变预警/决定由外部体系+船长负责）；
3. **自动完成影响推演与预案准备**，让人把时间花在审批与判断上，而不是信息搜集上；
4. **全链路审计**，让每个判断、每个动作都可回溯。

**核心数据**
- 人工拼图：20–45 分钟 `[待验证]`
- 航变响应传统逐批沟通：8 名客服连续 5h+ `[待验证]`
- 系统目标：感知→建议→审批任务生成 ≤3 分钟

**视觉规划**
- 左侧四行价值点：快速调用 / 弱信号发现 / 预测预案 / 审计留痕
- 右侧一张端到端流程图缩略

## 第 4 页：问题定义——船↔岸交界为什么难

**主标题**
三处断裂：登离船、港口接驳、航变。

**正文**
邮轮乘客在“船↔岸”交界处体验断裂最明显，而这些问题不是单一部门能解决的。

**问题一：登离船动态不可见**
- 登船日同一时段集中到达，排队长度不可见；
- 离船日靠广播/纸质通知分层下船，从停锚到码头约 1 小时，分层下船再等近 3 小时。

**问题二：港口接驳信息静态**
- 官方接驳信息以静态 PDF 为主；
- 出租车拒载/宰客；
- 宝山区政府连续两年承认交通秩序问题。

**问题三：航变响应靠人工拼图**
- 通知链存在多层衰减；
- 口径不一致，乘客在信息真空中产生不信任；
- 2026 台风“白海豚”事件导致数百人拒下船。

**结论**
现有系统是“人工拼图”，不是“决策系统”。

- 底部一行证据来源标注

## 第 5 页：价值场景对比——登离船 / 港口接驳 / 航变

**主标题**
同一套系统，三个场景，都从“人肉拼图”变成“分钟级决策”。

**场景 1：登离船动态调度**
- 现状：固定批次、广播/纸质通知、排队不可见
- ClarSyn：动态时间窗、按码头状态调整批次、定向触达
- 提升：决策准备时间从小时级压缩到分钟级

**场景 2：港口接驳协同**
- 现状：静态 PDF、人工引导、乘客不知道等多久
- ClarSyn：把港口静态资料与船期结合，生成可执行接驳建议
- 提升：减少乘客滞留不确定性，缓解现场引导压力

**场景 3：航变响应**
- 现状：事件发生后靠人工逐批沟通，预测与预案准备几乎空白
- ClarSyn：快速调用气象、船期、港口、客服 API，**发现航变/气象弱信号**，提前生成影响预测与应变预案
- 提升：把“事后解释”变成“事前预测 + 预案准备 + 快速决策”

**ROI 口径**
不做货币化，用“相对量级 + 显式假设”；数字待船司真实数据校准。

**视觉规划**
- 三行对比表：现状 → ClarSyn → 提升量级
- 航变行用强调色标注“弱信号预测 + 预案准备”

## 第 7 页：系统架构总览

**主标题**
感知 → 决策 → 触达，分层清晰。

**架构分层**

- 卫星：仅异步同步

**关键原则**
能规则不用 ML；能用小模型不用大模型；能离线不用云端。

## 第 8 页：多 Agent 架构与 Agent Loop

**主标题**
不是“多个 Agent 贴纸”，而是有分工、有通信、有回路的决策架构。

**核心模块**
1. 多源事件接入：气象 API、船期、港口、客服信号统一标准化
2. 事件分类与严重度判定
3. 库外异常识别：发现未收录的弱信号组合
4. 确定性计算内核：时间窗、影响人数、资源缺口
5. 知识检索：策略、条款、历史事故
6. 方案组合与推演：事件 → 影响 → 资源 → 方案
7. 推理附件生成：结论 + 置信度 + 依据
8. 证据与置信度检查：低信度转人工
9. 权限路由与审批门
10. 执行触达
11. 审计与事故模式记忆

**Agent Loop**
- Observe：接入气象、船期、港口、客服信号
- Orient：分类、异常识别、态势整合
- Decide：影响推演、预案组合、推理附件
- Act：审批、触达
- Learn：审计回写事故模式记忆库，持续优化

**编排规则**
- 顺序主链路 + 库外异常旁路 + 超时升级回流 + 审计回流
- 每个 Agent 输入输出独立，可回滚、可审计

**视觉规划**
- 大幅 Agent Loop 图：OODA 闭环 + 模块列表 + 回流箭头

## 第 13 页：AI 价值高地②——长链路推演与弱信号整合

**主标题**
推演没写过的组合，把 20–45 分钟拼图压成分钟级局势。

**案例**
E09 台风航变：港口靠泊窗口取消、侧风 34kn、AI 赔付风险升高 → 弱信号叠加 → AI 判据自动升级 L4 → 影响推演与预案重排。

**价值表述**
- 提前发现气象/航变弱信号，而不是等事件发生后解释
- 快速生成“影响预测 + 预案准备”，让船长在决策窗口内看到选项
- 规则系统需要预写所有分支，AI 能推演未见过的组合

**技术栈**
多 Agent/Workflow 串联（事件 → 影响 → 资源 → 方案）+ 本地小/中模型 + RAG。

**视觉规划**

## 第 19 页：差异化与风险 / 为什么是现在

**主标题**
为什么是 ClarSyn，而不是旧系统、聊天 AI 或导航系统？

**差异化**
- vs 传统规则系统：三块 AI 高地是规则到不了的——开放域异常、长链路推演、可解释性
- vs 聊天式 AI：不是“帮人写话术”，而是“快速调用 API、发现弱信号、生成预案”
- vs 港口/机场排队系统：我们做船岸协同决策层，不是单点排队

**为什么是现在**
2026 航变/港口接驳是官方与媒体双确认的持续痛点；气象 API、港口数据、本地小模型等条件已经成熟；AI 能力刚好补规则系统空白。

**风险与对策**
- 外部数据不可得 → 按可用性分层，能接则接，不能接不假设
- 模型幻觉 → 多源事实锚 + 结构化约束 + 人工兜底
- 组织边界 → 不越权，只做船方权限内
- 离线 → T0–T3 降级

**视觉规划**
- 对比表格 + 风险对策四宫格
